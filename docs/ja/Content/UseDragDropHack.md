# Use Drag Drop Hack

*UseDragDropHack* は、OLE ドロップ ターゲットを登録するサンドボックス化されたアプリケーション ウィンドウへのファイル ドロップに対する Sandboxie の互換性ワークアラウンドを制御します。ウィンドウ メッセージのファイル ドロップをそのターゲットにブリッジするもので、ホスト ファイルにアクセスする一般的な権限でも、すべてのドラッグ アンド ドロップ操作のスイッチでもありません。

## 構成と既定

```ini
[DefaultBox]
UseDragDropHack=y
```

現在のランタイムは、存在しない有効な値を `y` として扱います。つまり、既定でワークアラウンドを要求します。これは `[bN]` をリストする設定メタデータとは異なります。明示的な `n` は、一致するプロセスに対してこの互換性パスを無効にしますが、一般的にドラッグ アンド ドロップを無効にするものではありません。

この設定は実行可能ファイル修飾値もサポートします:

```ini
[DefaultBox]
UseDragDropHack=example.exe,n
```

イメージ名の検索は、大文字と小文字を区別しないプログラム名パターンおよび構成されたプロセス グループをサポートします。特定のプログラム、パターン、またはグループの肯定一致は否定一致より優先され、両方とも一般値より優先されます。`*,` セレクターは非修飾値と同じ優先度を持ちます。同じ優先度レベルの一致の中では、後に列挙されたエントリが前のものを置き換えます。ボックス構成はテンプレートまたは `[GlobalSettings]` からエントリを継承することもあるため、上書きをトラブルシューティングするときは有効な構成を検査してください。

たとえば、オプションの `OfficeLicensing` 互換性テンプレートには `UseDragDropHack=excel.exe,n` が含まれています。そのテンプレートがボックスに適用されると、Excel のワークアラウンドを無効にできます。テンプレートはこれを Excel 互換性修正と呼びますが、対処する正確な失敗を説明していません。

## ワークアラウンドの動作

フックがインストールされると、Sandboxie はまず実際の OLE `RegisterDragDrop` を呼び出します。登録が成功した後、ウィンドウがまだ `WM_DROPFILES` を受け入れていない場合、ワークアラウンドは `WS_EX_ACCEPTFILES` を追加し、アプリケーションの `IDropTarget` をウィンドウに関連付け、Sandboxie のウィンドウ プロシージャ処理をインストールします。互換性のあるファイル ドロップ メッセージで、Sandboxie は OLE データ オブジェクトを構築し、ターゲットの `DragEnter`、`DragOver`、および `Drop` メソッドを呼び出します。`RevokeDragDrop` が成功すると、追加された関連付けとウィンドウ スタイルが削除されます。

これは対象となるファイル ドロップ パスのための互換性ブリッジであり、すべてのアプリケーションまたはデータ形式が機能するという約束ではありません。通常のサンドボックス ファイル アクセスおよび復元のルールは別個のままです。

## 条件と制限

`RegisterDragDrop` および `RevokeDragDrop` フックは、Sandboxie の OLE 初期化が実行され、その COM プロキシ パスがアクティブな場合にのみインストールされます。`DisableComProxy=y` または open-COM モードは、`UseDragDropHack=y` が構成されていても、そのフック インストール ブランチをバイパスします。

`OpenWinClass=*` の場合、Sandboxie はこのワークアラウンドもインストールしません。必要なプロパティとウィンドウ プロシージャのフックがそのモードでは利用できません。特定のウィンドウ クラスのみを開くルールは、この全クラス条件とは同じではありません。これは `OpenWinClass=*` がすべての形式のドラッグ アンド ドロップを無効にするという意味ではありません。より広範なウィンドウ アクセス設定については [Open Win Class](OpenWinClass.md) を参照してください。

一部のアプリケーション タイプは、ファイル ドロップ メッセージがこのパスに到達した後に追加の処理を行います。その処理はこの設定をブラウザー固有にするものではなく、アプリケーション間で同一の動作を保証するものでもありません。

## ユーザー インターフェイスと変更の適用

SandMan および Sandboxie Control Classic は現在 `UseDragDropHack` 用の専用チェックボックスを提供していません。SandMan では、**Sandbox Options > Edit ini Section > Edit ini** を通じて編集します。

このオプションは、ドロップごとではなく、SbieDll がサンドボックス化されたプロセスでその `ole32.dll` フックを初期化するときに読み取られます。変更後は、影響を受けるサンドボックス化されたアプリケーションを再起動して、その OLE フックが新しい値を使用するようにしてください。SandMan、サービス、またはドライバーの再起動は通常必要ありません。

## バージョン履歴

設定メタデータは導入バージョンとして Sandboxie Plus 1.9.6 をリストしています。1.9.6 のソース変更は構成チェックと Excel テンプレート例外を追加しました。基になるドラッグ アンド ドロップ ブリッジはその設定より前から存在します。
