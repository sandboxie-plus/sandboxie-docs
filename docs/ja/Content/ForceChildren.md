# Force Child Processes

`ForceChildren` は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定 (v1.14.5 / 5.69.5 で導入) で、親プロセスの特定の子プロセスを指定されたサンドボックス内で開始するように強制します。既知の親によって起動されたプロセスを自動的にサンドボックス化したい場合に便利です。

## 構文

一般的な形式:

```ini
[DefaultBox]

ForceChildren=<program>
```

ここで `<program>` は次のいずれかです:

- ワイルドカードを含むイメージ パス (例: `C:\Users\*\App\*.exe`)。ワイルドカード パターンは正規パスに対して大文字と小文字を区別せずに照合されます。
- イメージ名 (バックスラッシュなし、例: `dopus.exe`)。ドライバーのイメージ マッチング ルールを使用してイメージ名で照合します。

注:

- `ForceChildren` のパスは、照合の前に正規化および標準化されます (重複するバックスラッシュが削除され、再解析ポイントが変換されます)。[^1]
- ワイルドカード パターンが使用される場合、パターン マッチャーが作成され、変換されたパスに対して大文字と小文字を区別せずに照合されます。[^2]

## 動作とマッチング ルール

- `ForceChildren` エントリは、新しいプロセスが作成されるときに評価されます。親プロセスが有効なボックスの `ForceChildren` ルールに一致する場合、子プロセスはそのボックスに強制されます。[^3]

- マッチングの試行 (おおよそ優先順位順):

    - 親のイメージ名が、イメージ名またはイメージ パターンである `ForceChildren` エントリと比較されます。[^4]
    - 親の正規化されたイメージ パスおよび/または作業ディレクトリが、`ForceChildren` エントリのワイルドカード パス パターン (`*` を含むエントリ) と比較されることがあります。[^5]

- ワイルドカードを含むルールはパターン エンジンを使用し、ワイルドカードを含まないルールは、正確な言語対応チェックのために NLS 対応の文字列比較およびイメージ マッチング ヘルパー ルーチンを使用します。[^2][^4]

- ボックスの `ForceChildren` 一致は、そのボックスが現在のユーザー/セッションに対して有効であり、強制ルールが有効であることに従います。ボックス内の `DisableForceRules` などの設定は、そのボックスの強制ルールが適用されるのを防ぎます。[^6]

- 特定のシステム プロセスおよび Sandboxie 内部は強制から除外されます。Sandboxie のホーム ディレクトリは決して強制されません。[^7]

## 例

1. 特定の親バイナリ (イメージ名) の子プロセスを強制する:

    ```ini
    [MyBox]
    
    ForceChildren=parentapp.exe
    ```

2. ワイルドカード パターンを使用して親イメージ パスを照合する:

    ```ini
    [MyBox]
    
    ForceChildren=C:\Users\*\Downloads\*\app.exe
    ```

## コマンド ライン スイッチ

詳細については [StartCommandLine](StartCommandLine.md#force_children-or-fcp) を参照してください。

### 関連するスイッチ:

- `/force_children` — コマンド ラインから force-children の動作を有効化/適用します。
- `/fcp` — `/force_children` の短縮形 (サポートされている場合)。

## アラートおよびその他の強制設定との相互作用

- `ForceChildren` エントリは、ドライバーが新しく開始されたプロセスが使用すべきボックス (ある場合) を決定するときに、`ForceFolder` および `ForceProcess` エントリとともに評価されます。

- 一致するルールに対してアラートが有効な場合 (たとえば、強制ルールがポリシーによって制限されている場合)、ドライバーはプロセスを強制する代わりにアラートを表示することがあります。ドライバーは、強制を防ぎ、オプションでユーザーにログ記録または通知できる「アラート」状態を追跡します。[^8]

- `ForceChildren` 設定は、`ForceProcess` (親に関係なく名前付きプロセスを直接強制する) および `ForceFolder` (フォルダー パスに基づいてプロセスを強制する) を補完します。特定の親によって生成されたプロセスを強制したい場合は `ForceChildren` を使用します。

## 実装上の注意 (ドライバーの動作)

- ドライバーは、プロセス作成時に有効なボックスごとに強制ルールのメモリ内リストを構築します。各 `ForceChildren` エントリは内部の `FORCE_ENTRY` 要素に変換され、ワイルドカードが存在する場合は正規化されたパスまたはコンパイルされた PATTERN のいずれかを格納します。[^2]

- イメージ名で照合する場合、ドライバーは言語対応およびイメージ名固有のマッチング ロジックを実装するヘルパー `Process_MatchImage` を使用します。[^4]

- このコードは、使用前に重複するバックスラッシュが削除され、再解析ポイントが解決されることを保証します。可能な場合は NT スタイルのパスへの変換が実行されます。変換を実行できない場合、元のパスが照合に使用されます。[^1][^5]

## 参照

- [ForceProcess](ForceProcess.md) — 名前またはパスでプロセスを強制します。
- [ForceFolder](ForceFolder.md) — フォルダー パスまたはパターンでプロセスを強制します。
- [DisableForceRules](DisableForceRules.md) — ボックスのすべての強制ルールを無効にするボックスごとの設定。

## GUI (Sandboxie Manager / SandMan)

### 場所:

- Sandboxie Manager (SandMan) を開きます。
- サンドボックスのオプションを開きます: サンドボックスを右クリックして "Sandbox Options" を選択します。
- Options ウィンドウで、強制エントリがリストされている Program Control / Force Programs 領域を見つけます。

### Force Children エントリを追加する方法:

1. Options ウィンドウの Program Control / Force Programs 領域に、強制エントリのリストと "Force  Program"、"Force Children"、"Force Folder" ボタンが表示されます。
2. "Force Children" をクリックして実行可能ファイルを選択してエントリを追加します (またはファイル ダイアログを開く Browse バリアントを使用します)。
3. 項目は種類ラベル "Children" とともにリストに表示されます。チェックされたエントリは `ForceChildren` に保存され、チェックされていないエントリは `ForceChildrenDisabled` に保存されます。
4. エントリを削除するには、それを選択して "Remove" をクリックします。

### 注と参照:

- UI ツリー ウィジェットは `OptionsWindow.ui` の `ui.treeForced` です。Options ウィンドウはこれらのリストを `OptionsForce.cpp` (LoadForced/SaveForced/AddForcedEntry) で読み込み/保存します。
- 同じページに表示される "Disable forced Process and Folder for this sandbox" チェックボックスは `ui.chkDisableForced` であり、`DisableForceRules` 設定にマップされます。

## 脚注

[^1]: ドライバーは、エントリを格納する前に重複するバックスラッシュを削除し、再解析ポイントを変換します。`Process_AddForceFolders` が `expnd` を `buf` に正規化し、`File_TranslateReparsePoints` を呼び出す方法を参照してください。

[^2]: ワイルドカード エントリは `Pattern_Create` を使用して PATTERN オブジェクトを作成し、小文字に変換された正規パスに対して `Pattern_Match` で照合されます。

[^3]: `Process_FcpInsert`、`Process_FcpCheck`、および関連ルーチンは、親ベースの強制マップを実装し、新しく作成された子プロセスを PID をキーとするマップに追加し、後で子プロセスの作成中にチェックできるようにします。

[^4]: イメージ名の照合は `Process_MatchImage` に委ねられます (エントリにバックスラッシュが含まれていない場合にドライバーが使用します)。

[^5]: ドライバーは `Process_TranslateDosToNt` を使用して DOS スタイルのパスを NT スタイルのパスに変換します。これは `File_TranslateDosToNt` をラップし、構文エラーで変換が失敗した場合は元のパスをコピーすることにフォールバックします。

[^6]: 現在の SID/セッションに対して有効で、`DisableForceRules` が設定されていないボックスのみが、強制データ リストを構築するときに考慮されます。

[^7]: Sandboxie ホーム ディレクトリ下のパスは強制から除外されます。コードは `Driver_HomePathNt` 下の一致を明示的にチェックしてスキップします。

[^8]: アラート ルールが一致すると、ドライバーはアラート状態 (`IsAlert`) を設定し、強制を延期することがあります。アラートはログに記録されたメッセージを生成することがあり、設定によっては、プロセスがボックスで開始されるのを防ぐことがあります。
