# Win32k フック

## 概要

Sandboxie は、特定の GUI またはグラフィックス ドライバーの呼び出しが Sandboxie の仲介を通過する必要があるアプリケーションとの互換性のために、選択された Win32k システム コールをフックできます。このメカニズムには 2 つの構成レベルがあります。ボックスまたはプロセスがフックを使用できるようになる前に、グローバル サポートが利用可能でなければなりません。

これは一般的な GPU アクセラレーション スイッチではなく、すべての Win32k システム コールをフックするわけでも、Windows のセキュリティ緩和策を切り替えるわけでもありません。実験的な Win32k フィルター テーブル サポートは別個の内部メカニズムです。

## グローバル フック サポート {#global-hook-support}

グローバル可用性設定は次のとおりです。

```ini
[GlobalSettings]
EnableWin32kHooks=y
```

現在のランタイム既定は有効です。ドライバーは Windows ビルド 14393 以降でのみ、かつ `EnableWin32kHooks` が有効な場合に Win32k システム コール サポートを初期化します。これはメカニズムを利用可能にします。すべてのサンドボックス化されたプロセスにフックを強制するものではありません。

この設定を無効にすると、後のプロセスごとの Win32k フック パスがインストールされるのを防ぎます。現在の設定メタデータは、このグローバル コントロールを詳細および実験的として分類しています。

SandMan はそれを **Global Settings > Advanced Config > Sandboxie Config** の下に次のラベルで公開しています。

> Hook selected Win32k system calls to enable GPU acceleration (required for chrome, firefox and more)

このコントロールは Windows ビルド 14393 より古いものでは利用できません。UI ラベルは互換性の動機を説明していますが、グローバルな有効化だけではすべてのアプリケーションを選択したり、GPU アクセラレーションを保証したりしません。

## プロセスごとのフック選択 {#per-process-hook-selection}

`UseWin32kHooks` は、利用可能なフック パスを使用するサンドボックス化されたプロセスを選択します。次のような実行可能ファイル修飾構成をサポートします。

```ini
UseWin32kHooks=program.exe,y
```

プロセス設定にはグローバル `EnableWin32kHooks=y` が必要です。実行可能ファイル修飾子のない値はボックスの動作を設定でき、修飾されたエントリは特定の実行可能ファイルを対象にできます。

該当する `UseWin32kHooks` 値が存在しない場合、現在の既定は、Sandboxie がその Google Chrome/Chromium イメージ タイプで分類するプロセスに対してのみ有効です。現在のテンプレートとアプリケーション検出ロジックは、他のブラウザーまたは Electron プロセスをそのタイプに分類できます。この分類はプロジェクトによって維持されており、アプリケーションの固定リストとして扱うべきではありません。

SandMan では、`UseWin32kHooks` は **Sandbox Options > Advanced Options > Miscellaneous** の下のプロセスごとの詳細オプション エディターを通じて利用できます。その説明は、グローバル Win32k フック サポートを最初に有効にする必要があることを述べています。専用の通常のチェックボックスではありません。

## GPU アクセラレーション互換性

主な互換性の動機は、Chrome/Chromium GPU 処理で使用されるグラフィックス ドライバーの相互作用です。Sandboxie の既定の Win32k フック マップには、名前が `GdiDdDDI*` に一致する選択された呼び出しが含まれます。

これらのフックにより、選択された呼び出しが Sandboxie の Win32k 仲介とトークン処理パスを使用できるようになります。これは、すべての GPU 呼び出しがフックされること、すべての Chromium 派生アプリケーションが手動構成を必要とすること、またはフックを有効にするとハードウェア アクセラレーションが保証されることを意味しません。

## プラットフォームおよびプロセスのゲート

Win32k フックは、関連するすべての条件が満たされた場合にのみプロセスのためにインストールされます。特に次の場合、インストールはスキップされます。

- Windows ビルドまたはドライバー サポートが利用できない。
- プロセスが Sandboxie の Win32k フック可能機能を持っていない。
- グローバル `EnableWin32kHooks` が無効である。
- プロセスがアプリケーション コンパートメント モードで動作している。
- 低レベル システム コール フック機能が内部的に無効である。
- `UseWin32kHooks` が無効であるか、そのプロセスに対して既定で有効になっていない。

これらのチェックは、サンドボックス化されたプロセスがそのフック パスを初期化する間に行われます。新しい選択が使用されるように、設定を変更した後は影響を受けるサンドボックス化されたプロセスを再起動してください。

## 詳細および実験的コントロール {#advanced-and-experimental-controls}

> [!WARNING]
> Sandboxie には、専門家の診断と開発を目的とした低レベル Win32k フック マップ コントロールが含まれています。それらは必要な仲介を無効にしたり、Sandboxie が安定性の理由で意図的に除外しているフックを強制したりできます。プロジェクトのメタデータとソース コメントは、追加のフックを強制するとシステムの不安定化や BSoD を引き起こす可能性があると警告しています。これらのコントロールは一般的な互換性設定としては推奨されません。

内部的には、`EnableWin32Hook` は特定の名前の呼び出しをフック セットに追加でき、`DisableWin32Hook` は呼び出しを削除でき、`IgnoreWin32HookBlacklist` は組み込みの安定性ブラックリストをバイパスします。このページは意図的にそれらの構成レシピを提供していません。

実験的な `UseWin32kFilterTable` サポートも内部的に存在します。これは汎用の Win32k フック設定ではありません。現在のコードは、Windows フィルター サービス テーブルを読み込むときと、Windows がすでに Win32k フィルター済みとして報告するプロセスの両方でそれを参照します。それ自体は任意のプロセスで Windows の Win32k フィルタリングを有効にせず、ここではサポートされている互換性コントロールとして文書化されていません。

`AlwaysUseWin32kHooks` は廃止されました。バージョン 1.0.11 で削除され、`UseWin32kHooks` に取って代わられました。現在のランタイム コンシューマーはありません。

## トラブルシューティング ガイダンス

- `EnableWin32kHooks` がグローバルに無効にされていないことを確認してください。
- 確認された Win32k または GPU 互換性の問題については、影響を受ける実行可能ファイルの有効な `UseWin32kHooks` 値を確認してください。
- 個々の Win32k フック名を強制するよりも、現在のテンプレートと Sandboxie のイメージ分類を優先してください。
- システム クラッシュやリグレッションを調査するときは、カスタム フック マップの実験を削除してください。
- Win32k フック ブラックリストをバイパスしたり、実験的なフィルター テーブル サポートを定期的なトラブルシューティング手順として使用したりしないでください。

Win32k フックを無効にしても Sandboxie のセキュリティがグローバルに無効になるわけではなく、それらを有効にすることは自動的なセキュリティ改善として提示されるべきではありません。このメカニズムは主に、選択された傍受された呼び出しの互換性に対処します。

## バージョン履歴

| 設定または変更 | バージョン |
| --- | --- |
| `EnableWin32kHooks` メタデータ | AddedVersion 1.0.0 |
| 変更ログに記載された Win32k フック機能 | Sandboxie Plus 1.0.3 / Classic 5.55.3 |
| `AlwaysUseWin32kHooks` | 1.0.3 で追加。1.0.11 で削除され、`UseWin32kHooks` に取って代わられました |
| `UseWin32kHooks` メタデータ | AddedVersion 1.0.11 |
| Win32k フックの使用が一時的にすべてのプロセスに対して既定化 | Sandboxie Plus 1.16.6 / Classic 5.71.6 |
| 互換性の問題により広範な既定が元に戻されました | Sandboxie Plus 1.16.7 / Classic 5.71.7 |

メタデータは `EnableWin32kHooks` を 1.0.0 で追加されたものとしてリストしていますが、Win32k フック機能は 1.0.3 / 5.55.3 のリリース ノートに記載されています。このバージョンの不一致の理由は確立されていません。現在の選択ルールを決定するのは、歴史的な既定の記述ではなく、現在の実行可能ファイルの動作です。
