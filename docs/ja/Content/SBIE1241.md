# SBIE1241

**Message:** SBIE1241 Cannot mount registry hive: _[xxxxxxxx / yy]_

**ログ記録先:** [Popup Message Log](PopupMessageLog.md)

**説明:**

サンドボックス化されたプログラムが起動すると、Sandboxie はそのサンドボックスのためにサンドボックス化されたレジストリを準備する必要がある場合があります。[レジストリ ハイブ ファイル](http://en.wikipedia.org/wiki/Windows_Registry#Hives) RegHive は、解決されたサンドボックス ファイル ルートの下に存在します (その構成とフォールバック動作については [FileRootPath](FileRootPath.md) を参照してください)。これは [KeyRootPath](KeyRootPath.md) で決定されたレジストリ宛先にマウントされます。既存のマウントされたハイブは、後続のサンドボックス化されたプロセスによって共有および再利用できます。新しいプロセスが必ずしもハイブを再度読み込むわけではありません。

SBIE1241 は、ハイブの初期化、マウント関連付けの検証、または関連するセキュリティ処理中の失敗を報告します。必ずしもハイブが読み込まれなかったことを意味するわけではありません。ハイブのマウントは、[レジストリ仮想化](RegistryVirtualization.md)で説明されている論理レジストリ ビューとは別個です。[^mount]

メッセージ内で、xxxxxxxx は 16 進数の NTSTATUS 値で、yy は 16 進数の診断段階です。表示される 11 は 10 進数の 11 ではなく 0x11 を意味します。先頭のゼロは書式設定のパディングです。2 つのフィールドを合わせて解釈してください。NTSTATUS は 10 進数の Win32 エラーではなく、自動的に GetLastError() と等価ではありません。段階番号は失敗点を識別するもので、時系列の手順ではありません。[^format]

これらの診断は、Sandboxie Classic と Sandboxie Plus が使用する共有ドライバーに由来します。上記の Popup Message Log リンクは Classic インターフェイスを説明しています。Sandboxie Plus の SandMan は、そのメッセージおよび通知処理を通じて同じ診断ファミリを提示します。

## 診断段階

| 段階 | 意味 |
| --- | --- |
| 0x11 | 既存のマウント関連付けが同じレジストリ宛先を使用していますが、ハイブ ファイル パスが異なり、まだアクティブな参照があります。STATUS_CANNOT_LOAD_REGISTRY_FILE (C0000218) を報告します。 |
| 0x22 | 通常のネイティブ ハイブ読み込み操作 ZwLoadKey が失敗しました。返された NTSTATUS が保持されます。 |
| 0x23 | 代替のシステム スレッド マウント ワークフローが失敗しました。宛先を開く失敗の後、特定のアプリ パッケージ関連プロセスに対して選択されることがあります。失敗は読み込みの前または最中、あるいはその後マウントされたキーを開くまたは保護する際に発生する可能性があります。 |
| 0x33 | レジストリ宛先はすでに存在しますが、そのハイブ関連付けの検証に失敗しました。これには、システム ハイブリストの開封またはクエリ、クエリ ストレージの割り当て、または異なるバッキング ハイブ ファイル パスの検出が含まれます。不一致は STATUS_OBJECT_NAME_COLLISION を報告し、他の検査失敗はそれぞれ独自のステータスを保持します。 |
| 0x41 | 通常のハイブ読み込みの前にプロセス トークンを開くのに失敗しました。ネイティブ NTSTATUS が保持されます。 |
| 0x42 | 元のトークンの既定の随意アクセス制御リスト (DACL) の取得に失敗しました。汎用の STATUS_UNSUCCESSFUL (C0000001) を報告し、必ずしも基になるクエリ エラーではありません。 |
| 0x43 | 一時トークンの既定 DACL の適用に失敗しました。ネイティブ NTSTATUS が保持され、通常のハイブ読み込みはまだ試行されていません。 |
| 0x44 | ネイティブ読み込みの試行後、元のトークンの既定 DACL の復元に失敗しました。読み込みが成功した場合でも、復元ステータスが保持されます。 |

段階 0x23 と 0x44 は、ネイティブ読み込みが成功した後に発生する可能性があります。読み込み成功後の 0x44 の場合、サービス通知はすでに試行されていますが、これは配信またはサービスの正常な処理を確認するものではありません。失敗した初期化が正常な読み込みをロールバックしたと仮定しないでください。[^mount]

すべてのハイブ初期化失敗が SBIE1241 を発行するわけではありません。以前のパスまたはストレージの準備、メモリ割り当て、またはマウント レコードとレジストリ ルートの長さチェックは、別個に失敗する可能性があります。プロセス初期化中のハイブ マウントの失敗は、初期化サブコード A3 を伴う SBIE1231 を生成することもあります。これは SBIE1241 の段階とは別個です。[^startup]

## トラブルシューティング

完全な NTSTATUS と段階、影響を受けるサンドボックス名、アプリケーション/プロセス コンテキスト、および近くの Sandboxie メッセージを含む完全なメッセージを保存してください。ログ メッセージは、開始したアプリケーションまたはサンドボックスを常に直接識別するわけではありません。

- 段階 0x11 と 0x33 では、有効な KeyRootPath と FileRootPath、いずれかのパスへの最近の変更、および他のプロセスが影響を受けるボックスまたはマウント関連付けをまだ使用しているかどうかを確認してください。ボックス間で宛先が重複していないか確認してください。関連付けの競合は、1 つのレジストリ宛先と異なるハイブ ファイル パスを伴うものであり、必ずしも無効な設定構文ではありません。
- 段階 0x22 と 0x23 では、実際の読み込みおよびストレージ コンテキストで NTSTATUS を解釈してください。破損または無効なハイブ データとドライブの満杯は依然として考えられる原因ですが、パス/アクセシビリティの問題、利用できないストレージ、およびその他のネイティブな失敗も考えられます。該当する場合は、イメージ ベースまたは RAM ベースのストレージの前提条件を検討してください。
- 段階 0x41-0x44 では、関連するトークンまたはセキュリティの診断を保持してください。[SBIE1222](SBIE1222.md) は追加のトークン クエリ コンテキストを提供する場合があります。SBIE1231 はプロセス初期化に関するもので、[SBIE2208](SBIE2208.md) はハイブのアンロードに関するものです。これらは別個の診断であり、互換可能なエラーではありません。

共有マウント状態を調査するときは、影響を受けるプロセスを停止すると役立つ場合がありますが、1 つのアプリケーションを再起動してもアクティブな関連付けが必ずしもクリアされるわけではありません。構成の再読み込みは、アクティブなハイブの即時再マウントを保証しません。

既定の修正として RegHive を削除、名前変更、またはリセットしないでください。サンドボックス データを変更または削除する可能性のある操作の前に、適切なバックアップと保存手段を準備してください。レジストリ ACL を盲目的に変更したり、所有権を取得したり、セキュリティ制限を無効にしたり、再インストールを万能の解決策として扱ったりすることは避けてください。
