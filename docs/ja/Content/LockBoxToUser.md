# Lock Box To User

_LockBoxToUser_ は [Sandboxie Ini](SandboxieIni.md) の設定で、v1.15.0 / 5.70.0 以降で使用できます。Sandboxie がサンドボックス フォルダーへのアクセスを、そのサンドボックスを作成したユーザーのみに制限するかどうかを制御します。

## 使用法

```ini
[GlobalSettings]

LockBoxToUser=y
```

既定では (`LockBoxToUser` が指定されていないか `n` に設定されている場合)、Sandboxie はシステム上のすべての認証されたユーザーへのアクセスを許可する ACL[^1] でサンドボックス フォルダーを作成します。これは、ログインしている任意のユーザーが、他のユーザーによって作成されたサンドボックス フォルダーに保存されたファイルに潜在的にアクセスできることを意味します。

`LockBoxToUser=y` が指定されている場合、Sandboxie は次のものへのアクセスのみを許可するより制限的な ACL でサンドボックス フォルダーを作成します:

- サンドボックスを作成したユーザー。
- SYSTEM アカウント[^2]。
- Administrators グループ[^3]。

この設定は、サンドボックス内容への不正アクセスを防ぐことにより、マルチユーザー環境でのセキュリティとプライバシーを強化します。

## セキュリティ上の考慮事項

この設定は、サンドボックス ファイルがシステム上のすべてのユーザーにアクセス可能であったセキュリティ脆弱性 ([CVE-2024-49360](https://github.com/sandboxie-plus/Sandboxie/security/advisories/GHSA-4chj-3c28-gvmp)) に対処するために導入されました。

> [!IMPORTANT]
> この設定を有効にするには、サンドボックス ルート フォルダー パスに `%USER%` マクロが含まれていることを確認して、各ユーザーが専用のサンドボックス フォルダーを取得するようにしてください。既定のパス `\??\\%SystemDrive%\\Sandbox\\%USER%\\%SANDBOX%` にはこのマクロが含まれており、マルチユーザー システムに推奨されます。

## 実装の詳細

`LockBoxToUser=y` が有効な場合、Sandboxie はセキュリティ記述子の作成プロセス[^4] を変更して、より制限的な SID のセットを使用します:

- **System Logon SID** (`S-1-5-18`): SYSTEM アカウントのアクセスを許可します。
- **Administrators SID** (`S-1-5-32-544`): ローカル管理者のアクセスを許可します。
- **User SID**: 作成ユーザーのアクセスを許可します。

無効な場合、標準の動作は次のものへのアクセスを付与します:

- **Authenticated Users SID** (`S-1-5-11`): すべての認証されたユーザーのアクセスを許可します。
- **User SID**: 作成ユーザーのアクセスを許可します。

[^1]: アクセス制御リスト (ACL) は、どのユーザーとグループが特定のリソースにアクセスできるか、およびどのようなアクセス許可を持つかを定義する Windows のセキュリティ構造です。ファイル、フォルダー、レジストリ キー、およびその他のオブジェクトへのアクセスを制御する Windows セキュリティ モデルの一部です。

[^2]: SYSTEM アカウント (SID `S-1-5-18`) は、ローカル コンピューター上で最高の特権を持つ組み込みの Windows アカウントです。Sandboxie はこのアカウントの下でコア コンポーネントを実行し、適切に動作するためにサンドボックス フォルダーへのアクセスを必要とします。

[^3]: Administrators グループ (SID `S-1-5-32-544`) には、コンピューター上で管理特権を持つユーザー アカウントが含まれます。このグループのメンバーは、システム メンテナンスとトラブルシューティングの目的でサンドボックス フォルダーにアクセスできます。

[^4]: セキュリティ記述子の作成は `secure.c` の `Secure_InitSecurityDescriptors()` 関数で処理され、`LockBoxToUser` 構成設定を照会し、その値に基づいて異なる ACL 構造を作成します。有効な場合、より広範なアクセス許可を持つ既定の 256 バイト ACL の代わりに、制限された SID を持つ 512 バイト ACL を作成します。
