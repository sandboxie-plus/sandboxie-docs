# SBIE2328

**Message** SBIE2328 Failed to resolve chrome sandbox hook %2

**Severity**: Error (popup)

> [!Note]
> 現在のフック インストーラーは、ブラウザー フックの解決が失敗したときに SBIE2328 をログに記録します。また、SbieDll_Hook を介した呼び出しについて、フック モニター出力に「Chrome Hook Unresolved」を記録します。この失敗記録には API/フック トレースを有効にする必要はありません。[^2]

## 説明

このメッセージは、Sandboxie の DLL フック コードが、認識されたブラウザー (Chromium/Chrome 派生または Firefox) の実行時フックをたどろうとしたが、使用可能なターゲット アドレスを解決できなかったことを示します。メッセージには関数名とエラー コード (たとえば NtMapViewOfSection (1)) が含まれます。[^1][^2]

Sandboxie には、一部のブラウザーがインプロセス フック (インターセプターにジャンプする小さなトランポリン) をインストールする方法を認識するヒューリスティック ロジックが含まれています。パターンが認識されると、Sandboxie は保存された元のターゲット関数を見つけ、小さなトランポリンではなくそれをフックしようとします。解決が失敗するか、返されたアドレスが検証に失敗すると、SBIE2328 がログに記録されます。[^1][^2]

## エラー コード

| コード | 意味 |
| --- | --- |
| 1 | Hook_CheckChromeHook はその失敗センチネル (void*)-1 を返しました。認識されたブラウザー フック パスが使用可能な保存された元のターゲットを生成しませんでした。これは、名前付き API エクスポートが欠落していることを意味する**ものではありません**。 |
| 2 | スキャナーはアドレスを返しましたが、Hook_IsCodeAddress がそれを拒否しました。VirtualQuery が失敗したか、アドレスがコミットされた実行可能メモリ内になかったか、その保護に PAGE_GUARD または PAGE_NOACCESS が含まれていました。 |

x64 および ARM64 スキャナーは、スキャン領域、ポインター スロット、および解決されたターゲットをすでに検証します。したがって、それらのスキャナー内で拒否された候補はコード 1 になる可能性があります。コード 2 は、DLL フック インストーラーでの別個の最終チェックです。コードだけでは、失敗した正確な命令またはポインターを識別しません。[^1][^2]

サポートされている外部トランポリン パターンが認識されない場合、ヘルパーは NULL を返し、このパスは SBIE2328 をログに記録しません。いずれのエラー コードでも、Sandboxie は元のソース アドレスを保持し、そこにフックをインストールし続けようとします。このメッセージは、それだけで後続のフック インストールが失敗したことを意味するものではありません。[^1][^2]

## 一般的な原因

- ブラウザーまたはターゲット モジュールが内部コード レイアウトを変更したため、スキャナーが期待される保存された元の命令パターンを見つけられなくなりました。[^1]
- スキャン領域またはポインター スロットがメモリ検証に失敗するか、保存されたポインターが null であるか、候補ターゲットが実行可能ではありません。[^1][^2]
- 認識されたトランポリンが、アーキテクチャ固有のスキャナーがサポートしていないインターセプター レイアウトにつながります。[^3]

## 推奨される操作

1. Sandboxie を最新リリースに更新します。フック ヒューリスティックはブラウザーの変更に合わせて時折更新されます。[^3]
2. 問題が特定のブラウザー バージョンまたはベンダーでのみ発生する場合は、別のブラウザー ビルドと比較します。API/フック トレースを無効にしても、この解決パスは無効にならず、失敗も修正されません。[^2]
3. 関数名とエラー コードを含む完全なメッセージ、および Sandboxie バージョン、ブラウザー バージョン、プロセス イメージ、アーキテクチャ、モジュール名を収集します。Sandboxie メンテナーに問題を報告する際は、フック モニター出力を含めてください。
4. FuncSkipHook または SkipHook を一般的な修正として扱わないでください。FuncSkipHook は、ブラウザー ターゲットの解決だけでなく、SbieDll_Hook 内の一致する関数名に対してフックを完全にバイパスします。SkipHook は、Dll_SkipHook をチェックする呼び出し元によってのみ尊重されます。フックをスキップすると Sandboxie の傍受動作が変わるため、メンテナーが推奨する的を絞った診断にのみ使用してください。[^2]

## 実装上の注意と脚注

以下の技術的な詳細は、メッセージがどのように生成されるかを追跡したいメンテナーおよび上級ユーザーを対象としています。正確な行番号は意図的に省略されています。

[^1]: フック解決ロジックは Sandboxie/common/hook_util.c の Hook_CheckChromeHook(...) とそのアーキテクチャ固有のスキャナーに実装されています。スキャナーがターゲットを解決できない、認識されたブラウザー フック パスは (void*)-1 を返します。一致する外部パターンがない場合は NULL を返します。x64 および ARM64 スキャナーはメモリ クエリ ヘルパーを使用して命令の読み取りを制限し、ポインター スロットを検証し、実行可能なターゲットを受け入れます。x64 Firefox パスはエクスポートされた g_originals 範囲を使用し、検証された 1 つのイメージ ローカル スタブ ポインターをたどることができます。

[^2]: Sandboxie/core/dll/dllhook.c では、SbieDll_HookFunc(...) が Hook_CheckChromeHook(...) を呼び出し、(void*)-1 に対してコード 1 を、または Hook_IsCodeAddress(...) が返されたアドレスを拒否したときにコード 2 を割り当てます。いずれのエラーでも、SbieApi_Log(2328, _fmt1, SourceFuncName, ChromeError) を呼び出します。ここで _fmt1_ は %s (%d) であり、統計が提供される場合は HOOK_STAT_CHROME_FAIL を設定します。SourceFunc を保持し、アーキテクチャ固有のフック インストーラーに進みます。SbieDll_Hook(...) は、Dll_HookTrace がなくてもこの失敗フラグに対して SbieApi_MonitorPutMsg(...) を介して「Chrome Hook Unresolved」を出力します。同じファイルが SbieDll_FuncSkipHook(...) と Dll_SkipHook(...) を実装しています。

[^3]: ヒューリスティックは、すべての可能なブラウザー トランポリンではなく、x86、x64、および ARM64 でサポートされている Chromium/Firefox フック レイアウトを対象としています。ブラウザーのレイアウト変更にはスキャナーの更新が必要になる場合があります。現在の x64 コードには Chrome の R15 保存された元の読み込みと、制限付きの Firefox ワン ホップ リゾルバーが含まれています。
