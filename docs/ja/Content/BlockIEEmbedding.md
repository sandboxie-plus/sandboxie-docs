# Block IE Embedding

_BlockIEEmbedding_ は [Sandboxie Ini](SandboxieIni.md) のグローバル設定です。Internet Explorer CLSID レジストリ パスにアクセスする特定のホスト側要求に対する、限定的な互換性回避策を有効にします。一般的なブラウザーまたは COM のブロック制御ではありません。

```ini
[GlobalSettings]
BlockIEEmbedding=y
```

有効なグローバル値がない場合、回避策はオフです。個々のサンドボックス セクションのみの値はこれを制御しません。該当するグローバルにマージされたテンプレートも有効な値を提供できます。

## スコープ

有効にすると、Sandboxie のドライバーは、コールバックに渡されたキー名に `CLSID\{0002DF01-0000-0000-C000-000000000046}` が含まれ、かつ呼び出し元がこのドライバー パスによってサンドボックス化されたプロセスとして追跡されていない場合、レジストリ キーのオープン/作成要求を拒否します。比較は大文字と小文字を区別せず、部分文字列を照合するため、渡されたサブキー パスも一致することがあります。レジストリ キーにアクセスする同等のすべての方法のカバレッジを保証するものではありません。Windows 10 Creators Update 以降では、カーネル モードから発信された要求はこのチェックの対象になりません。

拒否は、呼び出し元の実行可能ファイルのベース名が、大文字と小文字を区別せずに次の名前のいずれかに完全に一致する場合にのみ適用されます:

- `winword.exe`
- `powerpnt.exe`
- `excel.exe`
- `explorer.exe`
- `svchost.exe`

一致するオープン/作成要求は、通常のサンドボックス レジストリ フィルタリングの前に `STATUS_ACCESS_DENIED` で拒否されます。`OpenKeyPath` などのレジストリ アクセス ルールは、その特定の拒否を上書きできません。追跡された Sandboxie プロセス レコードを持つ呼び出し元は `BlockIEEmbedding` によって拒否されません。後続のレジストリ処理は、その呼び出し元に適用される通常のパスに従います。この設定は、値のクエリ、値の書き込み、キーの列挙、または削除を直接傍受しません。

設定がオフの場合、キー名または実行可能ファイルが一致しない場合、またはプロセス名を取得できない場合、この特別な拒否は発生しません。要求は、他の Sandboxie ルールまたは Windows のアクセス許可によって依然として失敗することがあります。

## 互換性の背景

このオプションは、埋め込み Internet Explorer と別途強制されたブラウザーを含む Office ハイパーリンクのシナリオに対する回避策として、Sandboxie 5.19.1 ベータ / 5.20 の時代に生まれました。その歴史的な結果は、現在の Windows または Office のバージョンでは保証されません。_BlockIEEmbedding_ は、それ自体で Internet Explorer を起動したり、[program forcing](ForceProcess.md) を有効にしたりしません。

## 構成の可用性

これは手動の INI 設定です。SandMan にも Sandboxie Control Classic にも専用のコントロールはありません。ドライバーは、関連する各レジストリ要求で有効なグローバル値をチェックします。Sandboxie の構成の再読み込みが成功した後、既に取得されたレジストリ ハンドルは取り消されませんが、以降の要求はアプリケーションを再起動せずに変更された値を使用できます。
