# Network Adapter MAC

**NetworkAdapterMAC** は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定で、**v1.15.2 / 5.70.2** 以降で使用できます。[Hide Network Adapter MAC](HideNetworkAdapterMAC.md) が有効な場合に、選択された NSI/NDIS テーブル パスにカスタム アドレス バイトを提供します。物理アダプターのアドレスや、アダプター ID を報告できるすべての API を変更するわけではありません。

## 構文と例

```ini
NetworkAdapterMAC=<ordinal>,<MAC address>
```

従来の 6 バイトの 16 進数 MAC アドレスを、ハイフンありまたはなしで使用します:

```ini
[DefaultBox]
HideNetworkAdapterMAC=y
NetworkAdapterMAC=0,12-34-56-78-9A-BC
NetworkAdapterMAC=1,DE-F0-12-34-56-78
```

パーサーは 16 進数を 受け入れ、ハイフンを無視します。該当する有効なカスタム値が利用できない場合、Sandboxie はインターセプトされたパスで置換バイトを生成します。この設定はローカル管理またはユニキャスト アドレス ビット パターンを強制しません。テスト対象のソフトウェアに適したカスタム値を選択してください。

パーサーは 6 バイトの結果を要求しません。`NetworkAdapterMAC=0,AA` は最初のバイトのみを置き換え、残りの元のバイトを保持します。`NetworkAdapterMAC=0,--` はバイトをまったく置き換えずに成功することがあります。パーサーの失敗のみがランダム フォールバックをトリガーします。完全な従来の MAC 置換には正確に 6 バイトを使用してください。
## ordinal の意味

ordinal は、サンドボックス化されたプロセスで処理された最初の未キャッシュの元のアドレスに対して `0` から始まり、新しい元のアドレスごとに進みます。繰り返しの元のアドレスは、キャッシュされた置換を再利用し、新しい ordinal を消費しません。この番号は、Windows インターフェイス インデックス、`ifIndex`、または安定したアダプター ID では **ありません**。どのアダプターが `0` または `1` を受け取るかは、クエリの順序によって、またプロセス間で異なることがあります。`wmic` や `ipconfig` によって表示される順序は、Sandboxie の ordinal マッピングを確定するものではありません。

置換キャッシュはサンドボックス化されたプロセスに対してローカルで、元のアドレスをキーとします。カスタム値を変更しても既存のマッピングは書き換えられません。影響を受けるプロセスを再起動してマップを再構築してください。ブールの有効化の決定は、該当する `nsi.dll` 初期化パスが実行されるときに読み取られるため、再起動が変更された有効化の値を適用する確実な方法でもあります。

互換性テストでは、`AA-00-00-00-00-00` や `AA-11-11-11-11-11` などの異なる有効な値が、このインターセプトされたパスを使用することがわかっているアプリケーションで順序を観察するのに役立ちます。そのような観察はそのプロセスとクエリ順序に適用され、ordinal が永続的なアダプター インデックスになるわけではありません。

## 構成の可用性

SandMan には **Sandbox Options > Advanced Options > Privacy** の下に **Hide Network Adapter MAC Address** チェックボックスがありますが、カスタム `NetworkAdapterMAC` エントリ専用のエディターは特定されていません。カスタム値は INI で構成できます。チェックボックスはボックスの直接の値を示しますが、有効な有効化の値は該当するテンプレートまたはグローバル構成から取得することもできます。

## 関連設定

- [Hide Network Adapter MAC](HideNetworkAdapterMAC.md) はこの NSI/NDIS アドレス置換パスを有効にします。
- [Bind Adapter](BindAdapter.md) は別個のネットワーク バインド動作を制御します。
