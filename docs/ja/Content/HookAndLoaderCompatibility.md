# フックおよびローダー互換性

これらの高度な設定は、選択された Sandboxie のフックまたは Windows ローダーの初期化パスを変更します。これらは対象を絞った互換性のトラブルシューティングを目的としており、サンドボックス化を無効にする一般的なスイッチではありません。傍受パスをスキップすると、それに依存する仲介または互換性の動作も変わる可能性があります。

## フッキング レイヤー

Sandboxie は 1 つの普遍的なフックを使用しません。ドライバーは選択されたネイティブ システム コールに関する情報を維持し、インジェクトされた低レベル パスは新しく開始されたプロセスでシステムコール スタブを準備できます。SbieDll は別途 Nt および Win32 API フックをインストールし、そのローダー コールバックは特定の読み込まれたモジュールのフックと回避策を初期化します。これらのパスの 1 つをスキップする設定は、必ずしも他のものをスキップするわけではありません。

## NoSysCallHooks

```ini
[DefaultBox]
NoSysCallHooks=y
```

`NoSysCallHooks` はボックス全体の Boolean オプションで、既定で無効です。有効な場合、Sandboxie はそのボックス内の新しく開始されたプロセスの低レベル システムコール スタブの初期化をスキップします。また、`NtOpenProcess`、`NtOpenThread`、および `NtDuplicateObject` の選択された SbieDll セキュア フック、および関連する WoW64 システムコール修正もスキップします。アプリケーション コンパートメント モードは、低レベル パスとそれらの選択されたセキュア フックを独立してスキップします。

これは、すべての Sandboxie フックまたは残りのプロセス インジェクションを無効にするものでは**ありません**。他の SbieDll フックと独立したドライバー コントロールは、依然として独自の初期化パスを持っています。このオプションは、診断された互換性の問題にのみ使用してください。それ以外は変更されていないサンドボックス動作を保ちながらすべての API 傍受をオフにする方法ではありません。

## DisableWinNtHook

`DisableWinNtHook` は、ドライバーの NT システムコール マップのための繰り返し可能なパターン設定です。マップ ローダーは `[SysCallPresets]` からエントリを読み取るため、この設定は各ボックスまたは実行可能ファイルに対して別々に選択されるのではなくグローバルです。基になる構成ルックアップには `[GlobalSettings]` のフォールバック動作がありますが、これらのソースを自由にマージされた 2 つのリストとして説明すべきではありません。同梱のプリセットはすでにエントリを提供しています。システムコール エントリ名を `Nt` または `Zw` プレフィックスなしで記述します。現在のプリセットが構文を示しています。

```ini
[SysCallPresets]
DisableWinNtHook=MapViewOfSection
```

ドライバーは `Zw` エクスポートをスキャンし、`Zw` プレフィックスを削除し、一致するマップ エントリを無効としてマークします。そのようにマークされたエントリは、Sandboxie が低レベル フック パスのためにシステムコール情報をコピーするときに省略されます。パーサーは複数のエントリを受け入れ、そのパターン マッチャーは `*` と `?` をサポートします。一致は大文字と小文字を含むエクスポート名の綴りを使用します。既知のエントリに一致しない名前またはパターンは効果がありません。これはイメージ認識ルールではありません。プログラム セレクター、プロセス グループ、および否定セレクターはここでは解析されません。

この設定は Win32 API フックを一般的に無効にするものではなく、名前付きシステムコールを使用するすべての高レベル API がアンフックになることを保証するものでもありません。`DisableWin32Hook` は、[Win32k フック](Win32kHooks.md)で説明されている別個の Win32k マップ コントロールです。

### 2 つのシステムコール設定の違い

`NoSysCallHooks=y` は、ボックス内のプロセスのためのより広範な低レベル システムコール スタブ初期化パスをスキップします。`DisableWinNtHook` は代わりに、そのパスで使用されるドライバー全体の NT システムコール マップ内の名前付きエントリを選択します。1 つ目はボックス レベルの Boolean、2 つ目は繰り返し可能なマップ パターンです。どちらの設定もすべての Sandboxie フックを無効にしません。

## NoParallelLoading

```ini
[DefaultBox]
NoParallelLoading=y
```

`NoParallelLoading` はボックス全体の Boolean オプションで、既定で無効です。新しく開始されたサンドボックス化されたプロセスでの SbieDll ローダー初期化中に、そのプロセスの `LoaderThreads` パラメーターを `0` に設定します。これはローダー互換性の問題をデバッグするために Windows ローダーの並列読み込み動作を対象とします。アプリケーションのマルチスレッドを無効にしたり、すべてのプロセス アクティビティを直列化したりしません。

## DllSkipHook

`DllSkipHook` は、有効なボックス構成内の繰り返し可能な DLL 名設定です。たとえば、現在の Proxifier 互換テンプレートには次が含まれます。

```ini
DllSkipHook=ws2_32.dll
```

SbieDll ローダーの初期化時に、各値は Sandboxie の既知のモジュール初期化子テーブル内の正確な DLL ベース名と大文字と小文字を区別せずに比較されます。一致すると、DLL が読み込まれるときにそのモジュールの Sandboxie 固有の初期化コールバックがスキップされます。Windows がその DLL を読み込むのを妨げるものでは**ありません**。他の別個のトレースまたはフック パスは、この設定によって普遍的に無効にされるわけではありません。

未知の名前、完全なパス、またはワイルドカード パターンはそのテーブルに一致せず、効果がありません。これらの値のための実行可能セレクター、プロセス グループ、または否定パーサーはありません。[Skip Hook](SkipHook.md) および [Function Skip Hook](FuncSkipHook.md) とは異なり、このオプションは個々のフック識別子またはエクスポートされた関数ではなく、既知のモジュール コールバックを選択します。

`NoParallelLoading` と `DllSkipHook` は異なる問題に対処します。前者はプロセスのローダー並行性を変更し、後者は既知のモジュールの選択された Sandboxie コールバックをスキップします。どちらも一般的な DLL ブロックまたはサンドボックス無効化メカニズムではありません。

## テンプレートとプリセット

Sandboxie の現在の `[SysCallPresets]` には、そのシステムコール マップのために維持されたいくつかの `DisableWinNtHook` エントリが含まれています。Proxifier テンプレートは上記の `DllSkipHook=ws2_32.dll` 互換性の例を提供します。これらは現在維持されているプリセットであり、すべてのエントリをコピーすることを推奨するものでも、テンプレートの内容が変更されないことを約束するものでもありません。`DllSkipHook` は、有効なサンドボックス構成内の該当する有効なテンプレートからも取得できます。

## 変更の適用

`NoSysCallHooks`、`NoParallelLoading`、および `DllSkipHook` は、プロセスまたは SbieDll の初期化中に読み取られます。変更した後は新しいサンドボックス化されたプロセスを開始してください。既存のプロセスは、インストールされたフックまたはローダー状態を再構築しません。ドライバーは、その構成が再読み込みされたときに `DisableWinNtHook` マップ フラグを更新できますが、既に初期化されたプロセス スタブは遡って再構築されません。マップ変更をテストするときは、構成を再読み込みし、影響を受けるサンドボックス化されたプロセスを再起動してください。その更新のために、ドライバーの再起動または Windows の再起動は通常は必要ありません。

現在の SandMan オプション ソースには、これら 4 つの設定のための専用コントロールがありません。[Sandboxie Ini](SandboxieIni.md)または該当するプリセットまたはテンプレートを通じて構成してください。

## バージョン履歴

変更ログは、`NoSysCallHooks` を Sandboxie Plus 0.4.5 / Classic 5.44.1、`DllSkipHook` を Plus 0.9.1 / Classic 5.51.1、`DisableWinNtHook` を Plus 1.3.0 / Classic 5.58.0、`NoParallelLoading` を Plus 1.7.0 / Classic 5.62.0 に記録しています。また、Plus 1.15.9 / Classic 5.70.9 でドライバーの再読み込みなしに `DisableWinNtHook` を変更するサポートも記録しています。
