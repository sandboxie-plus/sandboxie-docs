# Disable File Filter

_DisableFileFilter_ は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定で、v0.9.0 / 5.51.0 以降で利用できます。SbieDll によって実装される別個のファイル仮想化ではなく、Sandboxie のプロセスごとのドライバー ファイル フィルター レイヤー (SbieDrv) における選択された適用を無効にします。

## 使用法

```ini
[DefaultBox]

DisableFileFilter=y
```

## 構文

```ini
DisableFileFilter=<y/n>
```

ここで:

- `y` は対応するプロセスごとのドライバー ファイル ポリシー チェックをバイパスします。
- `n` はコンシューマーのフォールバックであり、以下の結合された `NoSecurityFiltering` 条件がそれらを無効にしない限り、それらのチェックを維持します。

## 動作と境界

ドライバー ファイル フィルター コールバックは登録されたままです。影響を受けるプロセスでは、選択された以降のポリシー チェックがスキップされますが、保護されたルートの処理やファイル/プロセスの初期化チェックなど、以前のまたは独立したチェックは残ることがあります。この設定はフィルター全体をアンロードしたり、すべてのドライバー ファイル チェックを削除したりするものではありません。

SbieDll ファイル フックおよび通常の仮想化パスは、論理からサンドボックスへのパス マッピング、サンドボックス コピーの作成、移行、およびリソース ルール マッチングを含めて、アクティブなままにできます。その別個のレイヤーについては [File Virtualization and Identity](FileVirtualization.md) を参照してください。

Open および Read モードはネイティブのホスト アクセス試行を選択できます。Read の書き込み制限はドライバーの適用に依存します。Closed は依然として最初に SbieDll によって一致する可能性がありますが、互換性フォールバックは、ドライバー フィルターが無効な状態で最終的な拒否を約束するものではないことを意味します。保持された DLL 仮想化とルール マッチングは、同等の独立したセキュリティ適用を提供しません。

この設定自体は Windows のアクセス許可を付与したり、プロセスを昇格させたり、トークン制限を削除したりするものではありません。ネイティブ操作は該当する Windows セキュリティ チェックの対象であり、依然として失敗することがあります。直接のホスト アクセスやホストへの書き込みの成功は保証されません。

## セキュリティへの影響

> [!WARNING]
> この独立したドライバー適用レイヤーを無効にすると、保護が大幅に弱まります。信頼できないソフトウェアではなく、特定の互換性要件を持つ信頼できるアプリケーションにのみ使用してください。継続的な DLL 仮想化は、無効にされた適用の代わりにはなりません。

## 構成スコープ

ドライバーは有効なボックス Boolean を読み取ります。有効なテンプレートおよび `[GlobalSettings]` フォールバックが寄与できます。有効な値が構成されていない場合、コンシューマーのフォールバックは `n` です。このコンシューマーは、プログラム/イメージ、ProcessGroup、または否定のセレクターをサポートしません。

## 変更の適用

有効なフィルター状態は、プロセスの作成中にサンドボックス化されたプロセスごとに保存されます。構成の再読み込みは、既存のプロセスのこの状態を書き換えません。

有効な値を変更した後は、影響を受ける新しいプロセスを開始してください。変更を一貫してテストするときは、影響を受けるサンドボックス化されたプロセス ツリーを再起動してください。この設定では、SandMan、サービス、ドライバー、または Windows の再起動は通常必要ありません。

## 関連する設定

### マスター オーバーライド

[No Security Filtering](NoSecurityFiltering.md) が [Application Compartment](NoSecurityIsolation.md) モードのプロセスに対して有効な場合、`DisableFileFilter=n` であっても、ドライバーは同じファイル フィルター無効状態を有効にします。これは実行時の状態を変更するものであり、構成に `DisableFileFilter=y` を追加するものではありません。`NoSecurityIsolation=y` だけではこのフィルターを無効にしません。

### 代替の詳細なコントロール

- **[DisableKeyFilter](DisableKeyFilter.md)**: プロセスごとのドライバー レジストリ キー フィルタリングを緩和します。
- **[DisableObjectFilter](DisableObjectFilter.md)**: 別個のプロセス/スレッド オブジェクト フィルター ポリシーを緩和します。
- **[NoSecurityFiltering](NoSecurityFiltering.md)**: Application Compartment プロセスのファイル、レジストリ キー、およびオブジェクト フィルターの無効状態を有効にします。
