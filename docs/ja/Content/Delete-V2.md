# Virtualization Scheme V1 and V2

Sandboxie は、サンドボックス内の削除または名前変更されたファイル、フォルダー、およびレジストリ エントリを追跡するために、V1 と V2 の 2 つの仮想化スキームをサポートしています。これらは、Sandboxie がこれらの変更を記録し、結果のサンドボックス ビューを提示する方法が異なります。

通常、これらの変更は元のホスト データをそのまま残します。`OpenFilePath` や `OpenKeyPath` などの直接アクセス ルールは例外です。選択されたスキームに関係なく、実際のホスト データへの変更を許可することがあります。

## 設定

ファイルシステムとレジストリのスキームは [Sandboxie.ini](SandboxieIni.md) で独立して選択されます:

```ini
UseFileDeleteV2=y
UseRegDeleteV2=y
```

`UseFileDeleteV2` は V2 ファイルシステム スキームを選択し、`UseRegDeleteV2` は V2 レジストリ スキームを選択します。いずれかのオプションを `n` に設定すると、そのサブシステムに V1 が選択されます。オプションはボックスに設定することも、`[GlobalSettings]` から継承することもできます。明示的なボックス レベルの `n` はグローバルの `y` を上書きできます。

## バージョン 1

古い V1 スキームは引き続きサポートされています。ファイルとディレクトリについて、Sandboxie は削除を特別な **作成時刻** でマークされたサンドボックス側のプレースホルダーで表します。ホストに基づくディレクトリが削除されると、サンドボックス側のディレクトリはマークされたプレースホルダーとして残ることがあり、ホスト ディレクトリは変更されません。V1 は、影響を受けるパスを解決するときにサンドボックス側の親マーカーもチェックします。

レジストリ V1 は別の表現を使用します。キーの削除されたサンドボックス コピーは **最終書き込み時刻** でマークされます。削除されたレジストリ値は代わりに、特別な型を持つサンドボックス側の値で表されます。したがって、ファイル、キー、および値が同一の種類のダミー オブジェクトを共有していると考えるべきではありません。

## バージョン 2

V2 は、パス状態を通常のサンドボックス ファイルおよびレジストリ オブジェクトとは別に保持します:

| サブシステム | 設定 | ランタイムが維持する状態ファイル |
| --- | --- | --- |
| ファイルシステム | `UseFileDeleteV2=y` | `FilePaths.dat` |
| レジストリ | `UseRegDeleteV2=y` | `RegPaths.dat` |

ファイルシステムについて、`FilePaths.dat` は削除されたパスの状態と再配置マッピングを記録します。削除はこのメタデータ内のパスをマークでき、パス検索は削除された親を認識できます。再配置マッピングは、特にホストに基づくフォルダーがボックス内で名前変更されたときに、Sandboxie が基になるホストの内容を名前変更されたサンドボックス可視の場所に引き続き提示するのに役立ちます。すべての名前変更がそのようなマッピングを必要とするわけではありません。

レジストリについて、`RegPaths.dat` は **キーと値の両方** の削除状態、およびキーの再配置マッピングを記録します。レジストリ V2 は、Sandboxie がサポートするサンドボックス化された `NtRenameKey` パスで使用される再配置処理を提供します。どちらのデータ ファイルも INI 設定ではなく、手動編集を意図したファイルでもありません。

2 つのファイルはサンドボックス コンテンツです。空でないボックスから手動で編集または削除して、そのスキームを変更したり個々の削除をリセットしたりしないでください。新しく初期化された V2 ボックスにそれらが存在しないことは、それ自体では V2 が無効であることを意味しません。Sandboxie は必要に応じて欠落している状態ファイルを作成できます。

## 名前変更の互換性

V1 のマーカー ベースの階層は、一部のサンドボックス化された名前変更後にホスト コンテンツの期待されるビューを失う可能性がありました。たとえば、報告された事例では、ホストに基づくフォルダーをボックス内で名前変更し、新しい名前の下でそのホスト側の子を表示できなくなりました。V2 のファイルシステム再配置状態は、その種のケースに対処します。レジストリ V2 も同様に、Sandboxie のサンドボックス化されたキー名前変更処理を可能にします。これは、すべての V1 名前変更が失敗する、またはすべての名前変更が再配置メタデータを作成することを意味するものではありません。

## 生の設定と SandMan のペア スキーム {#raw-settings-and-sandmans-paired-scheme}

生の構成では、ファイルシステム V2 とレジストリ V1 など、2 つのスキームを混在させることができます。SandMan の **Virtualization scheme** コントロールは、代わりにそれらをペアとして扱います:

| SandMan の表示 | ボックス/グローバルの `UseFileDeleteV2` | ボックス/グローバルの `UseRegDeleteV2` |
| --- | --- | --- |
| Version 1 | `n` | `n` |
| Version 2 | `y` | `y` |
| Indeterminate | 異なる値 | 異なる値 |

この表は、明示的な `[GlobalSettings]` フォールバックを伴う SandMan の直接のボックス値を説明しており、必ずしもボックス セクションの 2 つの明示的な行ではありません。この UI 検索には有効なテンプレート値が含まれないため、テンプレートがいずれかの設定に寄与する場合、ランタイムの有効な構成は異なることがあります。Version 2 を選択すると、両方の設定が `y` として書き込まれます。Version 1 を選択すると、グローバル フォールバックが既に false の場合はローカル設定が削除され、グローバルの `y` を上書きする必要がある場合は明示的なローカルの `n` が書き込まれます。

### 2 つの異なる既定値

これらの既定値は異なるレイヤーで適用されます:

* **ランタイム フォールバック:** 有効な `UseFileDeleteV2` または `UseRegDeleteV2` 値が存在しない場合、Sandboxie のランタイムはその設定に `false` を使用し、そのサブシステムに V1 を選択します。
* **New Box Wizard:** 現在の SandMan は最初に **Version 2** を選択し、その選択でボックスが作成されるときに両方の V2 設定を書き込みます。ウィザードは後続のボックス用にユーザーが選択したボックス スキームの既定を記憶できるため、その既定を変更したユーザーは代わりに Version 1 が事前に選択されることがあります。

したがって、有効な V2 設定がないボックスは V1 を使用し、新しく作成された SandMan ボックスは通常、明示的な V2 設定を持ちます。V2 はウィザードの初期選択であり、低レベルの設定欠落時の既定では **ありません**。

## SandMan でのスキームの変更

**Sandbox Options > File Options > Box Structure > Virtualization scheme** を開きます。SandMan は **Version 1** と **Version 2** を提供し、そのボックス/グローバルのファイルとレジストリの選択が異なる場合は **Indeterminate** を表示します。

> [!WARNING]
> SandMan は、サンドボックスが空の場合にのみスキーム コントロールを有効にします。SandMan を通じてスキームを変更する前にサンドボックスを空にしてください。内容のあるボックスの生の INI 設定を変更しても、既存の削除および再配置状態がインプレースで変換されるわけではありません。

設定は、サンドボックス化されたプロセスがファイルとレジストリの処理を初期化するときに読み取られます。スキーム変更後は影響を受けるサンドボックス化されたプロセスを再起動してください。SandMan、サービス、またはドライバーの再起動は通常必要ありません。SandMan は互換性の選択肢として V1 を引き続き提供します。

## スナップショット

V2 状態はサンドボックス コンテンツの一部であり、スナップショット処理も含まれます。スナップショットの作成には利用可能な `FilePaths.dat` および `RegPaths.dat` データ ファイルが含まれ、スナップショットのマージにはファイルシステム V2 パス状態のための特定の処理があります。このページはこれらのファイルの手動操作を規定するものではありません。スナップショット操作については [Box Snapshots](../PlusContent/BoxSnapshots.md) を参照してください。
