# サンドボックス ルートとボリューム レイアウト

Sandboxie は、ボックスのファイル コンテナー、マウントされたレジストリ ハイブ、および名前付きオブジェクト名前空間に別個のルートを使用します。これらの設定は場所とレイアウトを選択しますが、それ自体はホスト ファイル、レジストリ キー、または IPC オブジェクトへのアクセスを付与しません。以下のパスは既定値であり、すべての構成されたボックスの不変の説明ではありません。

## 3 つのサンドボックス ルート

| ルート | 既定 | 目的 |
| --- | --- | --- |
| [`FileRootPath`](FileRootPath.md) | `\??\%SystemDrive%\Sandbox\%USER%\%SANDBOX%` | リダイレクトされたファイルと `RegHive` ファイルを保持するファイル コンテナー。 |
| [`KeyRootPath`](KeyRootPath.md) | `\REGISTRY\USER\Sandbox_%USER%_%SANDBOX%` | そのハイブがマウントされるレジストリの場所。 |
| [`IpcRootPath`](IpcRootPath.md) | `\Sandbox\%USER%\%SANDBOX%\Session_%SESSION%` | サンドボックス化された名前付きオブジェクトの NT 名前空間ルート。その既定にはセッションが含まれます。 |

ルート文字列はボックスのために展開および正規化されます。これには、適切な DOS ファイル パスの NT パスへの変換や、重複するまたは末尾のバックスラッシュの削除が含まれます。便利な置換には `%SANDBOX%`、`%USER%`（または `%USERNAME%`）、`%SID%`、および `%SESSION%` が含まれます。ファイルの場所は `%SystemDrive%`、`%SBIEHOME%`、および適切なシェル フォルダー変数も使用できます。`%BOXNAME%` は、このルート展開パスにおける `%SANDBOX%` のサポートされているエイリアスでは**ありません**。展開は、任意のレジストリ、IPC、またはファイル ルート値を有効にするものではありません。

## ファイル ルートの選択とレガシー フォールバック

Sandboxie は最初に有効な `FileRootPath` を探します。それが利用できない場合にのみ、有効な非推奨の [`BoxRootFolder`](BoxRootFolder.md) を探し、`\Sandbox\<box name>` を追加して、それをファイル ルートとして使用します。どちらの設定も利用できない場合、上記の組み込みの既定値を使用します。「有効」には、ボックスの設定、該当する有効なテンプレート、および `[GlobalSettings]` フォールバックが含まれます。たとえば、グローバルの `FileRootPath` はボックス ローカルの `BoxRootFolder` より優先されます。新しい構成には `FileRootPath` を使用してください。

## ファイル レイアウト

既定のレイアウトでは、ボックスのファイル ルートは次を含むことができます。

```text
FileRootPath\
  drive\C\...                 local files on drive C:
  user\current\...           current user's profile files
  user\all\...               shared/all-users profile files
  user\public\...            public profile files, where available
  share\server\share\...     network-share files
  RegHive                     sandboxed registry hive
```

他のドライブは独自の文字の下に表示されます。Windows は `RegHive` に関連するファイルも維持する場合があります。[サンドボックス階層](SandboxHierarchy.md)ページは通常のリダイレクト例を説明しています。以下の設定は、アプリケーションが使用するホスト パスを変更せずにファイル側のフォルダー名を変更できます。

## ユーザー プロファイル レイアウト

[`SeparateUserFolders`](SeparateUserFolders.md) は既定で `y` です。有効な場合、Sandboxie は認識されたプロファイル パスをポータブルな `user\current`、`user\all`、および利用可能な場合は `user\public` の場所にマップします。`n` の場合、それらの特別なプロファイル マッピングを初期化しないため、通常のローカル プロファイル パスはドライブ レイアウトに従います（例: `drive\C\Users\...`）。これは Windows プロファイルまたはアカウントのアクセス許可を変更しません。

## サンドボックス内のドライブ ID {#drive-identity-in-the-sandbox}

`UseVolumeSerialNumbers` は既定で `n` です。`y` の場合、既知のドライブ文字の後に、読み取ることができる Windows ファイルシステム ボリューム シリアルが続きます。`drive\C` はたとえば `drive\C~1234-ABCD` になります。文字は名前の一部のままです。シリアルが利用できないかゼロの場合、サフィックスは追加されません。これは文字を再利用するリムーバブル ボリュームを区別するのに役立ちますが、すべての衝突に対する保証でもセキュリティ境界でもありません。物理ディスクのファームウェア シリアルを使用したり、ディスク ID を隠したり、`share` レイアウトを変更したりしません。

## ドライブ文字なしのボリューム {#volumes-without-drive-letters}

`UseVolumeGuidWhenNoLetter` は既定で `n` です。ディレクトリにマウントされているがドライブ文字が割り当てられていないボリュームの場合、既定のレイアウトは最初のマウントされたディレクトリをそのボリュームのボックスの場所として使用し、その他のマウント ポイントをそこにマップします。`y` の場合、Sandboxie は代わりに `drive\{volume-guid}` の形式のフォルダーを使用し、マウントされたディレクトリをそれにマップできます。通常のドライブ文字マッピングは依然として優先されます。GUID 設定はすべてのドライブの新しいレイアウトではありません。その結果は、Windows が公開するボリュームとマウント ポイントに依存します。

## ルートまたはレイアウトの変更

ルートまたはレイアウト設定を変更すると、将来の操作がサンドボックス データを探す、または配置する場所が変わります。既存の内容を自動的に移動するものでは**ありません**。特に、データが入ったボックスで `SeparateUserFolders` または `UseVolumeSerialNumbers` を切り替えると、以前のフォルダー名の下にファイルが残る場合があります。SandMan はボックスが空でない場合、両方のチェックボックスを無効にします。空のボックスでレイアウト オプションを使用してください。既存のデータを保持する必要がある場合は、別途処理してください。これらの設定を変更しても移行されません。構成で `FileRootPath` を変更するだけでは古いファイル コンテナーは再配置されません。古いハイブがマウントされている間に `KeyRootPath` を変更すると、すでに使用中のハイブと競合する可能性もあります。

復元パス マッピングは、ボックスで現在認識されているレイアウトを使用します。古いレイアウトの下に残された内容は、これらの設定を変更しても移行されません。クリーンアップの動作は別個のトピックです。

## 詳細なボリューム チェック {#verbose-volume-checks}

`EnableVerboseChecks` は既定で `n` です。そのメタデータと過去の変更ログは、含まれるボリュームでの短い名前 (8.3) の作成に関する省略可能な警告 (`SBIE2227`) を説明しています。現在の実装では、ハイブ マウント ハンドラーはボリューム チェックの前に **レジストリ** ルートを（ファイル ルートではなく）DOS パス変換に渡します。通常の `KeyRootPath` はその変換を通過できないため、`EnableVerboseChecks=y` でも通常のボックスでは 8.3 テストと警告に到達しません。このオプションをファイル コンテナー ボリュームの有効なチェックとして依存しないでください。テストが異常な構成を通じて到達された場合、特定の 8.3 名がすでに存在するかどうかではなく、ボリュームの短い名前作成状態を照会します。

## 変更の適用

ルート パスは、Sandboxie がボックス パス情報を構築するときに解決されます。3 つの DLL ファイル レイアウト オプションは、サンドボックス化されたプロセスがそのファイル処理を初期化するときに読み取られます。既に初期化されたプロセスは、構成が変更されたというだけの理由でそれらのマッピングを再構築しません。影響を受けるサンドボックス化されたプロセスを再起動し、マウントされたまたはデータが入ったボックスをインプレースで変更しないようにしてください。デバイス変更通知はプロセス内のドライブ文字情報を更新できますが、オプション値を再読み取りしません。

SandMan は、**Global Settings > Advanced Config > Sandboxie Config** でグローバル ルート既定値を公開し、**Sandbox Options > Advanced Options > Miscellaneous > Add Option** でボックスごとのルート エントリを提供します。New Box ウィザードもファイル コンテナーの場所を提供します。2 つの主要なファイル レイアウト チェックボックスは **Sandbox Options > File Options** にあります。`UseVolumeGuidWhenNoLetter` と `EnableVerboseChecks` には専用のチェックボックスがありません。詳細構成は手動で入力できます。

## バージョン履歴

- `SeparateUserFolders=n` は Sandboxie Plus 0.2.2 / Classic 5.41.2 で追加されました。
- `UseVolumeSerialNumbers=y` は、文字を再利用するリムーバブル ボリュームからのデータの混合を避けるために、Plus 0.8.0 / Classic 5.50.0 で追加されました。
- `EnableVerboseChecks=y` は、Plus 1.7.2 / Classic 5.62.2 で歴史的な `SBIE2227` チェックのオプトイン形式になりました。上記の現在のランタイム制限は、その歴史的な説明より優先されます。
- `UseVolumeGuidWhenNoLetter=y` は、新しい文字なしレイアウトが元に戻された後、Plus 1.13.1 / Classic 5.68.1 でオプトイン GUID レイアウトになりました。
