# 分離メカニズム

通常のセキュリティ分離ボックス内のプロセスは、一般に厳しく制限された Windows プライマリ トークンで実行されます。これは Windows セキュリティ チェックの下でアクセスできるものを制限しますが、Sandboxie の他のメカニズムがアプリケーションに必要な仮想化と互換性の動作を提供します。正確なトークン処理は構成に依存します。アプリケーション コンパートメント モードは通常のプライマリ トークン置換をバイパスします。

Sandboxie は複数のトークン構築およびフィルタリング パスをサポートします。現在の通常のパスは、新しい厳しく制限されたプライマリ トークンを構築しますが、歴史的なフィルタリング パスは引き続き利用可能で、実装固有の Windows カーネル処理を使用します。詳細については、[アクセス トークンの分離](AccessTokenIsolation.md)と[トークンの内部](TokenMagic.md)を参照してください。

Sandboxie はまた、選択されたネイティブ システムコール スタブを傍受し、それらの呼び出しを SbieDrv 経由でルーティングします。該当する仲介操作について、ドライバーは呼び出しを処理しながら保持されたソース トークンまたはスレッド トークン コンテキストを使用できます。独立したドライバー フィルターは、構成された直接アクセスの例外を含む有効なポリシーに従ってリソース アクセス制限を強制します。ネイティブの Windows アクセス許可は引き続き適用されます。

アプリケーションが直接システムコールを発行してパッチされたユーザー モード システムコール スタブをバイパスした場合、Sandboxie の保持されたソース トークン コンテキストを回復することはありません。呼び出しは通常、サンドボックス トークンの下で続行され、該当する Windows アクセス チェックと独立した Sandboxie 強制の対象のままです。

すべての機能をこの方法で復元できるわけではないため、Sandboxie は標準 Windows DLL 内のその他多数の関数もフックし、ヘルパー サービス SbieSvc を通じて回避策とリダイレクトを提供しますが、時には一部の機能を完全に無効にすることを選ぶこともあります。

ファイルシステムとレジストリの仮想化は、主にユーザー モードで SbieDll によって実装されます。サポートされている操作をサンドボックス バッキング ストレージにマップし、対象となるホストとサンドボックスのデータをマージされたビューで結合します。仮想化は、ドライバーによって強制される制限およびネイティブの Windows 承認とは別個です。仮想化パスが利用できないかバイパスされた場合、結果は操作、有効なトークン、リソース ルール、および残りの強制に依存します。アクセス拒否もホスト アクセスの成功も保証されません。
