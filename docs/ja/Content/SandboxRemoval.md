# サンドボックスの削除と除去のライフサイクル

サンドボックスの内容を削除することと、サンドボックス定義を除去することは別個の操作です。SandMan は両方をサンドボックス化されたアプリケーションの外側で実行します。どちらの操作も Delete V1/V2 のファイルまたはレジストリ仮想化設定によって制御されません。

| 操作 | 結果 |
| --- | --- |
| **Delete Contents** (ボックスのクリーンアップ) | 保存されたサンドボックス変更を破棄またはリセットし、サンドボックス定義を保持します。スナップショットが保持されている場合、結果の状態は空のディレクトリではなく保存されたスナップショットになる場合があります。 |
| **Remove Sandbox** | サンドボックス定義を除去します。通常の手動除去は最初にその保存された内容を処理します。ストレージが空でない場合、除去は失敗する可能性があります。 |

**ファイル ルート スコープ:** 通常のボックスの場合、**Delete Contents** と **Remove Sandbox** は現在解決されたファイル ルートに対して動作します。[FileRootPath](FileRootPath.md) を変更しても以前のルートからデータは移動されないため、そこに残されたファイルはそれらの操作によってクリーンアップされません。クイック復元は現在のルートをスキャンし、以前のルートはスキャンしません。ルートを変更する前に、古いルートのデータを別途処理してください。
## 自動コンテンツ クリーンアップ

[`AutoDelete=y`](AutoDelete.md) は、以前にアクティブだったボックスが実行中のプロセス ゼロに達したことを SandMan が観測したときに、その内容をクリーンアップするよう要求します。この設定は存在しない場合オフです。それ自体はサンドボックス定義を除去しません。通常のボックス クローズ パスでは、SandMan は最初に [`OnBoxTerminate`](SandManTriggers.md#onboxterminate) を実行し、次に `NeverDelete` と `AutoDelete` をチェックします。クリーンアップが適格な場合、[復元](QuickRecovery.md)が削除前に復元可能なファイルを提供する場合があります。そのワークフローをキャンセルするとこのクリーンアップが停止し、表示可能な復元可能ファイルがない場合はサイレントに続行できます。復元は、すべての貴重なファイルが見つかる保証ではありません。

クリーンアップが続行する場合、SandMan は通常のコンテンツ クリーンアップ操作の前に [`OnBoxDelete`](SandManTriggers.md#onboxdelete) を実行します。トリガーはホスト側の自動化であり、削除を実行するコマンドではありません。SandMan は、待機する非キュー パスまたはキューに入れられたジョブを通じてクリーンアップを実行できます。起動時クリーンアップ オプションは、すでに空のボックスに対してボックス クローズ処理を呼び出すこともできます。

## スナップショットとクリーンアップ結果

自動クリーンアップは、ライブ変更のみを破棄し、ボックスを保持されたアクティブまたは既定のスナップショット状態に戻すことができます。[`AutoDeleteSnapshotTarget`](AutoDeleteSnapshotTarget.md) は自動クリーンアップのためにそのターゲットを選択します。`AutoDelete` をオンにするものではありません。手動の **Delete Contents** には、すべてのスナップショットを削除するかどうかを含め、独自のスナップショット選択があります。[ボックス スナップショット](../PlusContent/BoxSnapshots.md)を参照してください。

クリーンアップは、一部の内容が変更された後に失敗する可能性があります。これはロールバックが保証されたトランザクションではありません。基になるフォルダー削除はアクセスを待機し、失敗を再試行しますが、それでもエラーを返す可能性があります。スナップショットの復元は別途失敗する可能性があります。

## 自動定義除去 {#automatic-definition-removal}

`AutoRemove=y` は別個のボックス設定です。SandMan はコンテンツ クリーンアップ完了が処理されるときにそれを参照し、次に定義の除去を試みます。それ自体はボックス クローズ時にクリーンアップを開始しません。`AutoDelete=n` の場合、最後のプロセスを閉じるだけではボックスは除去されません。それでも、後の手動 SandMan クリーンアップが同じ除去遷移に到達する可能性があります。

New Box Wizard の **Remove after use** オプションは、`AutoDelete=y` と `AutoRemove=y` の**両方**を書き込みます。ストレージを空のままにする通常のクリーンアップでは、これはコンテンツ クリーンアップと定義除去を組み合わせます。スナップショット保持クリーンアップはストレージを存在させたままにする場合があり、その場合、基になる除去操作は定義の除去を拒否します。

クリーンアップと除去をオール オア ナッシングのトランザクションとして扱わないでください。失敗したキュー クリーンアップ ジョブは `BoxCleaned` 完了遷移に到達しません。非キュー待機パスは、そのクリーンアップ進行状況がエラーを報告しても `AutoRemove` 遷移を試みることができます。基になる通常の除去は、ストレージが空でないボックスを依然として拒否します。定義またはデータがなくなったと仮定する前に、実際の結果を確認してください。

## 保護設定 {#protection-settings}

`NeverDelete=y` は自動コンテンツ クリーンアップをブロックし、通常の完全クリーンアップおよびキュー クリーンアップ パスによってチェックされます。`NeverRemove=y` は通常の手動 SandMan **Remove Sandbox** アクションを保護します。これらは異なる操作を保護し、ファイルシステム アクセス制御ではありません。

**Sandbox Options > File Options > Box Delete options** で、三状態の **Protect this sandbox from deletion or emptying** チェックボックスは次のようにマップされます。

| チェックボックス | 保存される設定 | 意味 |
| --- | --- | --- |
| チェック済み | `NeverDelete=y`, `NeverRemove=y` | それぞれの通常パスを通じて内容と定義を保護します。 |
| 部分的にチェック | `NeverRemove=y`、`NeverDelete` オフ | 手動除去を通じて定義を保護しますが、通常のコンテンツ クリーンアップを許可します。 |
| 未チェック | 両方オフ | どちらの保護も選択されていません。 |

これらの保護にはパス固有の制限があります。通常のボックスの場合、`NeverDelete` は手動除去に必要なクリーンアップを妨げる可能性があります。非キュー手動クリーンアップ パスでは、通常の完全クリーンアップ ガードが保護されたボックスを拒否する前に `OnBoxDelete` コマンドが実行される場合があります。そのパスは、その `NeverDelete` ガードを通過せずに保持されたスナップショットを選択することもできます。アンマウントされたイメージ バッキング ボックスの除去には別の特別なパスがあります。`NeverDelete` を普遍的なデータ保存保証として使用しないでください。逆に、クリーンアップ後の現在の `AutoRemove` 遷移は、通常の手動除去がするとしても、`NeverRemove` を参照し**ません**。したがって、`AutoRemove=y` と `NeverRemove=y` の手書きの組み合わせは、自動ルートと手動ルートで異なる結果になります。

## 手動アクション

**Delete Contents** の場合、SandMan はその設定に従って確認を求めたり復元ウィンドウを提供したりし、実行中のサンドボックス化されたプロセスを終了し、通常またはスナップショット認識のコンテンツ クリーンアップを開始します。`OnBoxDelete` は該当する場合、そのクリーンアップの前に実行されます。定義は通常残りますが、`AutoRemove=y` はクリーンアップ後の後続の除去試行を開始できます。

**Remove Sandbox** の場合、SandMan は確認を求め、マウントされたイメージ ストレージを処理し、通常のボックスに対して `NeverRemove` をチェックし、定義を除去する前に除去モードでクリーンアップを要求します。この直接除去モードは `OnBoxDelete` を実行しません。通常の除去は空のストレージを必要とします。失敗したクリーンアップまたは残っているイメージは定義の除去を妨げる可能性があります。内部の一時/シャドウ オブジェクトには別個のパスがあり、通常のユーザー向け構成オプションではありません。

## 構成と変更の適用

これらはボックス ライフサイクル設定であり、イメージまたはプログラムで修飾されたリソース ルールではありません。`AutoDelete`、`AutoRemove`、`NeverDelete`、および `NeverRemove` の現在の SandMan ブール コンシューマーはボックス値を直接読み取り、存在しない場合は `n` を使用します。それらの呼び出しは `GlobalSettings` またはテンプレート フォールバックを要求しません。`AutoDeleteSnapshotTarget` は、自動クリーンアップが始まるときに、該当するグローバル/テンプレート値を含む有効な構成から読み取られます。ライフサイクル スイッチは、対応するボックス クローズ、クリーンアップ、または手動除去イベントで評価されるため、それらを変更しても通常はサンドボックス化されたプロセス、サービス、または Windows を再起動する必要はありません。

## Sandboxie Plus と Classic

このページは現在の SandMan の動作を説明しています。古い[削除設定](DeleteSettings.md)ページは Sandboxie Control / Classic インターフェイスを保持しています。Classic の [`DeleteCommand`](DeleteCommand.md) はそのレガシー削除コマンドを選択し、SandMan のクリーンアップ前 `OnBoxDelete` トリガーとは別個のままです。

## バージョン履歴

古い `AutoDelete` と `NeverDelete` 設定には、現在の設定メタデータに確立された導入バージョンがありません。`AutoRemove` は Sandboxie Plus 1.7.1 で、`NeverRemove` は 1.10.1 で、`AutoDeleteSnapshotTarget` は 1.18.2 で追加されました。これらのバージョンは、完全なライフサイクルまたは Classic インターフェイスがそれらのリリースで始まったことを意味するものではありません。
