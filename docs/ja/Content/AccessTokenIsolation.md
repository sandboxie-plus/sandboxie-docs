# アクセス トークンの分離

Sandboxie は、サンドボックス分離の 1 つのレイヤーとして、厳しく制限されたプライマリ アクセス トークンを使用します。このトークンは、サンドボックス化されたプロセスが直接 Windows アクセス チェックを通じて実行できることを制限します。ファイル、レジストリ、IPC、およびその他のサンドボックス ルールは、より広範な分離モデルの別個のレイヤーです。

Sandboxie Plus 1.14.1 は、`UseCreateToken` と `SandboxieAllGroup` 設定を導入しました。その動作と既定値は導入以来進化しています。

## 現在の動作

`UseCreateToken` 自体は既定で `n` ですが、`SandboxieAllGroup` は既定で `y` で、新しいトークン構築パスも選択します。その結果、`UseCreateToken` が明示的に存在しない場合でも、新しいサンドボックス化されたトークンを作成することが現在の通常の動作です。

## UseCreateToken

```ini
UseCreateToken=y
```

この設定は、歴史的な `SepFilterToken` フィルタリング パスを使用する代わりに、新しいプライマリ トークンを構築する Sandboxie のトークン構築パスを明示的に選択します。`SepFilterToken` は、Sandboxie が歴史的に実装固有の分析を通じて特定する内部 Windows カーネル ルーチンであり、公開された文書化された Windows API ではありません。

実効的な動作は次のとおりです。

- `UseCreateToken=y` は、`SandboxieAllGroup` に関係なく新しいトークン パスを選択します。
- `UseCreateToken=n` だけでは、`SandboxieAllGroup=y` の場合に歴史的なパスを選択しません。
- `UseCreateToken=n` と `SandboxieAllGroup=n` の両方の場合、Sandboxie は内部ルーチンを特定できれば歴史的なフィルタリング パスを使用できます。
- 内部ルーチンを特定できない場合、Sandboxie は新しいトークンの構築にフォールバックします。

## SandboxieAllGroup

```ini
SandboxieAllGroup=y
```

この設定は、共有 Sandboxie SID を有効にします。

```text
S-1-5-100-0
```

Windows はこの SID を次のように表示します。

```text
Sandboxie\All Sandboxes
```

Sandboxie は、サンドボックス化されたトークン内の通常の有効なグループとして SID を追加します。グループはすべてのサンドボックスのプロセスによって共有されるため、Windows のアクセス制御または監査ポリシーがそれを使用してサンドボックス化されたプロセスをまとめて照合できます。SID 自体はアクセスを付与しません。ACL または別のポリシーがそれを参照する必要があります。また、個々のサンドボックスを識別したり、あるサンドボックスを別のサンドボックスから分離したりしません。

## 実効設定

| `UseCreateToken` | `SandboxieAllGroup` | 実効的な動作                                                     |
| ---------------- | ------------------- | ---------------------------------------------------------------------- |
| 既定 / なし | 既定 / なし    | 共有 Sandboxie グループを使用した新しいトークン パス                         |
| `n`              | `y`                 | 共有グループを使用した新しいトークン パス                                   |
| `y`              | `y`                 | 共有グループを使用した新しいトークン パス                                   |
| `y`              | `n`                 | 共有グループなしの新しいトークン パス                                |
| `n`              | `n`                 | 利用可能な場合は歴史的なフィルタリング パス。それ以外の場合は新しいトークン フォールバック |

グローバル設定は、個々のサンドボックスに設定が存在しない場合に実効値に影響を与えることができます。

## SandMan コントロール

SandMan では、コントロールは **Sandbox Options > Security Options > Advanced Security > Sandboxie token** で利用可能で、**Create a new sandboxed token instead of stripping down the original token** とラベル付けされています。

| UI 状態          | 意味                                                                             |
| ----------------- | ----------------------------------------------------------------------------------- |
| チェック済み           | 新しいサンドボックス化されたトークンを作成し、共有 `Sandboxie\All Sandboxes` グループを含めます |
| 部分的にチェック | 共有グループなしで新しいサンドボックス化されたトークンを作成します                               |
| 未チェック         | 両方のオプションを無効にし、利用可能な場合は歴史的なフィルタリング パスを許可します         |

SandMan は、既定またはグローバル継承がすでに選択された状態を生成する場合、リテラルの `y` または `n` を書き込む代わりに設定を削除することがあります。別個のグローバル オプションも共有グループが有効かどうかを制御します。

## トークンの制限

通常の新しいトークン パスでは、Sandboxie は次のものを含む他の制限の中でも、厳しく制限されたプライマリ アクセス トークンを構築します。

- プロセスが使用できる特権を減らします。
- 一般に、通常のグループを拒否専用に変換し、アクセスを付与できないようにします。
- 構成に応じて、低または信頼されていない整合性ポリシーを適用します。
- Sandboxie の分離モデルで使用されるサンドボックス ID を置き換えます。

正確なトークンの内容は、他の詳細設定によっても影響を受ける場合があります。

### 共有グループとサンドボックスごとの ID

`Sandboxie\All Sandboxes` はすべてのサンドボックスに共通であり、ポリシーがすべてのサンドボックス化されたプロセスを照合する必要がある場合に役立ちます。SandboxieLogon で使用されるサンドボックスごとの ID は、特定のサンドボックスを識別し、異なる目的を果たします。

## セキュリティへの影響

制限されたプライマリ トークンは、直接 Windows アクセスの試行が単に元の無制限の ID で実行されないようにするのに役立ちます。その後、Sandboxie のドライバーを介したパスがファイル、レジストリ、IPC、およびその他のリソース アクセス ルールを別途強制できます。

新しいトークン パスと歴史的なフィルタリング パスは、主にその実装とトークンの内容が異なります。どちらも Sandboxie のより広範な分離設計に関与しており、どちらもセキュリティ モデル全体として扱うべきではなく、新しいトークン パスがすべての構成で無条件に安全であるわけではありません。

## 管理者と昇格の動作

アプリケーションを昇格して実行しても、サンドボックス化されたプロセスによって使用されるプライマリ トークンが完全な管理者グループと特権セットを保持するわけではありません。Sandboxie は依然としてそのトークン制限を適用します。[管理者権限の削除](DropAdminRights.md)は、管理者と昇格の動作にさらに影響を与える別個の設定です。

## NoSecurityIsolation との相互作用

次の設定がアクティブな場合、これらのトークン分離設定は通常のトークン置換には使用されません。

```ini
NoSecurityIsolation=y
```

そのモードのより広範な影響については、[セキュリティ分離なし](NoSecurityIsolation.md)を参照してください。

## 互換性と失敗時の動作

新しいトークン パスは、通常の実装パスとして `SepFilterToken` に依存することを避け、後の Sandboxie Plus リリースで通常の動作になりました。両方の設定が実効的に新しいパスを無効にし、内部ルーチンが利用可能な場合、歴史的なパスは引き続き利用可能です。

歴史的なフィルタリング ルーチンを特定できない場合、Sandboxie は新しいトークンの構築にフォールバックします。サンドボックス化されたトークンを実際に構築または適用する際の実行時失敗は、プロセスの初期化を妨げる可能性があります。

## バージョン履歴

- Sandboxie Plus 1.14.1 は `UseCreateToken` と `SandboxieAllGroup` を導入しました。
- 以降のリリースには、実装の互換性とセキュリティの修正が含まれていました。
- Sandboxie Plus 1.17.0 以降、`SandboxieAllGroup` が既定で有効になり、新しいトークン パスが通常の動作になりました。
