# Enable Object Filtering

_EnableObjectFiltering_ は [Sandboxie Ini](SandboxieIni.md) のグローバル設定で、プロセスおよびスレッド ハンドルに対する Sandboxie のカーネル オブジェクト マネージャー コールバック レイヤーを制御します。このレイヤーは、サンドボックス化されたプロセスと同じサンドボックスの外のターゲットとの間の選択されたアクセスを制限します。また、[Confidential Box](ConfidentialBox.md) で使用される別個のホストからサンドボックスへの保護もサポートします。

一般的な設定名にもかかわらず、現在のコールバック登録は特にプロセスおよびスレッド ハンドル用です。ファイル、レジストリ、IPC 名前空間、およびその他のオブジェクトの種類は、別個の Sandboxie メカニズムによって処理されます。

## 現在の既定と構成

オブジェクト フィルタリングは既定で有効です。通常の操作のために、ユーザーは明示的な `EnableObjectFiltering=y` エントリを追加する必要はありません。

グローバル コールバック レイヤーを無効にするには:

```ini
[GlobalSettings]
EnableObjectFiltering=n
```

現在のランタイムはこの設定を `GlobalSettings` から読み取ります。個々のサンドボックス セクションにのみ配置しても、そのサンドボックスのコールバック登録を制御しません。

> [!WARNING]
> グローバル コールバック レイヤーを無効にすると、すべてのサンドボックスに対して重要なプロセス/スレッド アクセス制御メカニズムが削除されます。Sandboxie のシステムコール固有のプロセス/スレッド チェックは一部のパスに残りますが、同一のカバレッジを提供するものではなく、同等の代替として扱うべきではありません。

## コールバックがフィルター処理するもの

現在の実装は、次のものに対してオブジェクト マネージャー コールバックを登録します:

- プロセス ハンドル;
- スレッド ハンドル;
- 新しいハンドルの作成;
- ハンドルの複製。

これらの操作に対して、Sandboxie は要求されたアクセスを変更しないままにするか、プロセス/スレッド アクセス ポリシーに従って削減することができます。通常の拒否パスでは、要求されたアクセス マスクはゼロに削減されます。コールバック自体は Windows がハンドル操作の処理を続行することを許可するため、アプリケーションは制限されたすべての要求に対して特定の 1 つの Win32 または NT エラーに依存すべきではありません。

カーネル ハンドルを作成または複製する操作は、このコールバックによって変更されません。これはハンドル操作の特性であり、任意のユーザー モード要求がフィルターをバイパスできることを意味するものではありません。

変更は将来のプロセス/スレッド ハンドルの作成と複製に影響します。既存のハンドルの権限を遡って削減したり、以前に制限されたハンドルに権限を追加したり、既存のハンドルを無効にしたりするものではありません。

## プロセスおよびスレッドのアクセス ポリシー

同じ有効なサンドボックス内でのプロセスまたはスレッドのアクセスは、通常このポリシーによって許可されます。あるサンドボックスのプロセスが別のサンドボックスのプロセスまたはスレッドを対象とする場合は、サンドボックスの外として扱われます。`HideOtherBoxes` などの可視性の制御は、ハンドル アクセス フィルタリングとは別個です。

外部ターゲットに対して、Sandboxie はターゲットを変更または制御するために使用できるプロセスおよびスレッドの権限を制限します。プロセス メモリの読み取りアクセスは、書き込み/制御アクセスとは別に処理されます。

ポリシーは IPC リソース ルールのプロセス ターゲット形式と統合されます:

```ini
OpenIpcPath=$:target.exe
ReadIpcPath=$:target.exe
ClosedIpcPath=$:target.exe
```

この用途では、一致する `ClosedIpcPath` ルールが `OpenIpcPath` より前に評価され、読み取り専用アクセスが該当する場合は `ReadIpcPath` が続きます。`OpenIpcPath` は他の方法では制限されるアクセスを許可でき、`ReadIpcPath` はサポートされている読み取りカテゴリにのみ適用され、`$:*` はすべてのターゲット プロセスに一致します。Sandboxie ルールが要求を許可した後も、通常の Windows アクセス制御が適用されます。

より広範なリソース ルールの動作については [Open IPC Path](OpenIpcPath.md)、[Read IPC Path](ReadIpcPath.md)、および [Closed IPC Path](ClosedIpcPath.md) を参照してください。

## コールバックとシステムコール固有のフィルタリング

Sandboxie には現在、関連する 2 つのプロセス/スレッド フィルタリング レイヤーがあります:

1. グローバルなオブジェクト マネージャー コールバック レイヤーは、操作につながったユーザー モード API または Sandboxie のシステムコール固有のチェックとは独立して、サポートされているハンドルの作成と複製をフィルター処理します。
2. システムコール固有のドライバー パスは、プロセスおよびスレッド ハンドルのオープン、列挙、または複製などの操作に対するチェックを保持します。

レイヤーはポリシー コードを共有しますが、同一のカバレッジを持ちません。グローバル コールバックがアクティブな場合、重複するシステムコール パスは通常コールバックに委ねられます。コールバックがインストールされていない場合、現在のシステムコール固有のパスは、実装されている箇所で独自のチェックを適用し続けます。

この区別は、`EnableObjectFiltering=n` がサンドボックスごとの [Disable Object Filter](DisableObjectFilter.md) 設定と同等ではないことを意味します。

| 構成 | スコープ | オブジェクト マネージャー コールバック | 効果 |
| --- | --- | --- | --- |
| 既定 | グローバル | インストール済み | 通常のプロセス/スレッド コールバック フィルタリング |
| `EnableObjectFiltering=n` | グローバル | 未インストール | すべてのサンドボックスのコールバック レイヤーを削除します。システムコール固有のチェックは残ることがあります |
| `DisableObjectFilter=y` | 影響を受けるサンドボックス化されたプロセス | 引き続きインストール済み | それらのプロセスの送信コールバック フィルタリングを緩和します |
| `NoSecurityFiltering=y` を使用する Application Compartment | 影響を受けるコンパートメント プロセス | 引き続きグローバルにインストール済み | プロセスごとのファイル、レジストリ キー、およびオブジェクト フィルターの無効状態を有効にします |

## ホストからサンドボックスへの保護

コールバックは、サンドボックス化されていないホスト プロセスがサンドボックス化されたプロセスまたはスレッドへのハンドルを要求するときにも、別個のチェックを実装します。このパスは `DenyHostAccess`、`ProtectAdminOnly`、および `NotifyBoxProtected` などの設定、ならびに Confidential Box の追加のプロセス保護をサポートします。

ホストからサンドボックスへのチェックは、サンドボックス化されたプロセスの送信フィルター状態とは別個です。ターゲット サンドボックスで `DisableObjectFilter=y` を設定しても、グローバル コールバック レイヤーがアクティブな間は、それ自体でこの保護が無効になるわけではありません。パスは、サンドボックスを管理または実行するために必要な Sandboxie および Windows コンポーネントに対する運用上の例外を保持します。

ユーザー向けのホスト アクセス ポリシーについては [Confidential Box](ConfidentialBox.md) を参照してください。

## Application Compartment

[Application Compartment](NoSecurityIsolation.md) モードは、それ自体ではオブジェクト マネージャー コールバックを無効にしません。`NoSecurityIsolation=y` と通常のフィルタリングでは、コンパートメント プロセスは依然としてこのプロセス/スレッド アクセス ポリシーの対象となることがあります。

[No Security Filtering](NoSecurityFiltering.md) も有効な場合、新しいコンパートメント プロセスは、対応するプロセスごとのファイル、レジストリ キー、およびオブジェクト フィルターの無効状態を受け取ります。コールバックはグローバルに登録されたままであり、他のサンドボックスは通常どおりフィルター処理されます。

## SandMan インターフェイス

グローバル制御は次にあります:

**Global Settings > Advanced Config > Sandboxie Config > Activate Kernel Mode Object Filtering**

チェックボックスは既定で選択されています。選択されている場合、SandMan は通常、明示的な無効化オーバーライドを削除し、有効なランタイム既定に依存します。オフにすると `EnableObjectFiltering=n` が書き込まれます。

このグローバル機能設定を保存すると、ドライバーの再構成を通じてコールバック レイヤーを登録または登録解除できます。Windows の再起動または通常のドライバー再起動は通常必要ありません。

ドライバーの起動中にコールバック登録が必要であるが失敗した場合、ドライバーの初期化が失敗し、Sandboxie は登録の問題をログに記録します。後の再構成中の失敗はログに記録され、コールバック機能は非アクティブのままになります。正確な UI 表示は異なることがあります。

## 変更の適用

グローバル設定を変更すると、将来のプロセス/スレッド ハンドルの作成と複製に影響します。これには、再構成後に既に実行中のプロセスによって行われる要求が含まれます。既に開いているハンドルは変更しません。

対照的に、`DisableObjectFilter` はサンドボックス化された各プロセスが初期化されるときに保存されます。その設定を変更した後は、影響を受けるサンドボックス化されたプロセスを再起動してください。

## バージョン履歴

コールバック機能は Sandboxie Plus 1.0.0 / Classic 5.55.0 で実験的機能として導入され、当初は明示的な `EnableObjectFiltering=y` 設定が必要でした。Sandboxie Plus 1.0.16 / Classic 5.55.16 で既定で有効になりました。
