# Network DNS Filtering

`NetworkDnsFilter` は、Sandboxie のインターセプトされた Windows Winsock サービス検索パスを通じて行われた一致するホスト名検索をブロックまたはリダイレクトします。ルールはサンドボックス内のすべてのプロセスに適用することも、選択したプログラムに適用することもでき、ドメイン名はワイルドカード パターンで照合できます。

これはユーザー モードの名前解決フィルターであり、パケット レベルのファイアウォールではありません。ホスト名をブロックしても、プログラムが IP アドレスに直接接続したり、Sandboxie がインターセプトしないパスを通じて名前を解決したりすることを防ぎません。

このフィルターには、該当する [Supporter Certificate](https://sandboxie-plus.com/supporter-certificate/) が必要です。

## 構文

```ini
NetworkDnsFilter=[process,]domain[:ip_address[;ip_address...]]
```

* `process` はオプションの [program selector](ProgramNamePrefix.md) です。省略した場合、ルールはサンドボックス内のすべてのプロセスに適用されます。
* `domain` は照合するホスト名またはワイルドカード パターンです。照合は大文字と小文字を区別しません。
* `ip_address` は、通常の結果の代わりに返されるオプションの IPv4 または IPv6 アドレスです。複数のアドレスはセミコロンで区切ります。アドレス部分を省略した場合、一致する検索はブロックされます。

たとえば、このルールはボックス内のすべてのプロセスからの一致する検索をリダイレクトします:

```ini
[DefaultBox]
NetworkDnsFilter=example.com:192.0.2.10
```

## ドメインの照合

ドメイン パターンは正規表現ではなく、Sandboxie のワイルドカード マッチングを使用します:

* `*` は任意の文字シーケンスに一致します。
* `?` は 1 文字に一致します。
* 照合は大文字と小文字を区別しません。

例:

```ini
[DefaultBox]
NetworkDnsFilter=*.example.com
NetworkDnsFilter=example.com
```

最初のルールは `www.example.com` などのサブドメインをブロックしますが、裸の `example.com` にも一致するわけではありません。これは 2 番目のルールでカバーされます。

ルールの選択は単純な「最後のルールが優先」リストではありません。ルールは構成順に検査されますが、プロセス一致レベルとドメイン パターン一致長も選択に関与します。`*` で終わらない一致するドメイン パターンは検索を終了します。それ以外の場合、後の候補は実装がより強い一致と見なした場合にのみ現在の一致を置き換えます。同等の候補は以前のエントリを保持します。特定のルールをより広範な重複ワイルドカード ルールの前に置き、曖昧な重複に依存しないようにしてください。

## ブロックとリダイレクト

アドレス部分を省略すると、一致する検索に対して結果を返しません:

```ini
[DefaultBox]
NetworkDnsFilter=blocked.example
```

アドレスを指定すると、この検索パスを通じて通常のシステム リゾルバーに一致する名前を要求することなく結果を合成します:

```ini
[DefaultBox]
NetworkDnsFilter=redirected.example:192.0.2.20
```

1 つのルールで複数の有効なアドレスを返すことができます:

```ini
[DefaultBox]
NetworkDnsFilter=service.example:192.0.2.20;192.0.2.21
```

無効なアドレス エントリは無視されます。一致するルールに要求されたアドレス ファミリの有効なアドレスが含まれていない場合、検索は結果を返しません。手動で記述したエントリは慎重に検証してください。

## プロセスの照合

コンマの前のオプションのセレクターは、実行可能ファイル名、Sandboxie のワイルドカード マッチング、構成されたプロセス グループ、および否定セレクター用の先頭の `!` をサポートします。例:

```ini
[DefaultBox]
NetworkDnsFilter=browser.exe,example.com:192.0.2.30
NetworkDnsFilter=*.exe,telemetry.example
NetworkDnsFilter=<InternetAccess>,internal.example:192.0.2.40
NetworkDnsFilter=!updater.exe,updates.example
```

最後のルールは `updater.exe` 以外のプロセスに適用されます。プロセス セレクターは完全なパスではなく実行可能ファイル名を使用します。省略されたセレクターまたは `*` はボックス内のすべてのプロセスに適用されます。

## IPv4 と IPv6

アドレスの選択は、検索の要求されたファミリに従います:

* IPv4 (`A`) 検索は、構成された IPv4 アドレスを返します。
* IPv6 (`AAAA`) 検索は、構成された IPv6 アドレスを返します。
* ルールに IPv4 アドレスのみが含まれている場合、Sandboxie は IPv4 マップ IPv6 結果を IPv6 検索でも利用できるようにします。
* ルールに明示的な IPv6 アドレスが含まれている場合、IPv6 検索は明示的な IPv6 エントリを使用します。Sandboxie はそのルールの IPv4 アドレスからマップされた IPv6 エントリも生成しません。
* IPv6 アドレスのみを含むルールは、IPv4 検索に対して結果を提供しません。

混在ルールは両方のファミリを提供できます:

```ini
[DefaultBox]
NetworkDnsFilter=dual-stack.example:192.0.2.50;2001:db8::50
```

## フィルターの適用方法

Sandboxie は、サンドボックス化されたプロセスが Winsock を初期化するときにフィルターをインストールします。検索を開始、取得、および終了するために使用される標準の Winsock サービス検索シーケンスをインターセプトします。一致するルールはローカルで処理されます: Sandboxie は構成されたアドレスを返すか、結果が利用できないことを報告します。一致しない検索は通常のシステム パスを通じて続行されます。

このメカニズムは、通常のリゾルバーがその名前を知らない場合でも、フィルターが構成された名前を処理できることを意味します。リダイレクトがアップストリームの解決の成功に依存していた以前の制限は、Sandboxie Plus 1.16.0 / Classic 5.71.0 で削除されました。

## Block DNS テンプレート

SandMan の別個の **Block DNS, UDP port 53** オプションは `BlockDNS` テンプレートを有効にします。現在のテンプレートは、サンドボックス化されたプログラムのポート 53 への直接の送信 UDP トラフィックをブロックします:

```ini
Template=BlockDNS
```

これは `NetworkDnsFilter` を補完できますが、すべての形式の名前解決をフィルターに強制するわけではありません。TCP ポート 53、DNS over HTTPS、DNS over TLS、リモート プロキシの名前解決、または UDP ポート 53 を使用しない別のリゾルバー パスをブロックしません。

## SandMan の構成

**Sandbox Options > Network Options > DNS Filter** を開きます。テーブルには **Program**、**Domain**、および **IP** 列が含まれます。行を管理するには **Add Filter** と **Remove** を使用します。**IP** フィールドはセミコロンで区切られた複数のアドレスを受け入れます。

各行は有効または無効にできます。SandMan は無効な行を `NetworkDnsFilterDisabled` として保存します。その名前は 2 番目のランタイム フィルター設定ではなく、非アクティブな UI ストレージです。テンプレートによって提供される行は読み取り専用で表示されます。

## 構成変更の適用

ルールは、サンドボックス化されたプロセスが Winsock を初期化するときに読み込まれます。既にネットワークを初期化したプロセスに対して動的に再構築されることはありません。ルールを変更した後は、影響を受けるサンドボックス化されたプロセスを再起動してください。SandMan、Sandboxie サービス、またはドライバーを再起動する必要は通常ありません。

## 制限とセキュリティ境界

`NetworkDnsFilter` は、Sandboxie のインターセプトされた Winsock サービス検索パスに到達するサポート対象の検索をカバーします。普遍的なドメイン アクセス ポリシーを提供するものではありません。特に:

* 独自のリゾルバー、生の DNS トラフィック、または内部の DNS-over-HTTPS 実装を使用するアプリケーションは、この検索パスを回避できます。
* プログラムがローカルで解決せずにリモート解決のためにホスト名をプロキシに送信する場合、ローカル DNS フィルターはそのホスト名を受け取りません。
* 別個のネットワーク ポリシーがブロックしない限り、プログラムは既知の IP アドレスに直接接続できます。
* DNS フィルター処理と [`DnsTrace`](SandboxieTrace.md) は別個です。トレースはサポート対象の検索アクティビティを記録しますが、フィルター処理を有効にしません。

直接接続を防ぐ必要がある場合は、独立したネットワーク制限を使用してください。DNS フィルター処理は、ファイアウォールとして、またはすべての DNS アクティビティがブロック、リダイレクト、またはプライベートに保たれる保証として扱うべきではありません。
