# WinDbg の使用方法

まれなケースとして、Sandboxie の監督下で実行されているプログラムが、誤動作の原因について何の手がかりも提供せずに正しく動作しない場合があります。このような場合、Microsoft の無料の [Debugging Tools for Windows](https://docs.microsoft.com/en-us/windows-hardware/drivers/debugger/debugger-download-tools) が、問題の解明や問題の原因の特定に役立ちます。

* * *

最新リリースの [_Windows SDK_](https://developer.microsoft.com/en-us/windows/downloads/windows-sdk)（32 ビットと 64 ビットの両方）をダウンロードしてインストールします。

_Debugging Tools for Windows_ のみが必要な場合は、デバッグ ツールをスタンドアロン コンポーネントとしてインストールできます。

パッケージは既定で _C:\Program Files (x86)\Windows Kits\10\Debuggers_ にインストールされます。

パッケージは、Windows スタート メニューに _Windows Kits_ というアプリケーション グループを作成します。アプリケーション グループには _WinDbg_ プログラムが含まれます。

64 ビット Windows でも 32 ビット デバッガーを使用することをお勧めします。64 ビット デバッガーを使用する必要があるのは、64 ビット プログラムをデバッグする場合だけです。詳細については、[32 ビットまたは 64 ビットのデバッグ ツールの選択](https://docs.microsoft.com/en-us/windows-hardware/drivers/debugger/choosing-a-32-bit-or-64-bit-debugger-package)を参照してください。

* * *

**シナリオ 1: デバッガーからプログラムを開始する**

Sandboxie スタート メニューを使用して、Sandboxie の下でデバッガーを開始します。

* [Sandboxie Control](SandboxieControl.md) > [サンドボックス メニュー](SandboxMenu.md) > Run From Start Menu

* Sandboxie Plus ウィンドウ > サンドボックスを右クリック > Run > Run From Start Menu

次に、Sandboxie スタート メニューをナビゲートして、_Windows Kits_ グループ内の _WinDbg_ プログラムを探して呼び出します。

WinDbg デバッガーが起動し、メイン ウィンドウが開きます。

デバッガーで、File メニュー > Open Executable コマンドを呼び出します。次に、デバッガーで実行するプログラムの EXE ファイルにナビゲートして選択します。

たとえば、_C:\Windows\System32\notepad.exe_ にナビゲートして選択します。

デバッガーは、新しいプログラムを制御（またはデバッグ）するためのコマンド ウィンドウを開きます。

Debug メニュー > Go コマンドを使用して、プログラムの実行を開始します。(F5 を押すこともできます。)このとき、デバッガーのステータス行が *BUSY* に変わります。以下に示す **最終ステップ** というタイトルのセクションを読み進めてください。

* * *

**シナリオ 2: 実行中のプログラムにデバッガーをアタッチする**

このシナリオでは、Sandboxie を使用してすでにプログラムを開始しており、プログラムはすでに実行中です。

Windows スタート メニューからデバッガーを通常どおり開始します。_Windows Kits_ グループ内の _WinDbg_ プログラムを探して呼び出します。

WinDbg デバッガーが起動し、メイン ウィンドウが開きます。

デバッガーで、File メニュー > Attach to a Process コマンドを呼び出します。(F6 を押すこともできます。)次に、デバッガーをアタッチするプログラムの EXE ファイルを特定します。

デバッガーは、アタッチされたプログラムを制御（またはデバッグ）するためのコマンド ウィンドウを開きます。

プログラムがすでに問題を示した後にアタッチした場合は、以下に示す **最終ステップ** というタイトルのセクションを読み進めてください。

そうでなければ、Debug メニュー > Go コマンドを使用してプログラムの実行を続行します。(F5 を押すこともできます。)このとき、デバッガーのステータス行が *BUSY* に変わります。以下に示す **最終ステップ** というタイトルのセクションを読み進めてください。

* * *

**最終ステップ**

このセクションは、問題のプログラムがすでに問題を示していることを前提としています。

*   プログラムがループでスタックする場合、すでにスタックしているはずです。
*   プログラムがクラッシュする場合、すでにクラッシュしているはずです。

問題の状態がまだ発生していない場合は、ここでプログラムを誤動作させてください。

プログラムが問題を示したら、WinDbg デバッガーのコマンド ウィンドウに戻ります。デバッガーのステータス行がまだ *BUSY* と表示されている場合は、Debug メニュー > Break コマンドを使用してプログラムを停止します。(Ctrl+Break を押すこともできます。)

デバッガーのステータス行が *BUSY* と表示されなくなったら、次のコマンドを入力します。一度に 1 つのコマンドを入力し、Enter を押します。

```
    .sympath srv*C:\Symbols*https://msdl.microsoft.com/download/symbols
    .reload
    ~* k 99
```

3 番目のコマンドは、デバッガーに何らかの出力を生成させます。コマンドが完了したら、デバッグ ログ全体をコピーしてください。Edit メニュー > _Copy Window Text to Clipboard_ コマンドを使用してデバッグ ログ全体をクリップボードにコピーし、Sandboxie サポートに戻ってこのデバッグ ログをコメントに貼り付けてください。
