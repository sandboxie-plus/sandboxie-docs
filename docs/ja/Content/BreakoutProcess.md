# Breakout Process

_BreakoutProcess_ は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定で、Sandboxie Plus 1.0.8 / Classic 5.55.8 以降で利用できます。サンドボックス化されたプロセスが起動しようとしたときに、現在のサンドボックスを離れることができる実行可能ファイルを識別します。

```ini
[DefaultBox]
BreakoutProcess=viewer.exe
```

値は実行可能ファイルの **ベース名** (`viewer.exe` など) です。照合は完全一致で、大文字と小文字を区別しません。現在のブレイクアウト実装は、この設定に対して `*` や `?` をワイルドカードとして解釈せず、その値として完全な実行可能パスはサポートされていません。SandMan の実行可能ファイル ピッカーもベース名を保存します。

## ホスト実行可能ファイルの要件

サービスは、ターゲット実行可能ファイルをソース サンドボックスのファイル ルート外のホスト ファイルとして開いて解決できる場合にのみ、一致する `BreakoutProcess` 起動を受け入れます。そのルート内で解決される実行可能ファイル、ネットワーク/MUP パス、または開いたり解決したりできないターゲットは、このブレイクアウト チェックを通過しません。このホスト ファイル検証は `BreakoutProcess` に固有です。[Breakout Folder](BreakoutFolder.md) に適用されると想定しないでください。

## 強制プログラムとの相互作用

ブレイクアウトはサンドボックス外の宛先を保証しません。ブレイクアウト ルールを受け入れた後、サービスは別の有効なボックスで一致する [Force Process](ForceProcess.md) または [Force Folder](ForceFolder.md) ルールを見つけ、そこでプロセスを作成することがあります。そのチェックがソース ボックスに解決し直す場合、起動は代わりに通常のサンドボックス化されたプロセス作成パスに従います。複数のボックスがプロセスを捕捉する可能性がある場合、固定された優先順位に依存しないでください。

この設定は将来のプロセス起動に影響し、サンドボックスで既に実行中のプロセスには影響しません。サービス検証、返されるハンドルの制限、セキュリティへの影響、および SandMan コントロールについては [Breakout Execution](BreakoutExecution.md) を参照してください。
