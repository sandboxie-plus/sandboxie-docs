# ファイル復元アーキテクチャ

ファイル復元は、選択された内容をサンドボックスからホストにアクセス可能な宛先に移動します。復元可能な場所を構成しても、サンドボックス化されたプログラムにそのホストの場所へのアクセスが付与されるわけではありません。復元アクションは、ユーザーが何を復元するかを選択した後、サンドボックスの外側で実行されます。

## 復元は複数のコンポーネントに分割される

| コンポーネント | 役割 |
| --- | --- |
| 自動検出 | `AutoRecover=y` の場合、SbieDll はサンドボックス化されたプロセス内の対象となるファイル アクティビティを監視し、復元候補を報告します。 |
| クイック復元 | SandMan は、復元ウィンドウが開かれたときに構成された場所を別途スキャンします。`AutoRecover=y` は必要ありません。 |
| 表示 | SandMan は、その設定に従って復元ダイアログまたは通知を表示します。 |
| 宛先 | ユーザーは対応するホスト フォルダーまたは別のフォルダーを選択します。 |
| 復元操作 | SandMan は選択されたファイルをサンドボックス ストレージからホストの宛先に移動します。 |

## 復元可能な場所

繰り返し可能な [`RecoverFolder`](RecoverFolder.md) エントリは、自動検出とクイック復元の両方の場所またはパターンを識別します。リテラル フォルダーは再帰的なクイック復元スキャン ルートを提供します。ワイルドカード エントリは代わりに候補パスをフィルターします。パターンによって表されるすべてのパスを再帰的にスキャンする指示ではありません。有効なエントリは、ボックス構成と有効なテンプレートから取得される場合があります。`%Personal%` などのシェル フォルダー参照は、使用可能なパスに展開できます。

## 自動復元と即時復元

[`AutoRecover=y`](AutoRecover.md) は、有効な `RecoverFolder` および [`AutoRecoverIgnore`](AutoRecoverIgnore.md) エントリを使用してプロセス側の検出を初期化します。候補は復元可能な場所に一致し、無視エントリに一致しない必要があります。Sandboxie は、関連するファイル アクティビティの後、対象となる空でないサンドボックス化されたファイルを報告します。これは、作成された正確な瞬間にプロンプトが出るという約束ではありません。検出自体はファイルを移動しません。

SandMan は復元イベントを受信し、ダイアログを開くか通知を表示できます。その通知設定と一時的な抑制は、ユーザーが目にするものに影響する場合があります。自動検出は、クイック復元の無視オプションに関係なく `AutoRecoverIgnore` を適用します。

`AutoRecover` 設定が存在しない場合の SbieDll のフォールバックは無効です。新しく作成されたボックスは明示的にそれを有効にする場合があります。現在の SandMan の新規ボックス ウィザードは Immediate Recovery を既定でチェック済みで提供し、Classic の新規ボックスの既定値は `AutoRecover=y` を書き込みます。したがって、製品によって作成されたボックスと、有効な `AutoRecover` 値を持たないボックスは同じように動作する必要はありません。

## クイック復元

[クイック復元](QuickRecovery.md)を開くと、SandMan は有効な復元場所を読み取り、リテラル ルートを再帰的にスキャンします。ワイルドカード エントリは、スキャンを通じて見つかった候補をフィルターします。ウィンドウは、構成された復元場所だけでなく、すべてのボックス化されたファイルを表示することもできます。

SandMan は、[`UseAutoRecoverIgnoreForQuick`](UseAutoRecoverIgnoreForQuick.md) が有効な場合、クイック復元リストに `AutoRecoverIgnore` を適用できます。ウィンドウの **Show All Files** または **Show Ignored** ビューは、そうでなければ隠されているファイルを公開できます。このクイック固有のフィルタリングは、自動検出器自身の無視チェックを置き換えるものではありません。

設定メタデータは `UseAutoRecoverIgnoreForQuick` を `n` 既定で説明していますが、現在の SandMan コンシューマーは存在しない値を有効として扱います。明示的な `n` はその通常のクイック リスト フィルタリングをオフにします。これは SandMan コンシューマーの既定であり、SbieDll 全体の実行時既定ではありません。

## 宛先とファイルの移動

**Recover to Same Folder** はサンドボックスの外側の対応する場所を選択し、**Recover to Any Folder** はユーザーが別の宛先を選択できるようにします。SandMan は再利用可能な宛先履歴をユーザー設定 (`SbieCtrl_RecoverTarget`) と独自の最後の宛先設定に保持します。これらは `RecoverFolder` ボックス ルールではありません。

SandMan は宛先を準備し、選択されたサンドボックス ファイルにホスト側の移動 (`QFile::rename`) を使用します。ターゲットがすでに存在する場合、上書きする前に確認します。上書きを承認すると、移動前に既存のターゲットが削除される場合があります。失敗した移動は報告され、未復元のサンドボックス ソースが残ります。復元はアトミックであること、または以前に承認された上書きをロールバックすることを保証されません。

SandMan は、ファイルを移動する前に、インストールされた FileChecker アドオンまたは構成された [`OnFileRecovery`](SandManTriggers.md) コマンドを実行する場合があります。チェッカーの失敗は、ユーザーが警告を明示的に上書きしない限り、その復元を停止させることがあります。チェッカーとユーザーの承認は、復元された内容を開いたり実行したりしても安全であることを証明しません。

## 変更の適用

自動検出とそのフォルダー/無視リストは、各サンドボックス化されたプロセスで初期化されます。自動検出器に新しい値を使用させる必要がある場合は、`AutoRecover`、`RecoverFolder`、または `AutoRecoverIgnore` を変更した後、影響を受けるサンドボックス化されたプロセスを再起動してください。SandMan は復元ウィンドウが作成されるときに復元場所を読み取り、クイック リストの無視設定はスキャンと更新中に再読み込みされます。そのウィンドウの外で `RecoverFolder` を変更した後は、復元ウィンドウを再度開いてください。これらの SandMan 側の変更は、クイック復元のためにサンドボックス化されたプロセスを再起動する必要はありません。

## Classic と SandMan

古い[復元設定](RecoverySettings.md)、[クイック復元](QuickRecovery.md)、および[即時復元](ImmediateRecovery.md)ページは、有用な Sandboxie Control / Classic ワークフローとスクリーンショットを保持しています。現在の Sandboxie Plus コントロールは **Sandbox Options > File Recovery** にあり、別個の **Quick Recovery** および **Immediate Recovery** セクションがあります。SandMan の表示設定は **Global Settings > General Config** にあります。**Recovery Options** には復元ウィンドウの設定が含まれ、**Notifications** には **Show recoverable files as notifications** が含まれます。

## バージョン履歴

ワイルドカード復元パターンと `UseAutoRecoverIgnoreForQuick` は Sandboxie Plus 1.18.0 / Classic 5.73.0 で追加されました。これは、古い復元設定の導入を年代付けするものではありません。
