# Bind Adapter IP

*BindAdapterIP* は、一致するサンドボックス化されたプロセスにおいて、サポートされている Winsock 操作のためにリテラルのローカル IPv4 または IPv6 アドレスを選択します。Sandboxie Plus 1.15.10 / Classic 5.70.10 で導入されました。

アドレスは、動作中のホスト ネットワーク インターフェイスに割り当てられている必要があります。そのアドレスが消えた場合、ルールは新しい DHCP、VPN、またはアダプターのアドレスに自動的に移行しません。Sandboxie が名前付きアダプターの現在使用可能なアドレスに従う必要がある場合は、代わりに [*BindAdapter*](BindAdapter.md) を使用してください。

## 構文

```ini
BindAdapterIP=[process,]ip_address
```

`process` を省略すると、ルールがサンドボックス内のすべてのプロセスに適用されます。プログラム固有のルールには実行可能ファイル名を指定します。1 つのプロセスに対して 1 つの IPv4 アドレスと 1 つの IPv6 アドレスを選択できます。各アドレス ファミリは独立して評価されます。

例:

```ini
BindAdapterIP=192.0.2.25
BindAdapterIP=browser.exe,2001:db8::25
```

上記のアドレスはドキュメント用に予約されており、ローカル バインディングとして使用できません。ホスト上のアクティブなインターフェイスに実際に割り当てられているアドレスに置き換えてください。

ルールは、継承されたテンプレート設定を含む、サンドボックスの有効な構成から読み取られます。Sandboxie Plus インターフェイスはボックス全体の IPv4 および IPv6 の値を管理します。実行可能ファイル固有のルールには手動の [Sandboxie Ini](SandboxieIni.md) 構成が必要です。

## 動作と優先順位

一致するプロセスに対して、SbieDll はユーザー モードの Winsock 傍受レイヤーを通じて構成されたアドレスを適用します。これはサポートされている接続およびデータグラムのパスを対象としますが、ファイアウォールではなく、それらのパスをバイパスするネットワーク コードのカバレッジを保証するものではありません。

該当する *BindAdapter* ルールは、*BindAdapterIP* よりも構成の優先順位が高くなります。構成された名前付きアダプターが利用できない場合、リテラル IP ルールはフォールバックとして使用されません。

*StrictBindIP* は既定で有効です。通常の傍受されたパスでは、利用できないアドレスまたは構成されていないアドレス ファミリが、バインドされていない接続にフォールバックするのを防ぎます。`StrictBindIP=n` の場合、バインドを適用できないときに Windows が別のローカル アドレスまたはインターフェイスを選択することがあります。構文、影響を受ける操作クラス、および制限については [Bind Adapter](BindAdapter.md#strictbindip) を参照してください。

*BindAdapterIP* はリテラル アドレスを識別するため、DHCP の更新、VPN の再接続、またはその他のホスト ネットワークの変更によって利用できなくなることがあります。Sandboxie は、アドレスが動作中のインターフェイスに割り当てられたままであるかどうかを再検証しますが、代替アドレスを使用するようにルールを書き換えることはありません。構成されたルールを変更した後は、影響を受けるサンドボックス化されたプロセスを再起動してください。通常、SandMan または Sandboxie サービスの再起動は必要ありません。

## Sandboxie Plus インターフェイス

**Sandbox Options** > **Network Options** > **Other Options** を開きます。**Bind to Adapter IP** グループで、**None (Don't bind to adapter)** を選択し、**IPv4:** または **IPv6:** フィールドにアドレスを入力します。

共有の SbieDll ランタイムは Sandboxie Classic でも使用されます。Sandboxie Classic は、機能が利用可能な場合は互換性のある手動構成を利用できますが、同等の最新のインターフェイスは提供しません。

## セキュリティ上の制限

*BindAdapterIP* は、サポートされているユーザー モード ソケット パス上の送信元アドレスを制御します。WFP ルールを作成したり、絶対的なインターフェイス閉じ込めを提供したりするものではありません。別のインターフェイスを介した直接トラフィックを防ぐ必要がある場合は、別個のネットワーク ポリシーを使用してください。[Windows Filtering Platform](../PlusContent/WFPSupport.md) を参照してください。
