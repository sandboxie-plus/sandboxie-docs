# SBIE2329

**Message** SBIE2329 Failed to find FFS sequence %2

**Severity**: Error (popup)

## 説明

このメッセージは、Sandboxie の DLL フック インストーラーが関数の Fast-Forward Sequence (FFS) ターゲットを見つけようとしたが、期待される命令パターンを認識できないときに発生します。Sandboxie は FFS 検出を使用して、小さなトランポリン スタブ (一般にブラウザーやその他のアプリケーションで使用される) をたどって実際の/ネイティブのターゲットに到達し、そこにフックをインストールします。そのシーケンスが見つからないか解決できない場合、SBIE2329 がログに記録され、フック インストーラーは別のフック戦略にフォールバックするか、失敗を報告する場合があります。

メッセージには、FFS シーケンスが見つからなかった関数の名前が含まれます。

## 一般的な原因

- ターゲット バイナリが変更され (新しいブラウザーまたはアプリケーションのバージョン)、ヒューリスティック パターンが一致しなくなりました。
- 関数プロローグが異なる方法でコンパイルまたは最適化されている (異なるツールチェーン、コンパイル時オプション) ため、FFS パターンが存在しません。
- コードが難読化、パック、または期待される FFS テーブル/ポインターを含まない小さなスタブに置き換えられています。
- アーキテクチャ/互換性の違い (x86 対 x64 対 ARM) により、利用可能なヒューリスティックが観察されたパターンをカバーしていません。

## 推奨される操作

1. 最新の Sandboxie ビルドに更新します — フック ヒューリスティックは新しいブラウザー/アプリケーションのレイアウトを処理するために定期的に更新されます。[^1]
2. 同じプログラムの別のビルドまたはベンダー (別の Chromium ベース ビルド、別の Firefox ビルド) でテストして、問題が特定のビルドに固有かどうかを確認します。[^2]
3. その特定の関数のフックが必須でない場合は、その関数/モジュールをフックからスキップしてヒューリスティックを無効にします (関数レベルまたはモジュール レベルのスキップ設定、または DLL によって公開されるトレース/フック スキップ構成を使用します)。これにより、名前付き関数に対する FFS 解決の試みが防止されます。[^3]
4. メンテナーに報告するための診断情報を収集します: プロセス イメージ名、モジュール名とベース、関数名 (ポップアップで報告されたとおり)、OS ビルド、および関数プロローグの小さなメモリ ダンプまたは逆アセンブリ。これにより、メンテナーがヒューリスティックを更新できます。[^4]

## 実装上の注意と脚注

これらの注意は、SBIE2329 がどのように、どこで生成されるかを追跡したいメンテナーおよび上級ユーザーを対象としています。行番号は意図的に省略されています。

[^1]: FFS 検出と解決のヘルパーは common/hook_util.c に実装されています (Hook_GetFFSTarget、Hook_GetFFSTargetOld、Hook_GetFFSTargetNew などの関数)。これらの関数には、FFS プロローグ シーケンスを認識して実際の/ネイティブのターゲット アドレスに解決するアーキテクチャ対応のヒューリスティックが含まれています。

[^2]: DLL フック インストーラー (core/dll/dllhook.c) は、フックをインストールしようとするときに Hook_GetFFSTarget() を呼び出します。FFS ターゲットが見つからない場合、フック パスはログ API への呼び出しを介して SBIE2329 をログに記録し (コードは未解決の FFS ケースに対して SbieApi_Log(2329, ...) を呼び出します)、FFS ターゲットの不在を示すフック統計を記録します。

[^3]: Hook_GetFFSTarget() は、同じ解決ロジックに依存する他の場所 (たとえば core/low/inject.c および core/dll/gui.c のインジェクションおよびトレース コード パス) から再利用されるため、同じヒューリスティックがトランポリンを解決できない場合、複数のサブシステムで障害が表面化する可能性があります。

[^4]: バグ レポートを提出するときは、ポップアップに表示された関数名とモジュール イメージ (または小さな抽出されたプロローグ/逆アセンブリ) を含めてください。この情報は通常、メンテナーがパターンを再現してヒューリスティックを拡張するのに十分です。
