# システム コール設定

## 概要

Sandboxie は、その分離と互換性のアーキテクチャの一部として、選択されたネイティブ システム コールを仲介します。この仲介には、呼び出しのための Sandboxie ハンドラーと、呼び出しが処理されている間のセキュリティ トークンの一時的な選択の両方が関与する場合があります。これらは別個の決定です。

Sandboxie はすべての Windows システム コールを傍受するわけではなく、システム コールの仲介はその唯一の分離レイヤーではありません。ファイルとレジストリのフィルタリング、カーネル オブジェクトのフィルタリング、仮想化、ネットワーク ポリシー、およびその他のコントロールは別々に動作します。Sandboxie のトークン アーキテクチャの背景については、[トークンとシステムコールの内部](TokenMagic.md)を参照してください。

## SysCallLockDown

ボックス全体の設定は次のとおりです。

```ini
SysCallLockDown=y
```

`SysCallLockDown=y` は、プロセスの傍受されたシステム コールをロックダウン モードにします。Security Hardened モードを有効にする `UseSecurityMode=y` も、プロセスにこのロックダウン動作を使用させます。

ロックダウンなしでは、Sandboxie の仲介パスは、傍受された呼び出しを処理するために必要に応じて元のまたは完全なトークンを一時的に使用できます。ロックダウンが有効な場合:

- 承認された傍受された呼び出しは、その元の/完全なトークン実行パスを使用できます。
- 承認されていない傍受された呼び出しは、そのパスを受け取らず、制限されたサンドボックス トークンの下で続行されます。
- 呼び出しは依然として実行できますが、制限されたトークンが必要な権限を欠いている場合は失敗する可能性があります。

したがって、`SysCallLockDown` は、すべての未承認システム コールをブロックする単純なリストではありません。Sandboxie が仲介する傍受されたパス内のトークン選択の決定を制御します。

Security Hardened モードと `SysCallLockDown` の直接使用には、有効な[サポーター証明書](../PlusContent/supporter-certificate.md)が必要です。

## 承認されたシステム コール

承認は、ロックダウンがアクティブな間に、傍受されたシステム コール エントリを元の/完全なトークン実行の対象としてマークします。Sandboxie の傍受を無効にしたり、関連する Sandboxie ハンドラーをバイパスしたり、呼び出しをサンドボックスの外で実行したりするものではありません。ファイル、レジストリ、オブジェクト、およびその他の独立したフィルタリングも引き続き有効です。

`ApproveWinNtSysCall` と `ApproveWin32SysCall` はグローバル承認マップを設定します。Sandboxie は個々のサンドボックスのための別個のマップを維持しません。組み込みの承認は `Templates.ini` の `[SysCallPresets]` セクションから来ます。カスタム承認は `[GlobalSettings]` に直接書き込むか、`[GlobalSettings]` を通じて有効にされたカスタム テンプレートによって提供できます。

個々のサンドボックス セクション内の、または特定のサンドボックスのためにのみ有効にされたテンプレート内の承認エントリは、これらのグローバル マップが構築されるときに参照されません。したがって、システムコールの承認はボックスごとのメカニズムではありません。カスタム承認は狭く保ってください。承認されたすべてのエントリは、ロックダウン下でのその呼び出しの元の/完全なトークン パスの対象を復元します。組み込みの承認はサポートされているシナリオのために維持されており、カスタム構成に丸ごとコピーすべきではありません。

### NT システム コール {#nt-system-calls}

`ApproveWinNtSysCall` は名前をグローバル NT システム コール承認マップに追加します。名前は `Nt` または `Zw` プレフィックスなしのドライバー エントリ名を使用します。直接のカスタム承認は `[GlobalSettings]` を使用します。例:

```ini
[GlobalSettings]
ApproveWinNtSysCall=OpenFile
ApproveWinNtSysCall=CreateFile
```

これらの例は構文を示すだけです。一般的に推奨される承認リストを構成するものではありません。

### Win32k システム コール {#win32k-system-calls}

`ApproveWin32SysCall` は、傍受された Win32k システム コールのための対応するグローバル承認メカニズムです。直接のカスタム承認は一致するパターンを使用できます。

```ini
[GlobalSettings]
ApproveWin32SysCall=GdiDdDDI*
```

Win32k 承認は、Sandboxie の Win32k システム コール フッキング パスが利用可能でプロセスのためにインストールされている場合にのみ効果があります。承認は依然としてロックダウン トークンの決定を制御します。一致する呼び出しのためにインストールされた Sandboxie ハンドラーをバイパスするものではありません。

## 構成の再読み込み

現在の Sandboxie バージョンは、ドライバー構成が再構成されるときに NT および Win32k 承認マップを再読み込みします。承認エントリを編集した後は、新しいマップが適用されるように **Options > Reload configuration** を使用してください。これらの承認リストの変更のためだけにドライバーの再起動は通常は必要ありません。

これは承認マップを更新します。すでに実行中のプロセスに割り当てられたトークンを再構築したり、プロセスが開始されたときにインストールされたシステム コール フックを変更したりしません。より広範なシステム コール構成の変更をテストするときは、影響を受けるサンドボックス化されたプロセスを再起動してください。

## OpenAllSysCalls

ボックス全体のデバッグ設定は次のとおりです。

```ini
OpenAllSysCalls=y
```

その名前にもかかわらず、`OpenAllSysCalls` は単に「すべてのシステム コールを許可する」わけでも、完全なサンドボックスを無効にするわけでもありません。`OpenAllSysCalls=y` は、インストールされた Sandboxie 第 1 段ハンドラーを持つ NT システム コール エントリにそのハンドラーをバイパスさせ、基になるシステム コール パスを直接呼び出させます。同じ内部ゲートが Win32k ディスパッチ パスにも存在しますが、現在の Win32k テーブルはそのパスに第 1 段ハンドラーをインストールしません。

ロックダウン トークンの決定は独立しており、このハンドラー決定の前に発生します。したがって、`OpenAllSysCalls=y` は `SysCallLockDown` を無効にせず、すべての呼び出しが元のトークンで実行されるようにするものでもありません。プロセスがロックダウンされており、傍受された呼び出しが承認されていない場合、制限されたトークンの動作が依然として適用されます。`OpenAllSysCalls` を有効にしても、その呼び出しに元の/完全なトークン実行が付与されるわけではありません。

> [!WARNING]
> プロジェクトは `OpenAllSysCalls` を明示的に安全でないデバッグ オプションとして分類しています。フックされたエントリに対してセキュリティ、仮想化、フィルタリング、または互換性の動作を提供する可能性がある、インストールされた Sandboxie 第 1 段ハンドラーをバイパスすることにより、システム コール レベルの仲介を弱めます。これはデバッグまたは非常に特定の互換性調査を目的としており、通常のサンドボックス構成としてではありません。

この設定は、ファイルとレジストリのフィルタリング、カーネル オブジェクト コールバック、ネットワーク ポリシー、またはその他の独立した Sandboxie コントロールなどの無関係なレイヤーを自動的に無効にしません。

## セキュリティ上の考慮事項

- 確認された互換性の問題によって必要とされる特定の呼び出しのみを承認してください。
- 組み込みの `[SysCallPresets]` 承認を、コピーする一般的なリストとしてではなく、維持された実装ポリシーとして扱ってください。
- 承認は一時的なトークン コンテキストを変更します。呼び出しの通常のハンドラーを削除するものではありません。
- `OpenAllSysCalls` は承認よりも多くの仲介を削除し、定期的な互換性スイッチとして使用すべきではありません。
- アプリケーションが動作することは、広範な承認またはデバッグ バイパスが意図された分離境界を保持する証拠ではありません。
