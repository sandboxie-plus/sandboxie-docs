# Breakout Document

_BreakoutDocument_ は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定で、Sandboxie Plus 1.15.0 / Classic 5.70.0 以降で利用できます。サポートされている Shell のドキュメント オープン要求から一致するパスをホストの Shell にルーティングできるため、ドキュメントがソース サンドボックスの外で開かれることがあります。プロセス ディレクトリの [Breakout Folder](BreakoutFolder.md) ルールとは別個です。

```ini
[DefaultBox]
BreakoutDocument=C:\Documents\*.pdf
BreakoutDocument=C:\Pictures\*.jpg
```

ルールは、傍受された `ShellExecuteExW` 要求に渡されたファイル/パス テキストに対して、このパス用の Sandboxie パターン構文を使用して大文字と小文字を区別せずに照合されます。ファイルの内容を検査したり、MIME タイプを検証したり、アプリケーションがドキュメントを開くすべての方法を対象としたりするものではありません。一致する要求はユーザー セッション プロキシによって再検証され、ホストの Shell に `open` 動詞でそのパスを開くように要求します。元の Shell 動詞、パラメーター、および作業ディレクトリはそのまま転送されません。

> **セキュリティ警告:** ホスト側で開くと、ソース サンドボックスの外でアプリケーションが起動したり、コンテンツが実行されたりする可能性があります。ルールは意図したパスとドキュメントの種類に限定してください。`BreakoutDocument=C:\path\*` のような広範なルールは、スクリプトや実行可能ファイルをサンドボックス外で実行できるようにする可能性があります。

SandMan の **Breakout Document** ワークフローはフォルダーと拡張子を要求し、広範または危険な選択について警告します。これらのチェックはインターフェイスでエントリを作成するときに適用され、実行時の拡張子許可リストではありません。手動で編集した INI には、より広範なパターンを含めることができます。

このルールは将来のサポートされている Shell オープン要求に影響し、完了したオープンや任意のファイル アクセスには影響しません。アーキテクチャ、Explorer 互換ブリッジ、その他のブレイクアウト設定、および SandMan コントロールについては [Breakout Execution](BreakoutExecution.md) を参照してください。
