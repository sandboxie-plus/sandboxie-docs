# Inject Dll

_InjectDll_ は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定で、対象となるサンドボックス化された x86 プロセスの起動中に追加の DLL を読み込みます。「インジェクト」とはそのプロセスに DLL を読み込むことを意味し、すべてのサンドボックス化されたプログラムが必須の読み込み段階に到達することを保証するものではありません。例:

```ini
   .
   .
   .
   [DefaultBox]
   InjectDll=c:\Program Files\Sandboxie Utilities\Sample.dll
```

## アーキテクチャの選択

適用される SbieDll ビルドが 1 つの設定リストを選択し、Windows のアーキテクチャだけが選択するわけではありません。別のアーキテクチャのリストへのフォールバックはありません。ターゲット プロセスと互換性のある DLL を使用してください:

| 実行コンテキスト | 設定 |
| --- | --- |
| x86 | `InjectDll` |
| x64 Windows 上の x86 | `InjectDll` |
| ネイティブ x64 | `InjectDll64` |
| ネイティブ ARM64 | `InjectDllARM64` |
| ARM64 上の x86 エミュレーション | `InjectDll` |
| Sandboxie の ARM64EC 固有ビルドを使用した ARM64 上の x64 | `InjectDll64` |

x64 パスには [InjectDll64](InjectDll64.md) を使用してください。ネイティブ ARM64 は `InjectDllARM64` を使用します。x64-on-ARM64 のマッピングは、検査されたソース/ビルド モデルを表すものであり、任意の ARM64EC DLL との独立したランタイム テスト済みの互換性ではありません。[設定の選択](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/core/dll/ldr_init.c#L34-L60) および [ARM64EC ビルド定義](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/Sandbox64ec.props#L14-L18) を参照してください。

## 構成と DLL パス

エントリは、サンドボックス化されたプロセスに関連付けられた有効な構成から取得されます。直接のサンドボックス値、該当する有効なテンプレート、および `GlobalSettings` 値が関与することがあります。複数の DLL に対して設定を繰り返してください。[構成の照会](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/core/dll/sbieapi.h#L371-L372) は変数展開を無効にしますが、テンプレートやグローバル フォールバックは無効にしません。[ドライバーの検索](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/core/drv/conf.c#L1505-L1567) が有効な値を提供します。

各値は DLL パスです。このコンシューマーは、実行可能ファイル名のプレフィックス、ProcessGroup、またはワイルドカードや否定のプロセス セレクターを解釈しません。

DLL への完全なパスを指定する必要があります。DLL ファイル自体がサンドボックス内にある場合、サンドボックス内の完全なパスを指定します。ファイルはターゲット プロセスのコンテキストでアクセス可能であり、互換性のあるアーキテクチャを持ち、該当するイメージ マッピング制限を満たす必要があります。パスを構成しても、読み込みの成功は保証されません。

インストール相対形式はバックスラッシュで始まります:

```ini
[DefaultBox]
InjectDll=\Extensions\Example.dll
```

ローダーは、結合されたパスがその長さチェックに収まる場合、この形式の先頭に Sandboxie インストール ディレクトリを付けます。これは汎用的なファイルシステム ルート パスではありません。バックスラッシュで始まる UNC 形式またはネイティブ パスが元の意味を保持すると想定しないでください。

[追加 DLL ローダー](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/core/dll/ldr_init.c#L178-L274) は、大文字と小文字を区別せずに `.dll` サフィックスを要求し、リテラル `..` をどこかに含む文字列をスキップします。構成変数を展開したり、一般的なパスの正規化を実行したりしません。一部の他の相対文字列はネイティブ ローダーに到達しますが、これは検証された任意の相対パス検索契約ではありません。ベアまたは相対の DLL 名に依存しないでください。

## 起動と複数の DLL

現在の起動パスは、[静的にインポートされた DLL](https://learn.microsoft.com/en-us/windows/win32/dlls/load-time-dynamic-linking) の通常の初期化後、元の実行可能ファイルのエントリポイント前に、構成された DLL を読み込みます。残りの Sandboxie エントリポイントの初期化は、構成された読み込みとコールバックに従います。これは古い固定のシステム DLL 順序を置き換えるものであり、すべての Windows DLL の順序を保証するものではありません。[エントリポイント パス](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/core/dll/ldr_init.c#L736-L910) を参照してください。

SbieDll はこの起動パスに到達し、実行可能ファイル エントリポイントのインターセプトをインストールする必要があり、プロセスはそのエントリポイントに到達する必要があります。実行可能ファイル エントリポイントがゼロの場合、このインターセプト パスが妨げられます。早期終了や初期化の失敗も、構成された読み込みを妨げることがあります。

エントリは、有効な列挙順に順次処理されます: 値を照会し、その文字列を検証し、ネイティブ読み込みを試み、読み込みの成功後にオプションのコールバックを呼び出してから次のエントリに進みます。依存関係、コールバック、およびその他のローダー アクティビティが追加の DLL 読み込みを引き起こすことがあるため、明示的なリストがモジュール読み込みの全体的な順序を確定するものではありません。

コンシューマーはエントリを並べ替えたり重複排除したりしません。重複するエントリは、読み込みの試行とコールバック検索を繰り返す原因になることがありますが、Windows の `DLL_PROCESS_ATTACH` 通知が繰り返されることを保証するものではありません。読み込みはトランザクションではなく、自動ロールバックも提供しません。

## オプションの InjectDllMain コールバック

読み込みが成功した後、Sandboxie は最初に `InjectDllMain` を探し、最初の検索でアドレスが得られない場合は `_InjectDllMain@8` を探します。コールバックはオプションです。一致するエクスポートを持たない DLL は読み込まれたままにできます。コードでコールバックを宣言します:

```c
__declspec(dllexport) void __stdcall InjectDllMain(
    HINSTANCE hSbieDll,
    ULONG_PTR UnusedParameter);
```

コールバックは同期的です。その最初の引数は読み込まれた SbieDll モジュール ハンドルであり、インジェクトされた DLL のハンドルではありません。2 番目の引数はゼロです。ローダーは戻り値を使用しません。DLL の読み込みが成功しただけでは、コールバックが見つかったことや正常に実行されたことを証明しません。

C++ 実装には適切な C リンケージ (`extern "C"`) を使用し、実際のエクスポート名と ABI を確認してください。x86 の `__stdcall` 装飾は重要です。他のアーキテクチャとツールチェーンは異なる規約を使用することがあります。[現在の検索](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/Sandboxie/core/dll/ldr.c#L1288-L1341) の寛容なマッチングの詳細に依存するのではなく、意図したエクスポート名を使用してください。

SbieDll のエントリポイントを解決するときは `hSbieDll` を使用することをお勧めします。指定されたハンドルは、ファイル名を仮定せずにインスタンスを識別します。`LoadLibrary` または `GetModuleHandle` も適切な場合に名前で SbieDll を特定できますが、指定されたハンドルと普遍的に同等であると想定すべきではありません。このコールバックは、別個の `SbieDll_RegisterDllCallback` API とは異なります。

## SandMan と Classic の構成

**Sandbox Options > Various Options > Dlls & Extensions** で、SandMan はインストールされたアドオンによって提供される DLL マッピングを管理し、任意のカスタム DLL パスは管理しません。アドオンは x86、x64、および (ネイティブ ARM64 SandMan ビルドでは) ARM64 マッピングを提供できます。

チェック済み、部分的にチェック済み、および未チェックの状態は、認識されたアドオン アーキテクチャ マッピングに対するボックス直接リスト内の一致を反映します。部分的な状態は継承の指標ではありません。パネルは完全な有効なテンプレート/グローバル構成を表示しないため、アドオンがチェックされていないことは、継承された DLL エントリが適用されないことを証明しません。

アドオンの状態を変更すると、一致する DLL サフィックスを持つ直接エントリが削除または置き換えられることがあります。これには、そのサフィックスを持つ別のコピーへの手動構成されたパスも含まれます。そのサフィックスの一致のないエントリは保持されます。[パネルの読み込み](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/SandboxiePlus/SandMan/Windows/OptionsAdvanced.cpp#L237-L286) および [保存](https://github.com/sandboxie-plus/Sandboxie/blob/43b629be6c17628e6298befccfec279774895ba5/SandboxiePlus/SandMan/Windows/OptionsAdvanced.cpp#L509-L546) のコードを参照してください。

任意のカスタム パスについては、[Sandboxie Ini](SandboxieIni.md) を手動で編集します。SandMan は **Edit ini Section > Edit ini** も提供します。[Sandboxie Control](SandboxieControl.md) Classic には、同等のアドオン パネルはありません。その **Configure > Edit Configuration** ワークフローは INI エディターを開き、エディターの終了後に構成を再読み込みできます。

## 変更の適用

編集ワークフローで必要なように構成を保存/再読み込みしてから、変更された DLL リストを確実に適用するために影響を受けるサンドボックス化されたアプリケーションを再起動します。新しく開始された対象プロセスは、更新された有効なエントリを使用できます。通常のリスト変更のためだけに、サービス、ドライバー、または Windows の再起動が本質的に必要なわけではありません。

既に初期化されたプロセスはリストを自動的に再列挙せず、エントリを削除しても、それらに既に読み込まれた DLL が自動的にアンロードされるわけではありません。再読み込み前に作成されたがまだ起動時の照会に到達していないプロセスは、更新された値をまだ認識できることがあります。

## 失敗と信頼

- 有効なエントリがない場合、これらの設定からの追加 DLL はありません。サイズが大きすぎる値はスキップされることがあり、他の構成照会の失敗は列挙を停止させることがあります。
- 誤った拡張子またはリテラルの `..` はそのエントリをスキップさせます。以降のエントリは依然として処理されます。
- 通常のネイティブ読み込みの失敗 (DLL の欠落、アクセス不能、または非互換など) はコールバックを呼び出さず、通常は次のエントリを試行できるようにします。該当するイメージ マッピング ポリシーも読み込みを拒否することがあります。
- コールバックの欠落は読み込みの失敗ではありません。コールバックの障害には、実証されたローカル例外分離バリアがなく、以降の読み込みや起動を中断させることがあります。早期の初期化またはエントリポイント インターセプトの失敗は、このパスを完全に妨げることがあります。

通常の読み込み失敗からの続行は、割り当ての失敗、コールバックの障害、または起動の失敗に対する保証ではありません。これらの設定は普遍的な回復または再試行メカニズムを提供せず、失敗は他の Windows または Sandboxie コンポーネントによって診断されることがあります。

信頼できるアーキテクチャ互換の DLL のみを読み込み、その保存場所を意図しない変更から保護してください。書き込み可能なサンドボックス場所にある DLL は、後のプロセスが読み込む前に変更されることがあります。通常のインジェクトされたコードは、既存の ID と制限の下でターゲットのサンドボックス化されたプロセス内で実行されます。それを読み込んでも、独立して無制限のホスト特権が付与されたり、該当するファイルおよびイメージ マッピング ポリシーがバイパスされたりするわけではありません。

[Host Injection](HostInjection.md) は、ターゲット ID、パス制限、および初期化動作が異なる別個のパスです。その `HostInjectDll*` の例を通常の `InjectDll*` のガイダンスとして使用しないでください。

参照: [InjectDll64](InjectDll64.md)、[SBIE DLL API](SBIEDLLAPI.md)、[Start Command Line](StartCommandLine.md)。
