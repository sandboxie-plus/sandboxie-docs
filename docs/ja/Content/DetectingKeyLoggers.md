# Detecting Key Loggers

[Help Topics](HelpTopics.md)、[Usage Tips](UsageTips.md) に移動します。

* * *

### 概要

すべてのクラスのキーロガーを確実に検出することは非常に困難です。このセクションでは、まずその理由を説明し、最後にそれらに対する可能な防御策を提供します。

まず、キーロガーのいくつかのクラスを区別する必要があります:

*   外部キーロガー
*   ルートキット キーロガー
*   Windows フック キーロガー
*   Windows メッセージ キーロガー
*   スクリプト キーロガー

### 外部キーロガー

外部 (またはハードウェア) キーロガーは、何らかの方法でコンピューターに接続するデバイスです。2 つの例は、キーボードとコンピューターの間に接続される小さなデバイス、またはワイヤレス キーボードから送信される無線信号を傍受するデバイスです。

このクラスのキーロガーの共通の原理は、それらがスパイしている Windows システムに対して _外部_ であることです。Windows 内で実行されるソフトウェアは、外部キーロガーを検出、削除、または防御することができません。

ここで説明する他のクラスのキーロガーは、Windows 内で実際に動作するソフトウェア キーロガーです。

### ルートキット キーロガー

ルートキット キーロガーは、通常は 2 番目のキーボード ハードウェア ドライバー (Windows の用語では _フィルター_ ドライバー) として自身を位置付けることにより、最も低いソフトウェア レベルでキーストロークを記録します。

一度インストールされると、このクラスのキーロガーは最高のログ記録機能を提供する可能性があり、取り除くのが難しいことがあります。しかし、そもそもインストールされるには、このキーロガーはオペレーティング システムの明示的な助けを必要とするため、Sandboxie によって容易にブロックされます。

### Windows フック キーロガー

これらのキーロガーはハードウェア ドライバーを装いませんが、それでもデスクトップで実行されているすべてのプログラムに自身を読み込む (または _フックする_) ようオペレーティング システムに要求する必要があります。

アプリケーションが通常の操作の一部としてそのようなフックをインストールすることは珍しくなく、それらをすべてブロックすると一部のプログラムがサンドボックス内で正常に実行できなくなります。

### Windows メッセージ キーロガー

このクラスのキーロガーはオペレーティング システムからの支援を必要とせず、1 つのプログラム内のアクティビティのみを確実に記録できます。ただし、Sandboxie のような監視プログラムの観点からは、それらは疑わしいことを何も行わないため、止めることができません。

デスクトップで実行されているプログラムがキーボード入力を実際に処理するために、オペレーティング システムはそのプログラムに入力を説明するメッセージを送信します。メッセージ キーロガーは、ログ記録されているプログラムと同じプロセス空間で実行されている可能性が高く、疑いを招かないさまざまな方法でこれらのメッセージを傍受できます。

通常、このキーロガーは秘密の Web ブラウザー プラグイン (またはプラグインの秘密のコンポーネント) であるため、Web ブラウザーに関連するキーボード アクティビティを簡単に記録できます。

### スクリプト キーロガー

このクラスのキーロガーは、あなたが訪問する Web サイトを標的にして侵害します。これは、あなた自身のコンピューターを標的にして侵害する、ここで説明する他の 3 つの形態のキーロガーとは対照的です。

JavaScript および VBScript 言語は、Web ページがキーストロークに反応するための機能を提供します。これらの機能の正当な使用は、洗練された Web ページの作成を可能にします。たとえば、Google や Yahoo! の検索が、考えられる検索文字列を提案するために入力したキーにどのように反応するかを考えてみてください。

Web サイトのセキュリティ上の弱点を悪用して、スパイはサイト内のページの 1 つにスクリプト キーロガーを埋め込みます。これらのキーロガーは、同じサイト上の他のスクリプトと実質的に区別できず、同じスクリプト機能を使用してキーストロークに反応し、それらを記録したりサードパーティのサイトに送信したりできます。

### キーロガーに対する防御 {#defending-against-key-logger}

Sandboxie はキーロガーを検出または無効にするようには設計されていませんが、サンドボックス化されたソフトウェアがサンドボックス内に留まること、そのようなソフトウェアが Windows に統合できないこと、およびサンドボックスを削除したときに完全に破棄できることを保証するよう設計されています。

これは、信頼できないアクティビティをすべてサンドボックス内で実行するよう注意すれば、常にサンドボックスを削除してそのアクティビティの影響を元に戻し、コンピューターを信頼できる状態に復元できることを意味します。

最初のステップは、Sandboxie を使用する前に、システムが悪意のあるキーロガーに感染していないことを確認することです。ここでは、アンチウイルスまたはアンチマルウェア ツールによるシステム スキャンが役立ちます。

次に、Web の閲覧、電子メールの読み取り、未知のプログラムのテストなどの信頼できないアクティビティをすべて、サンドボックスの制限された領域内でのみ実行します。これはキーロガーに感染しないことを意味するものではありませんが、それらを取り除くことができることを意味します:

*   すべてのサンドボックス内のすべてのアクティビティを停止するよう Sandboxie に指示することで、それらをすべて確実に停止できます。
    *   [File Menu](FileMenu.md#terminate-all-programs) および [Tray Icon Menu](TrayIconMenu.md#terminate-all-programs) の **Terminate All Programs** コマンドも参照してください。
*   一度停止すると、サンドボックスの内容を削除することで、それらのプログラム コードの痕跡を破棄できます。
    *   [Delete Sandbox](DeleteSandbox.md) も参照してください。

一度破棄されると、それらはあなたのキーボード アクティビティを記録できなくなり、信頼できるサイトを閲覧してパスワードを入力しても安全です。

サンドボックスを定期的に削除したくない場合は、信頼できる閲覧用に 1 つのサンドボックスを確保し、信頼できるアクティビティを実行する前にそのサンドボックスだけを削除できます。ただし、最大限の保護のために、まずすべてのサンドボックス内のすべてのサンドボックス化されたアクティビティを停止することが依然として重要です。

* * *

キーロガーに対するもう 1 つの保護手段は、キーロガーが記録した情報を送信するのを防ぐために、Web ブラウザー以外のあらゆるものに対してインターネットへのアクセスを拒否するよう Sandboxie を構成することです。[Program Settings](ProgramSettings.md#internet) の "インターネットにアクセスできる唯一のプログラム" の設定を参照してください。

2 つの注意点に注意してください:

*   インターネット アクセス機能は、適切なファイアウォールの代替でもなく、キーロガーに対抗または妨害するメカニズムとして設計されたものでもありません。

*   一部のキーロガーは、Web ブラウザーをハイジャックして、記録された情報を送信するための媒体として使用することで、インターネット アクセス制限を回避する可能性があります。
