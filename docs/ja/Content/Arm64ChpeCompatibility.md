# ARM64 および CHPE 互換性

Sandboxie は Windows on ARM64 でいくつかのプロセス アーキテクチャをサポートしますが、それらはすべて同じインジェクション パスを使用するわけではありません。その CHPE 回避策は主に、強制ルールによって選択されたプログラムを含む x86 プロセスを Sandboxie の x86 フックと互換にするためのものです。セキュリティ強化設定ではありません。

## サポートされているアーキテクチャ

| Windows on ARM64 上のプロセス | 現在の Sandboxie の動作 |
| --- | --- |
| ネイティブ ARM64 | ARM64 ドライバー、低レベル インジェクション、システムコール フック、および SbieDll ビルドによってサポートされます。 |
| ARM64 上の x64 プロセス | AMD64 ターゲットとして検出され、Sandboxie によって ARM64EC 固有の低レベル インジェクション パスと ARM64EC SbieDll ビルドを通じて処理されます。これはネイティブ ARM64 とは別個であり、すべてのアプリケーションが互換であることを保証するものではありません。 |
| CHPE バイナリなしのエミュレートされた x86 | x86/WoW64 パスと x86 SbieDll を通じてサポートされます。 |
| ARM32 | 実装されていません。サンドボックス インジェクションを試みると `SBIE2338` を報告し、プロセスはサンドボックス内で開始できません。ARM32 は x86 ではありません。 |

Sandboxie はインジェクション中にターゲット プロセスのアーキテクチャを検出します。ARM64 上の x64 ターゲットの場合、Sandboxie は内部の ARM64EC 固有のインジェクション データと ARM64EC SbieDll ビルドを使用します。これは Sandboxie の実装パスを説明するものであり、x64 エミュレーションと ARM64EC が互換性のあるアーキテクチャ用語であると言っていると読むべきではありません。ユーザーは Sandbox Options で別個の ARM64EC モードを選択しません。このパスは以下の x86 CHPE 回避策とも別個です。

## x86 CHPE が重要な理由

CHPE は、Windows on ARM64 上の一部の x86 プロセスにハイブリッド システム バイナリを使用します。Sandboxie の現在の x86 インジェクション パスは、`SyChpe32` からの CHPE 専用 `ntdll.dll` ではなく、`SysWOW64` からの通常の x86 `ntdll.dll` を想定しています。通常の x86 モジュールが存在しない場合、インジェクションは `SBIE2338` の CHPE 形式で失敗します。

このため、Sandboxie は通常、新しい x86 プロセスが非 CHPE システム バイナリを使用するように手配します。これは特に[強制プログラム](ForceProcess.md)と[強制フォルダー](ForceFolder.md)にとって重要です。強制のために選択されたホスト プロセスは、Sandboxie がインジェクションを試みる前にすでに CHPE バイナリで開始している可能性があります。

## DisableCHPE とそのグローバル スコープ {#disablechpe-and-its-global-scope}

ARM64 ビルドでは、SbieSvc は起動中にグローバル構成から Boolean `DisableCHPE` を読み取ります。その既定は `y` です。有効で、サービスのドライバー支援起動が成功した場合、SbieSvc はこの**ホスト**レジストリ キーの下に `LoadCHPEBinaries=0` を設定します。

```text
HKLM\SOFTWARE\Microsoft\Wow64\x86\xtajit
```

そのキーはホスト上の x86 プロセス作成に対してグローバルです。したがって、既定の回避策は SbieSvc が実行されている間、サンドボックスの**外**の新しい x86 プロセスに影響を与える可能性があります。ボックスごとの設定でも、1 つのアプリケーションのイメージ オプションの変更でもありません。すでに実行中のプロセスを遡って変更しません。

サービスのホスト全体のレジストリ変更をオプトアウトするには、次を使用します。

```ini
[GlobalSettings]
DisableCHPE=n
```

これは高度な互換性のトレードオフであり、推奨される一般的な構成ではありません。個々のサンドボックス セクション内の値は、サービスのグローバル ルックアップを制御しません。この設定は独立した ARM64EC トグルではありません。

### バックアップ、復元、および失敗

回避策を有効にするとき、SbieSvc はホスト キーを開くか作成します。`LoadCHPEBinaries_old` が存在せず、既存の `LoadCHPEBinaries` 値を読み取ることができる場合、その値を `LoadCHPEBinaries_old` として保存します。既存のバックアップは上書きしません。次に `LoadCHPEBinaries=0` を書き込もうとします。元の値が存在しなかった場合、保存する古い値はありません。

回避策が有効な状態での通常のサービス停止またはシャットダウン時に、SbieSvc は保存された値を復元し、バックアップを削除しようとします。バックアップが存在しない場合、代わりに `LoadCHPEBinaries` を削除します。これらの操作は試行されるものであり、保証されるものではありません。キーを開くことに失敗すると変更または復元が妨げられ、コードはすべての読み取り、書き込み、または削除の結果をチェックしません。部分的なレジストリの失敗または異常なシャットダウンにより、ホスト CHPE 構成が元の状態と異なるままになる可能性があり、`LoadCHPEBinaries=0` が残ることもあります。回避策が有効なままの後の起動は既存のバックアップを保持し、後の通常の停止でそれを復元できます。`DisableCHPE=n` で起動すると、その復元パスは実行されません。クラッシュ後の自動回復を前提としないでください。

## `DisableCHPE=n` の場合の動作

`DisableCHPE=n` は、SbieSvc が起動時の `xtajit` 書き込みを適用するのを停止します。通常の新しい x86 ホスト プロセスは、Windows とその他の構成が許す場合に CHPE を使用できます。そのようなプロセスが `ForceProcess` または `ForceFolder` に一致し、CHPE バイナリで開始した場合、Sandboxie のインジェクションは期待される通常の x86 `ntdll.dll` を見つけることができません。`SBIE2338 (CHPE)` を報告し、ドライバーはプロセスをボックスに正常に強制するのではなく、終了対象としてマークします。CHPE `ntdll.dll` がすでに読み込まれた状態で Sandboxie のインジェクション ステップに到達する x86 ターゲットには、同じインジェクション失敗が発生する可能性があります。エラーは強制ルールに限ったものではありません。

このオプトアウトは、Sandboxie のプロセスごとの CHPE 処理を無効にし**ません**。ホスト全体のレジストリ書き込みとは別に、SbieSvc はサービス プロセスに SbieDll のイメージ オプション フックをインストールし、SbieDll はプロセスの初期化中に対応するフックをインストールし、ARM64 低レベル x86 パスは独自の同等の処理をインストールします。これらのパスは関連するプロセス作成クエリに対して `LoadCHPEBinaries=0` を報告し、`DisableCHPE` 構成値によってゲートされません。したがって、サンドボックス化されたプロセスまたは子は CHPE なしで作成される場合があります。`DisableCHPE=n` は、すべての x86 プロセスがそれを使用することを約束しません。

## アーキテクチャの失敗と `SBIE2338`

現在の ARM64 インジェクション パスは、2 つの異なる条件に対して `SBIE2338` を発行します。サポートされていない ARM32 ターゲット (`ARM32`) と、通常の `SysWOW64` `ntdll.dll` が見つからない x86 ターゲット (`CHPE`) です。いずれの場合も、失敗したインジェクションがドライバーに報告され、ドライバーはプロセスを終了対象としてマークします。ARM64EC パスは別途実装されています。その他の初期化失敗はこれら 2 つの `SBIE2338` ケースではありません。

## 変更の適用

グローバル `DisableCHPE` 値は、SbieSvc のドライバー支援起動中に読み取られます。SbieSvc が実行されたまま Sandboxie.ini を再読み込みしても、ホスト レジストリ変更を再適用または元に戻しません。グローバル値を変更した後は SbieSvc を再起動し、新しい影響を受ける x86 プロセスを開始して、変更されたプロセス作成動作を観察してください。このコードは、この設定のためだけに Windows の再起動または別個のドライバーの再起動を必要としません。値を変更しても、すでに実行中のプロセスのアーキテクチャまたはインジェクトされたフックを再構築することはできません。

SandMan の現在のオプション インターフェイスには専用の `DisableCHPE` コントロールはありません。[Sandboxie Ini](SandboxieIni.md)のグローバル セクションで手動で構成してください。

## バージョン履歴

Sandboxie Plus 1.5.0 / Classic 5.60.0 は Windows on ARM64 サポートを導入しました。これには ARM64/ARM64EC インジェクションとフック、CHPE 回避策、および ARM32 の制限が含まれます。以降のリリースでは、ARM64 FFS フックの問題や ARM64 での x64 プロセス起動など、特定の ARM64 互換性の問題が修正されました。1.18.5 のソース変更は、Chromium/Firefox スタイルのインターセプターのために ARM64 フック ターゲット スキャンを強化します。ここで説明する `DisableCHPE` 構成または CHPE ライフサイクルを変更するものではありません。
