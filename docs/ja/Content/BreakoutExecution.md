# ブレイクアウト実行

ブレイクアウトは、選択された将来の操作に対するサンドボックス封じ込めの意図的な例外です。[Breakout Process](BreakoutProcess.md)と[Breakout Folder](BreakoutFolder.md)は、サンドボックス内からの新しいプロセス作成の試行に影響を与えることができます。[Breakout Document](BreakoutDocument.md)は代わりに、一致するパスを開くためのサポートされている Shell 要求に適用されます。これらの設定は、すでに実行中のプロセスをボックスの外に移動したり、昇格を付与したり、任意のファイル アクセスをサンドボックス化されていないものにしたりしません。

## プロセス ブレイクアウト

サンドボックス化されたプログラムが新しいプロセスを起動しようとすると、Sandboxie は最初にターゲットがブレイクアウト候補であるかどうかをチェックします。次に、サンドボックス化されたプロセスは、Sandboxie サービスにソース ボックスの外でそれを作成するよう要求します。サービスは、プロセスを作成する前に独立してブレイクアウト ルールをチェックします。最初の候補チェックだけでは脱出を許可しません。

サービスが `ERROR_NOT_SUPPORTED` でブレイクアウト要求を拒否した場合、Sandboxie は通常のサンドボックス化されたプロセス作成パスを続行します。他の作成エラーには必ずしもそのフォールバックがあるわけではありません。`BreakoutProcess` の場合、サービスはさらに、ターゲット実行可能ファイルがソース サンドボックスのファイル ルートの外側のホスト ファイルに解決されることを要求します。その特定のホスト ファイル チェックは `BreakoutFolder` には適用されません。

ブレイクアウトが成功しても、必ずしもプロセスがサンドボックス化されていない状態になるわけではありません。サービスは、一致する [Force Process](ForceProcess.md) または [Force Folder](ForceFolder.md) ルールについて有効なボックスをチェックするため、別のボックスが起動を捕捉する場合があります。たとえば、Email ボックスから PDF を表示すると `browser.exe` が起動する場合、Email の `BreakoutProcess=browser.exe` と Browser ボックスの `ForceProcess=browser.exe` がそのブラウザー起動を Browser にルーティングできます。これはボックス間の構成可能な優先順位ではありません。複数のボックスが一致する場合、特定の宛先が選択されることに依存しないでください。`ForceChildren` はこの明示的な宛先チェックに関与しません。

その強制チェックがソース ボックスに解決し直された場合、サービスは `ERROR_NOT_SUPPORTED` でブレイクアウト要求を拒否し、通常のサンドボックス化された作成が再開されます。ホスト ブレイクアウトの場合、サービスは要求に適したトークンを使用してプロセスを作成し、完全制御ハンドルではなく、制限付きアクセスのプロセス ハンドルとスレッド ハンドルをサンドボックス化された呼び出し元に返します。ブレイクアウトは昇格メカニズムではありません。

## ドキュメント ブレイクアウト

`BreakoutDocument` は、フォルダー ベースのプロセス ルールではなく、別個の Shell オープン メカニズムです。傍受された `ShellExecuteExW` パスで、Sandboxie は供給されたファイル/パス テキストを構成されたパターンと比較します。一致はユーザー セッション プロキシを通じて送信され、プロキシはサンドボックス化された呼び出し元とセッションを検証し、ルールを再度チェックします。次に、ホスト Shell に `open` 動詞で一致したパスを開くよう要求します。

ホスト要求にはパスが含まれ、元の Shell 要求の未変更のコピーではありません。元の動詞、パラメーター、および作業ディレクトリは転送されません。これは、アプリケーションがドキュメントを開く可能性のあるすべての方法をカバーするわけではありません。ホスト側のオープンは、元のボックスのファイルおよびレジストリ仮想化の外でアプリケーションを起動したり、コンテンツを実行したりできます。

> **セキュリティ警告:** 狭いパスと意図されたドキュメント タイプを使用してください。`BreakoutDocument=C:\path\*` のような広範なルールは、実行可能ファイルまたはスクリプト コンテンツをソース サンドボックスの外で実行させることができます。SandMan は広範または危険なドキュメント パターンについて警告しますが、その拡張子チェックは UI の安全対策であり、ランタイム許可リストではありません。手動で編集された構成には、より広範なパターンが含まれる場合があります。

## Explorer 互換ブリッジ {#explorer-compatibility-bridge}

`BreakoutDocumentProcess` は、イメージ対応の Boolean 互換性設定で、既定で無効です。Windows Explorer テンプレートは `BreakoutDocumentProcess=explorer.exe,y` を設定します。これは、Explorer が通常傍受される `ShellExecuteExW` ルートではなく、プロセス作成を通じて関連するドキュメント起動を開始できるためです。そのイメージについて、Sandboxie は将来のプロセス作成の試行中にコマンド ラインの残りを `BreakoutDocument` ルールと比較します。これは Explorer 互換ブリッジであり、別の汎用ブレイクアウト リストではありません。通常、手動構成は必要ありません。これは Sandboxie Plus 1.15.1 / Classic 5.70.1 で追加されました。

## 構成と変更の適用

アクティブなブレイクアウト エントリは、ボックス構成または該当するテンプレートから取得できます。SandMan で **Sandbox Options > Program Control > Breakout Programs** を開き、**Breakout Program**、**Breakout Folder**、**Breakout Document**、**Show Templates**、および **Remove** を使用します。チェックされていないエントリは、対応する `BreakoutProcessDisabled`、`BreakoutFolderDisabled`、または `BreakoutDocumentDisabled` 設定の下でインターフェイスに残ります。これらの保存されたエントリはアクティブなブレイクアウト ルールではありません。このインターフェイスには単一のグローバル ブレイクアウト スイッチはありません。

プロセス ルールは将来の関連するプロセス作成の試行のために評価され、ドキュメント ルールは将来のサポートされている Shell オープン要求のために評価されます。変更は既存のプロセスを再配置したり、完了したドキュメント オープンを変更したりしません。有効な構成が更新された後、後続で評価される操作は、ブレイクアウトのためだけに Windows、サービス、または既に実行中のサンドボックス化されたアプリケーションを再起動することなく、新しいルールを使用できます。

## バージョン履歴

`BreakoutProcess` と `BreakoutFolder` は Sandboxie Plus 1.0.8 / Classic 5.55.8 に登場しました。1.0.9 / 5.55.9 で、プロセス ブレイクアウトはサービスによって作成されるプロセスを中心に作り直されました。`BreakoutDocument` は 1.15.0 / 5.70.0 で導入され、続いて 1.15.1 / 5.70.1 で Explorer 関連の `BreakoutDocumentProcess` ブリッジが導入されました。
