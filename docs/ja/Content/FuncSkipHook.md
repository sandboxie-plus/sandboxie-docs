# Function Skip Hook

`FuncSkipHook` は [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定で、特定のエクスポートされた API 関数をフックしようとしないよう Sandboxie に指示します。

この設定は、特定の関数に対するフック試行が不安定さ、他のセキュリティ製品との非互換性、または望ましくない動作を引き起こす場合に役立ちます。

## 構文

```ini
[DefaultBox]

FuncSkipHook=FunctionNameA
FuncSkipHook=FunctionNameB
```

注:

- 各 `FuncSkipHook` エントリは、フック対象として検討されている関数名の先頭と比較され、一致するとフックがスキップされます。

## 使用法

通常、特定のアプリケーションまたはフック識別子に対するフックを避けるためにテンプレートで使用されます。

例:

```ini
[DefaultBox]

FuncSkipHook=SomeVendor_BrokenCall
FuncSkipHook=PStoreCreateInstance
```

## 動作

- ヘルパー `SbieDll_FuncSkipHook` は `FuncSkipHook` エントリを構成に対して照会します。構成された各エントリについて、構成されたワイド文字列とフック対象の ASCII 関数名の間でプレフィックス比較を実行します。関数名の先頭文字と一致している間に構成文字列が尽きた場合、その関数は一致したと見なされ、フックがスキップされます。[^1]
- 効率のため、最初の照会で `FuncSkipHook` エントリが見つからなかった場合、以降の呼び出しではこのチェックを完全にスキップします。

## 技術的な注意

- コードは `SbieApi_QueryConfAsIs` を使用して、照会が失敗する (または異なるエラーを返す) までインデックスをループしてエントリを読み取ります。返された各 `WCHAR` バッファは、両方のポインターを並行して進めながら関数名と比較されます。比較は、構成されたワイド文字列が終了したが ASCII 関数名にはまだ文字が残っているときに停止し、一致を報告します。
- この比較は事実上大文字と小文字を区別するプレフィックス マッチです (生の文字を並行して比較します)。大文字と小文字を区別しないマッチングに依存する場合、`FuncSkipHook` は `SkipHook` とは異なる動作をすることに注意してください。

## GUI

`FuncSkipHook` は高度な設定であり、通常は INI で手動編集します。Sandboxie に同梱されるテンプレート ファイルには、`FuncSkipHook` エントリの例が含まれていることがあります。

## 関連設定

- [SkipHook](SkipHook.md) — モジュールまたは識別子でフックをスキップするためのモジュール/フック名レベルの設定。

## 脚注

[^1]: 実装は `SbieDll_FuncSkipHook` (`dllhook.c` を参照) にあります。この関数は `SbieApi_QueryConfAsIs` で `FuncSkipHook` エントリを照会し、構成されたワイド文字列を関数名と 1 文字ずつ比較します。構成文字列が尽きると一致を示し、フックのスキップをトリガーします。エントリが見つからない場合、この関数は効率のため以降のチェックを無効にする内部フラグを設定します。
