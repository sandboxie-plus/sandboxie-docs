# RunCommand

`RunCommand` は SandMan のサンドボックスの **Run** メニューにカスタム エントリを追加します。エントリを選択すると、その構成されたコマンドがそのサンドボックス内で開始されます。エントリを定義しても、プログラムが自動的に、サンドボックス起動時に、または他のサンドボックス イベントで開始されることはありません。

これは SandMan のメニュー機能であり、ドライバーによって強制される実行ルールではありません。現在の Sandboxie Control Classic コードは、対応するカスタム Run メニュー コンシューマーを提供しません。

## 構成形式

各 `RunCommand` 行は 1 つのメニュー エントリを定義します。単純な形式は、表示名とコマンド ラインを最初の `|` で分離します:

```ini
[DefaultBox]
RunCommand=Notepad|"C:\Windows\notepad.exe"
RunCommand=Config\Open win.ini|"C:\Windows\notepad.exe" "C:\Windows\win.ini"
```

コマンドには引数を含めることができます。スペースを含む実行可能パスを引用符で囲み、起動するプログラムが必要とする引数を引用符で囲みます。SandMan はコマンド ラインを通常のサンドボックス ランチャーに渡します。`RunCommand` は別個のシェル コマンド パーサーを提供しません。

名前にバックスラッシュがあるとメニュー階層が作成されます。たとえば、`Config\Open win.ini` は **Run > Config** の下に表示されます。複数のレベルは `Tools\Editors\Notepad` として記述できます。

レガシ形式は、名前部分の最初のコンマの後にオプションのアイコンも受け入れます: `Name,icon|command`。最初のコンマと最初の `|` が区切り文字であるため、これらの文字を必要とするメニュー名には JSON を使用してください。

アイコンまたは作業ディレクトリには、`Command`、`Name`、オプションの `Icon`、およびオプションの `WorkingDir` フィールドを持つ JSON 値を使用します:

```ini
RunCommand={"Command":"\"C:\\Windows\\notepad.exe\" \"C:\\Windows\\win.ini\"","Name":"Config\\Open win.ini","Icon":"C:\\Windows\\System32\\notepad.exe,0","WorkingDir":"C:\\Windows"}
```

JSON では、示されているようにバックスラッシュと埋め込まれた引用符をエスケープする必要があります。SandMan のエディターは、アイコンも作業ディレクトリも設定されていない場合はコンパクトなレガシ形式を書き込み、それ以外の場合は JSON を書き込みます。エントリをシリアル化するときに `WorkingDir` から二重引用符を削除します。

`Icon` は、アイコン ファイルとインデックスを `path,index` として、またはコマンドの実行可能ファイルとともに使用するインデックスのみを指定できます。明示的なアイコンがない場合、SandMan はコマンドの実行可能ファイルのアイコンを試みます。指定されたアイコンを読み込めない場合、フォールバック アイコンを使用します。特殊なインデックス `-1` は SandMan のインターネット アイコンを選択します。

## 作業ディレクトリとサンドボックス パス

`WorkingDir` はオプションです。存在する場合、SandMan はそれを `Start.exe` ランチャーの作業ディレクトリとして渡します。空の場合、SandMan はその起動に作業ディレクトリを設定しません。開始するプログラムに適したパスを使用してください。

SandMan はコマンドおよび作業ディレクトリ文字列内の `%BoxRoot%` を認識し、起動前にそのサンドボックスのファイル ルート パスに置き換えます。プログラムをピン留めすると、そのようなパスが作成されることがあります。この置換を一般的な環境変数展開として扱わないでください。

## グローバル、サンドボックス、およびテンプレートのエントリ

エントリは、すべてのサンドボックス用の `[GlobalSettings]` に、または個々のサンドボックス セクションに配置できます。適用可能なテンプレートもエントリを提供できます。SandMan がサンドボックスの Run メニューを構築するとき、ローカル、テンプレート、およびグローバルの値を一緒に要求します。これらのエントリは単一の上書き値として扱われるのではなく結合されます。ボックス固有のエントリを追加しても、同じ名前のグローバル エントリは置き換えられず、重複したメニュー アクションが発生する可能性があります。

サンドボックスの **Run Menu** エディターは、グローバル設定およびテンプレートからの完全な有効なリストではなく、それ自体のエントリを表示します。グローバル エディターはグローバル エントリを別途管理します。有効なリストはサンドボックス、適用可能なテンプレート、およびグローバル設定からのエントリを結合できるため、異なる構成ソースからのエントリの相対順序を安定したメニュー順序として依存しないでください。

## SandMan インターフェイス

1 つのサンドボックスに対して、**Sandbox Options > General Options > Run Menu** を開きます。エディターは **Name** と **Command Line** をリストし、プログラムまたはコマンドを追加し、エントリを削除し、上または下に移動するコントロールを備えています。**Add program** は **Browse for Program** も提供します。

すべてのサンドボックスで利用可能なエントリには、**Options > Global Settings > General Config > Run Menu** を開きます。これは `[GlobalSettings]` エントリ用の別個のエディターです。

実行中のサンドボックス化されたプロセスの **Preset > Pin to Run Menu** アクションも使用できます。SandMan はその実行可能ファイルと作業ディレクトリをボックス ローカルのエントリに記録します。サンドボックスの **Run from Start Menu** サブメニューの下に表示されるショートカットも同様にピン留めでき、利用可能な場合はそのコマンド、引数、アイコン、および作業ディレクトリを保持します。そのサブメニューはサンドボックスのスタート メニュー項目を表し、ホストの Windows スタート メニューではありません。

Run メニュー項目はデスクトップ ショートカットの作成にも使用できます。`RunCommand` 値自体は Windows の `.lnk` ファイルではありません。

## 実行と変更

カスタム エントリが選択されると、SandMan はそのコマンドと作業ディレクトリ内の `%BoxRoot%` を展開し、選択されたボックスと既定の開始フラグを指定して通常の `RunStart` パスを呼び出します。そのパスはボックスの `Start.exe` を呼び出します。`RunCommand` は昇格を要求したり、ボックスの通常の制限をバイパスしたりしません。

SandMan は、選択されたサンドボックスのメニューを更新するときに構成から Run メニューを再構築します。変更を保存した後、必要に応じてメニューを再度開いてください。既存のサンドボックス化されたプロセスを再起動する必要はありません。SandMan の外で `Sandboxie.ini` を編集する場合は、まず構成を再読み込みしてください。

`RunCommand` は、`StartCommand` や `StartSystemBox` などの自動起動設定、および `OnBoxDelete` や `OnBoxTerminate` などのホスト側の [SandMan トリガー](SandManTriggers.md)とは別個です。別個の `CSbieUtils::RunCommand()` ヘルパーは他の SandMan コマンドを実行し、`RunCommand=` メニュー エントリのコンシューマーではありません。

## バージョン履歴

変更履歴は、Sandboxie Plus 0.5.0 / Classic 5.45.0 リリース ペアでカスタムのサンドボックスごとの Run メニュー コマンドとプロセスのピン留めを記録しています。これは SandMan UI のマイルストーンを確立するもので、現在のメタデータに `AddedVersion` がない `RunCommand` 設定の元の導入日ではありません。

以降のマイルストーンには、1.6.1 / 5.61.1 のグローバル Run メニュー エントリ、1.8.0 / 5.63.0 のメニュー フォルダー、および 1.9.0 / 5.64.0 のカスタム アイコンが含まれます。その後のリリースでは Run メニュー エントリの作業ディレクトリ処理が修正されました。
