# BlockLocalLoop

**BlockLocalLoop** は Sandboxie Plus 1.17.4 以降で使用可能な [Sandboxie Ini](SandboxieIni.md) のサンドボックス設定です。Sandboxie の対象となるネットワーク パスを通じた一致する IP ループバック トラフィックを制限し、既定では無効です。

```ini
[DefaultBox]
BlockLocalLoop=y
```

これは限定的なループバック制限であり、完全なローカル ネットワークまたはホストの分離ではありません。サンドボックス化されたプロセスが同じコンピューターで実行されているサービスと通信するすべての方法をブロックするわけではありません。

## アドレス スコープ

ユーザー モード Winsock 強制は次を認識します:

- 完全な IPv4 `127.0.0.0/8` ループバック範囲。
- IPv6 ループバック アドレス `::1`。
- `127.0.0.0/8` のアドレスを含む IPv4 マップ IPv6 ループバック アドレス。

`BlockLocalLoop` は、非ループバック アドレスが同じコンピューターに属するかどうかを判断しません。ホストの LAN または Wi-Fi アドレス、`10.x.x.x` や `192.168.x.x` などのプライベート アドレス、リンクローカル アドレス、割り当てられた非ループバック IPv6 アドレス、および仮想アダプター アドレスは、その通常のアドレス スコープ外です。より広範なアクセスは通常の `NetworkAccess` ルールで制御すべきです。

この設定は DNS 名ではなく解決された IP アドレスに作用します。たとえば、`localhost` または `127.0.0.0/8` や `::1` に解決されるカスタム ホスト名は制限の対象です。非ループバック アドレスに解決される名前は、それがローカル コンピューターを識別するという理由だけでブロックされることはなく、DNS 解決自体も妨げられません。

制限はポート固有ではなくアドレス ベースです。文書化されたポートごとの例外や、特定のブラウザー、RPC エンドポイント、またはシステム サービスに対する組み込みの除外はありません。

## 通信動作

有効な場合、Sandboxie のユーザー モード Winsock パスは、一致するループバック アドレスへの標準的な送信通信を拒否します。対象となるパスには、通常の TCP 接続試行、接続済み UDP、UDP 送信、および選択された UDP 受信パスが含まれます。たとえば、`connect`、`WSAConnect`、`sendto`、または `WSASendTo` を通じた呼び出しは制限の対象です。

ユーザー モード パスによってブロックされた標準的な Winsock 操作は、通常、接続拒否エラーで直ちに失敗します。Windows Filtering Platform (WFP) によってブロックされた操作を含む他のネットワーク パスが、同じ正確なエラーを返すと仮定すべきではありません。

`BlockLocalLoop` 自体は、サンドボックス化されたアプリケーションがローカル ソケットをバインドしたり、ループバック アドレスでリッスンしたりすることを妨げません。ローカル リスナーの作成を防ぐのではなく、対象となるループバック パスを通じた通信を制限します。

同一サンドボックスの除外はありません。この設定が有効なサンドボックス化されたプロセスによって開始される送信ループバック トラフィックについて、この制限はピアが次のいずれであるかを区別しません:

- サンドボックス化されていないホスト プロセス。
- 同じサンドボックス内の別のプロセス。
- 別のサンドボックス内のプロセス。

その結果、同じサンドボックス内のクライアント/サーバーのペアも影響を受けることがあります。

文書化されたスコープは、対象となる Winsock パスを通じた TCP および UDP を含む IPv4 および IPv6 上の IP ネットワーキングです。AF_UNIX ソケット、名前付きパイプ、またはその他の非 IP IPC メカニズムには適用されません。ユーザー モード パスだけから包括的な Raw Socket または ICMP フィルタリングを仮定すべきではありません。

## ネットワーク ルールと WFP サポート

`BlockLocalLoop` は通常の `NetworkAccess` ルールとは独立して評価されます。許可ルールは成功した `BlockLocalLoop` の一致を上書きしません。より広範な拒否ルールは、既にブロックしているトラフィックに対してこの設定を冗長にする可能性があります。

既定の強制レイヤーは、サンドボックス化されたプロセス内のユーザー モード Winsock パスです。WFP サポートがグローバルに有効な場合:

```ini
[GlobalSettings]
NetworkEnableWFP=y
```

Sandboxie のドライバーも Windows Filtering Platform を通じて関与します。WFP は傍受された Winsock エクスポートを超えて強制を拡張し、追加の IP トラフィック クラスにカーネル承認を適用できます。ユーザー モード フォールバックは主にサンドボックス化されたプロセスによって開始されるトラフィックを制限します。WFP が有効な場合、承認は受信接続および受信パスにも適用できます。

### 実装上の注意と制限事項

信頼できる文書化された動作は、主に標準的な Winsock 強制パスに基づいています。カーネル WFP サポートは有効な場合に追加のカバレッジを提供しますが、現在の実装の詳細はアドレス ファミリとネットワーク パスによって異なります。通常の Winsock パスをバイパスするアプリケーションが同一の動作を受け取ると仮定すべきではなく、WFP を通じた完全な双方向 IPv4 ループバック ブロックは保証されません。

バインドまたはリッスン自体は妨げられません。グローバルな `NetworkEnableWFP` オプションの変更は `BlockLocalLoop` の変更とは別個です。その有効化要件については [WFP Support](../PlusContent/WFPSupport.md) を参照してください。

## 互換性と目的

この設定は、サンドボックス化されたコードによる、ループバックのみでリッスンするホスト ローカル サービス (認証されていない localhost サービス、開発または管理エンドポイント、ローカルのヘルパーまたは制御サービスなど) へのアクセスを低減できます。

実際にループバック通信を使用する場合、ソフトウェアが影響を受けることがあります。例:

- ローカル開発サーバーに接続するブラウザー。
- ローカル ヘルパーを使用する Electron または WebView アプリケーション。
- `127.0.0.1` または `::1` を使用する OAuth またはログイン コールバック。
- IDE、テスト ツール、および開発サーバー。
- ローカル データベース、HTTP または SOCKS プロキシ、および DNS リゾルバー。
- TCP または UDP ループバック経由で通信するゲーム ランチャーまたはヘルパー プロセス。

これらのカテゴリのすべてのアプリケーションがループバックを使用するわけではありません。ホストに割り当てられた非ループバック アドレスはこの設定のスコープ外のままであり、名前付きパイプまたはその他のローカル IPC メカニズムは無関係です。より広範な制限が必要な場合はネットワーク アクセス ルールを使用してください。

## スコープと変更の適用

`BlockLocalLoop` は通常のボックス設定であり、通常のテンプレートまたはグローバル構成の解決を通じて継承できます。文書化されたプログラムごとの構文はありません。

ユーザー モード値はサンドボックス化されたプロセスでネットワークが初期化されるときに読み取られます。オプションを変更しても既に実行中のすべてのプロセスが確実に更新されるわけではないため、影響を受けるサンドボックス化されたアプリケーションを再起動することが変更を適用する確実な方法です。新しく開始されたプロセスのためだけにサービスまたはドライバーの再起動は必要ありません。

## ユーザー インターフェイスと通知

現在、通常の Sandbox Options に専用の **BlockLocalLoop** チェックボックスはありません。次の方法で構成します:

**Sandbox Options** > **Edit ini Section** > **Edit ini**

また、ブロックされた接続ごとに専用の `BlockLocalLoop` 通知やユーザー向け SBIE メッセージはありません。アプリケーションは通常、自身のネットワーク障害を報告します。

## バージョン履歴

*BlockLocalLoop* は Sandboxie Plus 1.17.4 で導入されました。既定では無効のままで、現在の Sandbox Options インターフェイスは専用のチェックボックスを提供していません。
