# 暗号化サンドボックス

Sandboxie Plus は、レジストリ ハイブを含むサンドボックス ルートを暗号化されたディスク イメージに保存できます。通常のサービス ワークフローは ImBox と、AES-XTS を使用する DiskCryptor 由来の暗号化実装を使用します。これは、Sandboxie の論理的なファイル仮想化ではなく、ファイル ルートの下の物理的なバッキングを変更します。

暗号化ストレージは保護の 1 つのレイヤーです。Sandboxie の実行時分離、およびサンドボックス化されたプロセスへのホスト アクセスを制限する設定とは別のものです。

## 保存時の暗号化ストレージ

イメージがマウントされていないとき、その内部に保存された内容は暗号化された `.box` バッキング ファイル内に残ります。SandMan は、プログラムを起動する前にプロンプトを表示して事前にマウントできます。他のスタートアップ パスは、対話型パスワード プロンプトなしでサービス側の取得を試みることができ、イメージのロックを解除できない場合は失敗する可能性があります。自動アンマウントは、現在のマウント オプションと、レジストリ/ルートの解放およびデバイス クリーンアップの成功に依存します。

この保存時の境界は、`Sandboxie.ini`、外部ヘッダー バックアップ、復元/エクスポートされたファイル、ホスト メタデータ、またはすべての外部アプリケーションの副作用を自動的にカバーするものではありません。

暗号化は、アンマウントされている間のバッキング ストレージを保護します。イメージがマウントされている間、サンドボックス内のプログラムとそれを操作するために必要な Sandboxie コンポーネントは、アクティブなサンドボックス ポリシーに従ってマウントされたファイルシステムにアクセスできます。暗号化は、ファイル、レジストリ、IPC、ネットワーク、クリップボード、GUI、またはその他のリソース制御を置き換えるものではありません。

暗号化されたイメージには、利用可能な ImDisk デバイス/ドライバーと、暗号化機能を備えた現在適用可能な有効なサポート証明書が必要です。ImDisk は仮想ディスクを提供し、ImBox は暗号化バッキングを提供します。イメージまたはその暗号化ヘッダーが損傷するとアクセスできなくなる可能性があるため、暗号化サンドボックスには依然としてバックアップが必要です。

## パスワードとヘッダーのモデル

標準のサンドボックス オプション作成ワークフローではパスワードが期待されます。ただし、低レベルのサービスは空のパスワード入力で暗号化バッキングを選択できます。暗号化だけでは、意味のあるパスワードが選択されたことを確立しません。通常のワークフローは、再利用可能なパスワード ボールトを提供したり、マウント パスワードを `Sandboxie.ini` に保存したりしません。

パスワードを変更すると、ペイロード全体を再暗号化するのではなく、ヘッダー/キー保護メタデータが更新されます。ヘッダー バックアップには機密の暗号化マテリアルが含まれ、内容のバックアップではありません。一致する古いヘッダーを復元すると、現在のヘッダーが上書きされ、古いパスワード/キー メタデータが復元される可能性があります。パスワードを変更しても、以前の一致するすべてのヘッダー バックアップが自動的に無効になるわけではありません。復元もトランザクション ロールバックも保証されません。パスワードとヘッダーの手順については、[ファイル イメージの使用](../Content/UseFileImage.md)を参照してください。

## マウント中のルート保護

マウント ダイアログは **Protect Box Root from access by unsandboxed processes** を提供します。これは、無関係なホスト プロセスからのマウントされたディスク ルートの下での関連する新しいファイルシステム オープンに対して、別個の SbieDrv 制限を要求します。例外には、所有サンドボックス、SbieSvc、`csrss.exe`、および許可されたセッション リーダーが含まれます。以前に取得したハンドルは普遍的に取り消されるわけではありません。このチェックによってスキップされるカーネル モードおよびその他のパスは、その範囲外です。Windows のファイルシステム権限は別個のままです。

[ProtectAdminOnly](../Content/ProtectAdminOnly.md) は、セッション リーダー例外にも管理アクセスが必要かどうかを制御します。これはすべての管理者または SYSTEM プロセスの一般的な例外ではありません。[マウント時の保護の強制](../Content/ForceProtectionOnMount.md)は、SandMan のレビュー済みマウント ワークフローを保護を要求するように制約し、すべてのサービス呼び出し元ではありません。保護要求は、イメージのマウントを失敗させることなく失敗する可能性があるため、保護されたマウントはフェイルクローズのホスト アクセス保証ではありません。通常のマウント クエリは、保護の登録の成功を確立しません。

ルート保護は、マウントされたルート パスに適用されます。これは普遍的なデータ フロー制御ではなく、サンドボックス化されたアプリケーションがそのサンドボックス ポリシーで許可されている他のチャネルを使用するのを防ぎません。

## 機密ボックス保護

[ConfidentialBox](../Content/ConfidentialBox.md) は独立した実行時設定です。文書化された運用上の例外を条件として、サンドボックス外のホスト プロセスがサンドボックス化されたプロセスとスレッドへのハンドルを取得するのを制限します。`DenyHostAccess` は、同じ保護パスのプログラムごとの許可または拒否ルールを提供します。

新しいボックス ウィザードの **Black Box** オプションは、選択した基本ボックス タイプを保持しながら、暗号化バッキング ストレージと `ConfidentialBox=y` を組み合わせます。既存のサンドボックスで **Encrypt sandbox content** を有効にしても、それ自体ですべての機密ボックスまたはイメージ保護設定が有効になるわけではありません。

[ProtectHostImages](../Content/ProtectHostImages.md) は別の独立した機能です。実行可能ファイルがホストから取得されたサンドボックス化されたプロセスが、サンドボックスから実行可能イメージを読み込むのを制限します。ストレージを暗号化したり、ホスト プロセスのハンドルを制御したりするものではありません。

## SandMan の構成

暗号化ストレージは次の場所で構成します。

**Sandbox Options > File Options > File Options**

関連するコントロールは次のとおりです。

- **Encrypt sandbox content** — ボックス ルートを暗号化されたディスク イメージに保存します。
- **Set Password** または **Change Password** — イメージ パスワードを作成または更新します。
- **Force protection on mount** — SandMan のマウント ダイアログをルート保護を要求するように制約します。すべてのマウントに対して自動アンマウントを強制するために依存してはなりません。現在の手動パスは、無効になっている自動ロック オプションをオフのままにすることがあります。

イメージをマウントするとき、SandMan は次も提供します。

- **Protect Box Root from access by unsandboxed processes**。
- **Lock the box when all processes stop**。

サンドボックス内から選択したホスト ファイルにアクセスするには、必要に応じて [OpenFilePath](../Content/OpenFilePath.md) などの通常のリソース アクセス ルールを構成します。これらのルールは意図的に指定されたアクセスを許可するものであり、ボックスのデータ フロー ポリシーの一部として確認する必要があります。

## セキュリティ境界

暗号化ストレージ、ルート保護、および機密プロセス保護は、異なるパスに対処します。これらを組み合わせることで、いくつかの形式のオフラインおよび実行時のホスト アクセスが減少しますが、実行中のサンドボックスからデータが出られないことを確立するものではありません。サンドボックス化されたアプリケーションがネットワーク接続、開かれたホスト パス、IPC、クリップボード、または別の許可されたチャネルを使用することが許可されている場合、ボックスが暗号化または機密であるという理由だけでこれらの設定がそのチャネルをブロックすることはありません。

## バージョン履歴

暗号化サンドボックス サポートと `UseFileImage` は Sandboxie Plus 1.11.0 / Classic 5.66.0 で導入されました。機密プロセス保護は暗号化イメージより前から存在します。`ConfidentialBox` と `DenyHostAccess` は Sandboxie Plus 1.3.3 / Classic 5.58.3 で導入されました。
