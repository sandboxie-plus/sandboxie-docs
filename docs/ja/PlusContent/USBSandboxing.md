# USB ドライブのサンドボックス化

USB ドライブのサンドボックス化は、Sandboxie の[強制フォルダー メカニズム](../Content/ForceFolder.md)に基づいて構築された SandMan 自動化です。SandMan は、適格な USB バッキング ボリュームのマウント ポイントに対して `ForceFolder` エントリを維持します。それらの強制された場所から起動されたプログラムは、指定されたサンドボックスによって処理されます。

この機能は、USB デバイス自体をサンドボックス内に配置したり、USB デバイス I/O を仮想化したり、ボリューム上のファイルにアクセスするすべてのプログラムをサンドボックス化したりするものではありません。そのセキュリティ効果は、どのプログラムが強制されるか、および指定されたサンドボックスの構成に依存します。

## 適格なストレージ

SandMan は Windows ボリュームとそのバッキング ディスクを列挙します。ボリュームは、少なくとも 1 つのバッキング ディスクが `USBSTOR` 列挙子を通じて報告された場合に適格となります。これには、USB フラッシュ ドライブ、USB ハード ドライブ、および USB SSD が含まれます。

適格性は、ドライブ文字、リムーバブル メディア属性、ファイルシステム、またはボリューム ラベルだけに基づくものではありません。したがって、通常のネットワーク ドライブまたは `SUBST`/再マップされたパスは、単にドライブとして表示されるという理由だけでは適格となりません。複数のディスク エクステントにまたがるボリュームの場合、現在の実装では、少なくとも 1 つのバッキング ディスクが `USBSTOR` として識別されれば、そのボリュームを USB バッキングとして扱います。

## 構成 {#configuration}

USB ドライブのサンドボックス化はグローバル構成であり、既定で無効になっています。自動メンテナンスには、有効な適用可能な[サポート証明書](supporter-certificate.md)が必要です。

```ini
[GlobalSettings]
ForceUsbDrives=y
UsbSandbox=USB_Box
```

`ForceUsbDrives=y` は、SandMan による USB 強制フォルダー ルールの自動メンテナンスを有効にします。設定が false または存在しない場合、SandMan は USB 強制フォルダー リストを再構築しません。これは低レベルの USB ブロッキング ポリシーではありません。`UsbSandbox` は、生成されたルールを受け取るサンドボックスの名前を指定します。存在しない場合、SandMan は `USB_Box` を使用します。

指定されたサンドボックスが存在しない場合、SandMan はそれを作成しようと試みます。この操作によって作成されたサンドボックスは通常のサンドボックスであり、特別な USB セキュリティ タイプではありません。SandMan は現在、正常に作成されたサンドボックスに次の設定を追加します。

```ini
UseFileDeleteV2=y
UseRegDeleteV2=y
UseVolumeSerialNumbers=y
```

作成が失敗した場合、SandMan は欠落しているサンドボックスの強制フォルダー ルールを更新できません。`UseVolumeSerialNumbers` はそのサンドボックスがパスを保存する方法を制御し、USB 除外に使用されるボリューム シリアル番号とは別個です。

## 生成される `ForceFolder` ルール

除外されていない適格な各ボリュームについて、SandMan はその現在のマウント ポイントを収集し、指定されたサンドボックスに直接 `ForceFolder` エントリとして書き込みます。

!!! warning
    USB の更新は、指定されたサンドボックスの直接 `ForceFolder` リストを、現在適格な USB マウント ポイントで置き換えます。無関係な永続的な手動ルールにその直接リストを使用しないでください。また、自動 USB 管理が有効な間は、そこに USB ドライブ文字を手動で維持しないでください。この置き換えはボックスの直接リストに関するものであり、継承された構成またはテンプレート構成が書き換えられることを意味するものではありません。

    `ForceUsbDrives` を無効にしたり、必要な有効な証明書を失ったりすると、自動メンテナンスは停止しますが、以前に生成された直接エントリは削除されません。`UsbSandbox` を変更すると、以降の更新で新しいボックスが維持されますが、以前のボックスで生成された直接エントリは自動的にクリーンアップされません。機能を無効にしたり、指定されたサンドボックスを変更したりするときは、古い直接 `ForceFolder` エントリを手動で確認して削除してください。

結果として得られるルールは、通常の `ForceFolder` 動作に従って、強制された場所から起動されたプログラムに影響します。それ以外はサンドボックス化されていないホスト プログラムによって実行されるすべての読み取りまたは書き込みをリダイレクトするものではありません。

## ボリュームの除外 {#excluding-volumes}

`DisabledForceVolume` は、特定のボリュームを自動 USB サンドボックス化から除外する繰り返し可能なグローバル設定です。

```ini
[GlobalSettings]
DisabledForceVolume=1234-ABCD
DisabledForceVolume=5678-EF90
```

各値は、SandMan によって大文字 16 進数の `XXXX-XXXX` としてフォーマットされた Windows ボリューム シリアル番号です。ドライブ文字、ボリューム GUID パス、USB ハードウェア ID、または物理ドライブ ファームウェア シリアル番号ではありません。

除外は Windows ボリューム シリアルに従うため、ドライブ文字を変更しても通常は無効になりません。ファイルシステムを再フォーマットまたは再作成するとそのシリアルが変更される可能性があるため、保存された除外が一致しなくなる場合があります。

## SandMan インターフェイス

**Global Settings > Program Control > USB Drive Sandboxing** を開きます。このページは次を提供します。

- **Automatically sandbox all attached USB drives** — `ForceUsbDrives` を有効または無効にします。
- **Sandbox for USB drives:** — 指定されたサンドボックスを選択します。
- **Volume** および **Information** 列を持つボリューム リスト。チェックされた USB バッキング ボリュームが含まれます。そのチェックボックスをオフにすると、そのシリアルが `DisabledForceVolume` に保存されます。

現在接続されていない除外ボリュームは、シリアルによって **Volume not attached** として一覧表示されたままになる場合があります。サンドボックス セレクターとボリューム リストには、有効な適用可能なサポート証明書が必要です。

## ドライブの更新

SandMan は、ドライブ情報を更新するとき（関連するデバイス変更通知の後を含む）、および USB 設定が適用された後に、生成されたルールを再構築します。したがって、新しく接続または削除された適格なボリュームを自動的に反映するには、SandMan が実行されている必要があります。

SandMan が実行されていない場合、以前に生成された `ForceFolder` エントリは構成に残りますが、追加と削除は独立した USB ポリシー エンジンによって再計算されません。

## バージョン履歴

`ForceUsbDrives`、`UsbSandbox`、および `DisabledForceVolume` はバージョン 1.12.0 で追加されたものとして記載されています。対応するリリース ペアは Sandboxie Plus 1.12.0 / Classic 5.67.0 でした。このページで説明されている自動 USB メンテナンスは SandMan によって実装されています。現在の自動 USB サンドボックス化には、有効な適用可能なサポート証明書が必要で、Insider 限定ではありません。
