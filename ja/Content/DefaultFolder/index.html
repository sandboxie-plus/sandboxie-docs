    Default Folder

    DefaultFolder は Sandboxie Ini の繰り返し可能なサンドボックス設定で、Sandboxie Plus 1.15.12 / Classic 5.70.12 以降で利用できます。Privacy Mode が有効な場合、対象となるプロセスの初期化中にサンドボックス化されたファイルシステム ビュー内のディレクトリ準備を要求します。Sandboxie はパスとアクセスの条件が許す場合にディレクトリの作成を試みますが、その存在は保証されません。

    使用法

    [DefaultBox]

DefaultFolder=%SystemRoot%
DefaultFolder=%USERPROFILE%
DefaultFolder=%APPDATA%\MyApplication
DefaultFolder=C:\SomeSpecificPath

    カスタム エントリは、初期化するプロセスの Windows 環境を使用します。%USERPROFILE% や %APPDATA% などのなじみ深い変数であっても、その環境に依存します。それらは必ずしもサンドボックス化されていない対話型ユーザーのセッションから取得されるわけではありません。

    SandMan では、これらの値を Sandbox Options > Edit ini Section > Edit ini で入力します。Privacy Mode は Sandbox Options > Resource Access > Access Policies の下の別個のコントロールです。Sandboxie Control Classic は Configure > Edit Configuration を提供します。これらのエディターは構成を保存するものであり、それ自体がディレクトリを作成するわけではありません。

    概要

    サンドボックスが Privacy Mode (UsePrivacyMode=y) で動作する場合、多くのホストの場所がアプリケーションから隠されますが、プログラムは一般的なディレクトリ構造が存在することを依然として期待することがあります。DefaultFolder は、ホスト ディレクトリのファイル内容をコピーせずに、それらの構造を準備するのに役立ちます。

    準備は、ボックス定義が作成されるときだけでなく、対象となるサンドボックス化されたプロセスの初期化中に発生します。制限付きトークンおよび AppContainer トークンの条件により、このカスタマイズ手順が除外されることがあり、以前の初期化の失敗がそれを妨げることがあります。後の対象プロセスが再び準備を試みることがあります。これは 1 回限りのボックス操作ではありません。

    動作の仕組み

    Sandboxie は、対象となる Privacy Mode プロセスの初期化中に 2 つのリストを順番に処理します1:

    1. 組み込みの既定値: Sandboxie は [TemplateDefaultFolders] の DefaultFolder エントリを明示的に読み取ります。これらは、レジストリに基づくフォルダー置換を含む Sandboxie の構成展開を使用します。この特別なセクションでは、Template=DefaultFolders で通常のテンプレートを有効にする必要はありません。
    2. カスタムの有効な構成: Sandboxie は該当するサンドボックス、有効なテンプレート、および GlobalSettings エントリを読み取ります。このリストでは Sandboxie 独自の変数展開が抑制され、代わりにコンシューマーは Windows の ExpandEnvironmentStringsW を使用してから、結果のパスを変換します。

    どちらのパスも、既存のサンドボックス ファイルシステム マッピングを通じて作成を試みます。該当するファイル パス ルールは依然として適用されます。オープン パスはボックス化されたディレクトリの作成をスキップし、クローズ パスは拒否されます。その他の該当するパスでは、欠落しているディレクトリの祖先が作成されることがあり、既存のディレクトリはそのアクセスおよび削除の状態が許す場合に再利用できます。

    構成の照会が失敗すると、現在のリストが終了します。特に、組み込みの展開の失敗は残りの組み込みエントリを停止させることがありますが、別個のカスタム リストは引き続き続行されます。無効なカスタム展開または変換の結果は個別にスキップされます。返されたディレクトリ作成の失敗は後のエントリを停止せず、このルーチンによって致命的なプロセス初期化エラーとして扱われません。

    テンプレートの統合

    Templates.ini2 に同梱されている [TemplateDefaultFolders] セクションは、システム、ユーザー プロファイル、パブリック、アプリケーション データ、および Windows 関連ディレクトリの維持されたリストを提供します。このリストはリリース間で変更されることがあります。すべてのプレースホルダーやすべてのディレクトリが、すべてのインストールまたはすべてのプロセス ID で使用できるわけではありません。

    同じ名前のローカル セクションは、同梱リスト全体を置き換えるのではなく、エントリを追加できます。通常のカスタマイズでは、サンドボックスの構成で DefaultFolder 値を使用する必要があります。

    以下の例はこの組み込みリストに属します。%Desktop%、%Personal%、および GUID 形式のプレースホルダーなどの名前は、Sandboxie のレジストリに基づくフォルダー情報を使用します。それらはカスタム エントリ用の Windows 環境変数では自動的にはありません。カスタムの DefaultFolder=%Desktop% には、初期化するプロセスに実際の Desktop 環境変数が必要です。

    システム ディレクトリ

    • %SystemRoot% (Windows ディレクトリ)
    • %TEMP% (一時ファイル)
    • %ProgramFiles% および %ProgramFiles(x86)%
    • %CommonProgramFiles% および %CommonProgramFiles(x86)%

    ユーザー プロファイル ディレクトリ

    • %USERPROFILE% (ユーザー プロファイル ルート)
    • %Desktop% (ユーザー デスクトップ)
    • %Personal% (ドキュメント フォルダー)
    • %{374DE290-123F-4565-9164-39C4925E467B}% (ダウンロード フォルダー)
    • %Favorites% (インターネットお気に入り)
    • %{BFB9D5E0-C6A9-404C-B2B2-AE6DB6AF4968}% (リンク フォルダー)
    • %My Music%、%My Pictures%、%My Video% (メディア フォルダー)
    • %{4C5C32FF-BB9D-43B0-B5B4-2D72E54EAAA4}% (保存されたゲーム)
    • %LOCALAPPDATA% (ローカル アプリケーション データ)

    パブリック ディレクトリ

    • %PUBLIC% およびそのサブディレクトリ

    使用例

    • Privacy Mode: ホストの場所が隠されているときにアプリケーションが期待する可能性のあるディレクトリ構造を準備します。
    • アプリケーションの互換性: 標準ディレクトリをチェックするアプリケーションを支援します (互換性を保証するものではありません)。
    • カスタム アプリケーション ディレクトリ: サンドボックス化されたビューでアプリケーション固有のディレクトリを要求します。

    制限

    • 準備には Privacy Mode と対象となるプロセスの初期化が必要です。
    • カスタム エントリは、絶対ドライブ文字または通常の UNC パスなど、使用可能なパスに展開される必要があります。相対パスまたはサポートされていないパス形式は変換に失敗することがあります。変換が成功しても作成が保証されるわけではありません。
    • カスタム展開は固定サイズの出力バッファを使用します。失敗した結果または大きすぎる結果、および % を依然として含む結果はスキップされます。これはリテラルのパーセント文字も拒否します。再帰的または無制限の展開に依存しないでください。
    • 作成は依然としてファイル パス ルール、ファイルシステムのアクセス許可、既存のファイルとの競合、共有または削除の状態、および利用可能なストレージの対象となります。
    • 作成はベスト エフォートであり、トランザクションではありません。後の失敗の後に一部の親ディレクトリが残ることがあり、ロールバックや回復は保証されません。

    DefaultFolder はアクセス ルールの免除ではありません。Privacy Mode を無効にしたり、クローズ パスや Windows のアクセス許可チェックを上書きしたり、ホスト ファイルシステムの ACL を変更したり、ホスト ファイルの内容へのアクセスを許可したりするものではありません。新しいボックス化されたディレクトリは独自のセキュリティ記述子を受け取ることがありますが、それはホストのアクセス許可を変更することとは異なります。作成されたディレクトリは、後のアプリケーション アクセスが成功することを証明するものではありません。

    例

    カスタム アプリケーション ディレクトリ

    [ApplicationBox]

UsePrivacyMode=y
DefaultFolder=C:\MyApp\Data
DefaultFolder=%APPDATA%\MyApplication

    展開、サンドボックス マッピング、および該当するアクセス条件が、これらの要求が成功するかどうかを依然として決定します。

    通常の構成の保存/再読み込みワークフローを通じて変更を適用し、その後新しい対象のサンドボックス化されたプロセスを開始してください。影響を受けるアプリケーションを再起動すると、その機会が得られます。通常の DefaultFolder の変更は、本質的に SbieSvc、ドライバー、または Windows の再起動を必要としません。既に初期化されたプロセスはリストを自動的に再処理しません。エントリを削除しても既存のディレクトリは削除されず、再読み込みはファイルシステムの内容を調整しません。後の対象プロセスは、成功しなかった準備の試行を再試行できますが、成功は保証されません。

    関連する設定

    • UsePrivacyMode - この準備ルーチンに必要な Privacy Mode を有効にします。
    • NormalFilePath - 一致するパスに通常のサンドボックス ファイル パス ポリシーを適用します。
    • FileRootPath - サンドボックス ファイル コンテナ ルートを構成します。

    1. File_CreateBaseFolders() は明示的に照会された既定値とそれに続くカスタムの有効な値を処理します。Privacy Mode 呼び出し元およびプロセス適格性チェックも参照してください。 ↩

    2. 維持されている [TemplateDefaultFolders] セクションが組み込みディレクトリ リストを提供します。 ↩
